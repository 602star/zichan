### 工具坑（本轮新踩，很值钱）

- **改 CRLF 文件时，先把内容按 `\n` 归一化再插、再统一转回 `\r\n`，会把整文件写坏**：
  第二次跑（内容已经是 `\r\n`）时 `\r\n` 被当成「行 + 空行」，结果每行之间插了一个空行，
  文件字节数翻倍（`\r\r\n` 3455 处）。**正确做法：读成 utf8 字符串后直接用 `\r\n` 拼插入文本，
  只做一次 `indexOf` + `slice` 拼接，绝不做全局行尾转换**。判据：`git diff --numstat` 只应是
  「N 增 0 删」，出现大批增删就是行尾被动了。
- **`git show HEAD:file > tmp.txt` 在 PowerShell 里会把 CRLF 重编码**，用它数 `\r\n\r\n\r\n`
  会得到假结果（HEAD 显示 0、工作区显示 6，实际两边都是 6）。**要用管道喂给 node**
  （`git show ... | node -e "..."` 读 `Buffer.concat`），不要用 `>` 重定向再读文件。
- **e2e 报的行号是转译后的**：`playwright test` 说用例在 182 行，而源码里它在 137 行。
  拿行号回源码定位会白找半天；用测试**名字**定位。
- `tools/e2e/test-results/` 里留的失败快照是**上一次**跑的结果（该目录被 gitignore）：
  先看 `apps/web/dist` 的构建时间，`dist` 比源码旧就说明那次失败是「没重建」而不是功能坏了。
  本轮实测：重建后同一用例 1.2 秒通过。
- 上次踩过的仍然成立：`grep_search` 在本仓库（含 `target/`、大量生成物）会超时，
  用 node 脚本按后缀跳过 `node_modules/.git/dist/target/ci-artifacts` 更可靠。
