## 一、用户报的两件事（已定位、方案确认、已落地）

原话：「优化一下在记账不写描述默认为一个横杠的方式？要不要如果不写描述，描述默认为二级分类？
还有优化一下一级二级分类过长时，和描述会重叠的问题？先定位问题再给我解决方案」

### 问题 A：「不写描述 → 显示 —」是哨兵字符串短路，不是设计

- 根因在 `apps/web/src/selectors/transactions.ts:370` 的 `payeeName()`：没商户时返回**字符串 `'—'`**。
  它被喂进 `description ?? payeeName ?? merchant ?? categoryLabel` 这条链（`Transactions.tsx:2299`
  列表标题、`1340`/`1335` 时间线、`selectors/transactions.ts:792` 账户流水摘要），`??` 只认
  null/undefined，于是 `'—'` 把后面的商户/分类兜底**全部短路** → 主标题就是一个横杠。
- 旁证一：`Transactions.tsx:2333` 有 `item.payeeName !== '—' ? ... : undefined`，说明作者知道这个
  哨兵脏，但只在详情小字上打了补丁，没修源头。
- 旁证二：两条读路径不一致。内存路径给 `'—'`，SQL 分页路径给 `COALESCE(p.name, t.merchant)` 即
  NULL（`packages/db/src/repository.ts:1402-1411`）→ 同一个「商户 为空」的高级查询，大账本与小账本
  结果不同。（`conditionValues` 用 `String(actual ?? '')` 与 `isEmptyValues`，把返回值改成 undefined
  是安全的，顺带把「等于 —」这种查询值去掉。）
- 结论：链尾本来就写着 `?? categoryLabel`，即「描述 → 商户 → 分类」本是原意；用户想要的
  「默认二级分类」不用新增设计，修哨兵即达到。

### 问题 B：分类 chip 压到描述上

- 根因：分类列是**固定 112px**（`Transactions.tsx:2349` 的 gridTemplateColumns），而 chip 用
  `ui/styles.ts:133` 的 `tag`（`whiteSpace: nowrap`，无 `max-width`/`overflow`）+ 行内
  `width: fit-content`。fit-content 的下界是 min-content（nowrap 文本全宽）→ 盒子顶出格子；列
  `gap: 12px`，所以**宽于 124px 的标签就画到描述文字上**。
- 实测方式（可复用）：一次性探针 `.tools/measure-chip.mjs`（用完已删），Playwright + 系统
  Chrome（`PLAYWRIGHT_EXECUTABLE_PATH=C:\Program Files\Google\Chrome\Application\chrome.exe`），
  复刻 chip 的 font-size 11px / weight 500 / padding 3px 8px / border 1px 与 app 的 font stack，
  再 `getBoundingClientRect().width`。**不用起 app、不用 build**，比跑 e2e 快得多。
- 数字（109 个默认启用分类）：完整「一级 / 二级」**75 个超 112px**，其中 **8 个超 124px 真压描述**
  （最宽 139px「金融税费 / 其他金融税费」，压 15px）；只显二级名时**最宽 84px，0 个溢出**。
- 手机端：`.zc-transaction-row` 窄屏是 `minmax(0,1fr) auto`（`styles.css:2256`），chip 在 col1、
  金额在 col2，同一机制（默认标签还够宽，自建长名会压金额）。

- 兜底链收敛成 `transactionMeta.transactionSummaryTitle(tx, payees, fallbackCategoryLabel)`；

  落点：列表标题、账户流水摘要（两条路径：selector 与 `Transactions.tsx` 的分页版）、
  作废列表、（时间线只受益于哨兵修好，仍不退到分类，因为分类是它自己的列）。
- 分类列宽走 `--zc-category-track` 变量：默认 112px，`@media (min-width: 1024px)` 才给
  `minmax(112px, 200px)`；chip 加 `maxWidth:100% + overflow:hidden + textOverflow:ellipsis +
  title`。

### 这一轮新踩到、值得记的坑

- **`minmax(112px, 200px)` 不会「按内容取中间值」**。两端都是固定长度时，这条轨道没有内在尺寸
  函数（不走 resolve-intrinsic-sizes），浏览器在有空间时直接把基尺寸撑到**增长上限 200px**。
  实测：chip 只有 134px，轨道仍是 200px。副作用是好的——长短标签的行列宽一致、不会参差；
  但如果想要「贴着内容」，得用 `fit-content(200px)`，代价是**每行各算各的**（每行是独立
  grid 容器）→ 摘要起始位置逐行参差，比宽一点更难看。所以选了 minmax。
- **一律 200px 在窄屏是倒退**：实测 768px 视口下摘要列只剩 **18px**。按视口量了一遍才定下
  1024 这个闸口（≥1024 摘要还有 286px+；<1024 收回 112px = 改动前布局，零回归）。
  量法：`page.setViewportSize()` 后读 `getComputedStyle(row).gridTemplateColumns` 并 split
  → 得到每条轨道的**已用 px**（不是 `gridColumnStart`，自动放置时它是 `auto`，没用）。
  取「分类列是第几条轨道」不能用写死下标：行首可能有勾选框轨道（实测 `[34,88,200,...]`），
  要用 `[...row.children].indexOf(chip)` 映射。
- 本机 e2e：**`PLAYWRIGHT_EXECUTABLE_PATH` 必须每次显式带上**。漏了不会报「浏览器不存在」，
  而是 32 条用例各 ~300ms 全红，看着像代码坏了——其实是半截安装的 chromium 起不来。
  另外 `npm run build:web` 只能在仓库根跑（`tools/e2e` 下没有这个 script，会静默跑旧 dist，
  探针结果全是改前的值，极易误判）。
- 分类选择器的坑（写 e2e 时撞上）：`EntityFormModal.splitCategoryLabel` 按**单个 `/`** 拆标签
  再 `join(' / ')` 拼回，所以叶子名自带斜杠时面板里会变成「打车 / 网约车」（带空格）——
  用 `getByRole('option', { name: /打车\/网约车/ })` 匹配不到，得容忍空格
  （`category.split('/').map(trim).join('\\s*/\\s*')`）。同时 `categoryGroups` 的搜索既比
  `option.label` 也比 `parsed.child`，所以搜索框填「打车/网约车」仍能过滤出结果，只有选择器
  的文本匹配会挂 → 现象很有误导性。
- e2e 里等新记的行：**别用金额**。`41.20` 落库后显示成 `41.2`（Decimal 去尾零），
  `filter({ hasText: '41.20' })` 永远等不到；有描述时用描述更稳。

## 五、分类选择器：叶子名里的斜杠（已修，走「结构传下去」那一版）

用户顺手报的：「分类选择器把标签按 `/` 拆开再拼回，所以叶子名自带的斜杠会显示成带空格的
样子（「打车/网约车」在面板里是「打车 / 网约车」）。影响 4 个内置分类，动它要牵连自建分类的
解析，我没顺手改。」要求先确认再修。

- 确认属实，且**自建分类比内置更惨**：内置 4 个只是「多个空格」（父级名恰好不含斜杠），
  而父级名带斜杠会凭空造出一级分组（`学习/培训 / 教材` → 一级「学习」+ 二级「培训 / 教材」）。
- 改法：`CategoryOption` 增 `name`/`parentName` 由 `categoryOptions()` 填；web 透传，
  `splitCategoryLabel` 结构优先、解析降级为兜底。顺带把 `categoryOptions` 的 `label` 从
  「每个选项重跑一次 `categoryLabel()`」改成按同一份目录自算（去掉那处 O(n²)）。
- **Playwright 断言坑（新，很重要）**：`toContainText` 先把期望串 `trim()` 再当子串找
  （`ExpectedTextMatcher.normalize` → `normalizeWhiteSpace` 带 `.trim()`）。所以
  `not.toContainText(' / ')` 的期望被裁成 `'/'`，只要文本里有斜杠就「命中」——这次差点被它
  误判成「修复无效」（报错里那个 `Received string: "打打车/网约车/网约车"` 是
  `indexOf = -1` 时高亮打印函数的错乱输出，不是真实文本）。**要断言空格只能用锚定正则。**
- 另一类坑：两条老 e2e 把 bug 的样子当成了预期（`toContainText('加油 / 充电')`），已改成锚定
  正则，它们从此也是这个 bug 的回归测试。
- 又一处坑（沿用上次记的）：真实浏览器里 `getByRole('option', { name })` 对含空格差异的
  名字是**不会**匹配的，而 `filter({ hasText })` 和内部搜索都比 `option.label`——现象很误导。
  修完之后按名字直接选就对了，不用再写容忍空格的正则。
- 验证：core 128 条 + web 498 条绿；typecheck / lint 干净；e2e 全量 33 条通过。
  e2e 那条新断言的证据链闭合：临时关掉结构分支重建 → 面板实测 `"打打车 / 网约车"`，
  恢复后 → `"打 打车/网约车"`。
- 仍未动的相邻项：`docs`/`memory` 之外，`Manage.tsx` 里给生命周期候选拼的
  `「父 / 子」` 文案（只在原生 select 里用，不经过选择器，所以没动）。
