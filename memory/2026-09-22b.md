### 实施时的偏离（方案 → 实现）

  和安全厢里其它管理路由的寻址方式一致；`accountId` 只出现在审计 payload 里。
- 路径形状与方案 §4.3 不同：`POST/GET /api/admin/users/:username/preview`、
  `GET /api/admin/previews/:id/backup`、`DELETE /api/admin/previews/:id`。
  方案里那条按 `accountId` 的路径没有采纳。
- 方案 §4.3 计划 4 条路由，实现是 4 条但**附件那条（`/previews/:id/attachments/:sha256`）没做**，
  属于阶段 5。所以「预览里点开附件」现在还是断的。
- 「默认开」落地为：**任何非 member 角色**都能开预览，不只看 Owner。这与方案 §11 一致。
- `assertRecentLogin()` 只加在**创建**那一步，读 `/backup` 不要求 —— 与方案 §4.3 一致。
- 预览**豁免账号修订号自增**，也**豁免特权目标保护**（`store.ts` 里两处显式排除
  `ledger-preview-open`）。方案没写这两条，是实现时加的判断，理由在 commit message 里。

### 工具坑（本轮踩的）

- **`npm test` 会串起 4 个 workspace 的 vitest**，输出里出现
  `Test Files 2 failed | 40 passed` 时**不一定真有失败**：再单独跑
  `npm test --workspace @zichan/sync-server` 是 42/42 全绿，连跑两次都一样，
  说明那是 vitest 分片输出的显示噪声，不是真红灯。**判据：看退出码 + 按 workspace 单跑复核**，
  不要照着聚合输出里的 `failed` 去查。
- **PowerShell 重定向把中文写坏**：`npm test > file 2>&1` 出来的文件是 UTF-16LE + 部分字节丢了，
  读回来每行都变成带 `\0` 的 `c h a r` 序列，`Select-String` 还能"匹配"到，看着像正常但内容是错的。
  数 `Test Files` 行会数不到。**要么用 `Out-File -Encoding utf8`，要么别落盘、直接看终端**；
  真要落盘就在 node 里 `.replace(/\x1b\[[0-9;]*m/g,'')` 再去 `\u0000`。
- **`node -e "…"` 里塞多行中文字符串会被 PowerShell/引号层打碎**（`'` 与 `\r\n` 组合导致
  `Invalid or unexpected token`）。写长文本一律**先写一个 `.mjs` 脚本文件再 `node 脚本`**，
  别赌内联。
- **`git add` 一个不存在的路径不会报错**（PowerShell 下 `2>$null` 也吞了），
  于是我以为把 `docs/admin-attachment-visibility-plan.md` 加进去了 —— 那个文件**其实已经不在工作区**，
  现在仓库里只有 `docs/admin-ledger-preview-plan.md`。**加文件前先 `Test-Path`。**
- 往 CRLF 的 `docs/worklog.md` 插条目：**读出 utf8 字符串 → 用 `\r\n` 拼插入文本 → 一次
  `indexOf` + `slice` 拼接**，不要做全局行尾转换。判据 `git diff --numstat` 是 `9 0`
  （纯新增）。上一轮那条「先归一化再转回」的写法会把文件写坏。
