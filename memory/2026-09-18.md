## 本轮：管理员两步验证（MFA）

上一批留待清单的第一项（「管理员 MFA」）。产品级过程见 `docs/worklog.md` 顶部，
管理后台文档新增「管理员两步验证（TOTP）」章节；这里只记判断、坑与下一次要小心的地方。

### 交付要点（一句话版）

- `apps/sync-server/src/totp.ts`（只用 `node:crypto`）+ `src/mfa.ts`（规则）+ `store.ts` 两张新表；
  登录 `/api/auth/login/finish` 在密码通过后不建会话，只发 5 分钟一次性挑战，`/api/auth/login/mfa`
  用验证码或恢复码换会话。第二因子**只保护管理后台登录**（需要 `X-Zichan-Session: admin-cookie`），
  同一账号的记账端登录不要验证码；本地维护程序（所有者恢复）也不要。
- 刻意做的三个「不锁门」决定：① 未 `confirm` 的绑定既不生效也不拦登录；② 恢复码一次一枚、
  用完提示重新生成；③ 策略 `requireAdminMfa` 保存前先算名单，有人没绑定就整条拒绝，且开着时
  不允许关自己的第二因子。策略与绑定状态不一致**不会让服务启动失败**，只在登录时拒绝。
- UI：新增 `/admin/security`（自助绑定/确认/恢复码/关闭），登录卡片加第二步状态。

### 测试抓到的两个真缺陷（值得记住的教训）

- `mfa.ts` 里 `disable` / `regenerateRecoveryCodes` 写成 `if (!await verify(username, code))`，
  而 `verify` 返回的是**对象** —— 结果任何错误验证码都能关闭两步验证或重发恢复码。写法上教训是
  统一的：**返回结构化结果时绝不用真值判断**，先取 `.ok` 再判断（代码里现在留了注释）。
- `regenerateRecoveryCodes` 把 `verify` **之前**读到的 `lastStep` 写回，等于把刚消耗掉的时间步
  还给持码人（可重放）。改成验证后重读记录。同类的坑：任何「校验 + 落库」的组合都要问一句
  「写回的字段里有没有被校验过程改过的」。
- 这两个都是端到端用例（登录两次 + 重复用码）先抓到的，单测（服务级）看不到——**MFA 这种跨步骤
  状态最好在 HTTP 层验一次**。

### 测试写法（可复用）

- 一个验证码只能用一次 ⇒ 同一个 30 秒窗口里没几个可用码。办法：**只伪造 `Date`**
  （`vi.useFakeTimers({ toFake: ['Date'] })` + `vi.setSystemTime`），服务端与被测代码在同一进程，
  于是每个码都能落在自己的时间步里，测试不必 sleep 也不必依赖真实时钟。
- 步号算术：`confirm` 用的是**当前**步（还没消耗任何步），登录必须用**下一步**（确认那一步已被
  消耗）。e2e 第一次就是这里算错（确认也跳了一步），导致随后登录被判重放。

## 环境与工具坑（本轮新踩 / 复现）

- **写入通道脱敏会真落盘**：`credentials:[REDACTED] === 'cookie' ? …` 这种 `键名: 非字面量表达式`
  在**写入**时就被替换成占位符，文件里真的是 `[REDACTED]`（tsc 报 `Cannot find name 'REDACTED'`
  才算实锤）。规避：值写成**引号字面量**（`{ credentials: 'same-origin' }` 这种能存活），或者先
  赋值（`request.credentials = 'same-origin'` 实测也能存活）。
- **显示层两个方向都会骗人**：`secret: a stolen database file` 在读取时被显示成
  `secret:[REDACTED] stolen…`，看着像损坏其实文件完好。判断有没有真损坏只有一个可靠办法：
  node 读原文件后输出**布尔**（`s.includes('RED'+'ACTED')`）或**字符码**，不要打印文本再靠眼睛。
- `git_commit` 工具**不传 `files` 等于 `git add -A`**：这次把 `.scratch-*/` 整个临时目录一起提交了。
  补救：`git rm -r --cached <dir>` + `git commit --amend -F <消息文件>`（未推送，安全）。
  以后一律显式传 `files`，或直接用命令行 git。
- `npx vitest run`（仓库根、无参数）会把 `tools/e2e/**` 的 Playwright 用例也当 vitest 收集，
  33 个 suite 直接报错（"Playwright Test did not expect test() to be called here"）。
  跑全量单测要用 **`npm test`**（`--workspaces`）。
- **e2e 需要指定系统 Chrome**：仓库内 `.playwright-browsers/chromium-1193/chrome-win` 里只有
  `chrome.dll`（缺 `chrome.exe`），默认启动会报 `Executable doesn't exist at …chromium_headless_shell-1193`。
  可行做法：`PLAYWRIGHT_EXECUTABLE_PATH="C:\Program Files\Google\Chrome\Application\chrome.exe"`
  （`account.config.mjs` 支持这个环境变量）。全量 `test:e2e:account` 约 10 分钟，其中
  `mobile-form-sweep.spec.mjs` 单独占 6.9 分钟。
- 往 SQL 模板字符串里插新语句要**插在语句之间**：这次把两张新表插进上一个 `CREATE TABLE` 的
  括号里，`tsc` 全绿（SQL 只是字符串），只有跑起来才报 `near "CREATE": syntax error` /
  `near ")": syntax error`。改完 DDL 必须真跑一次存储层测试。
- 设置页字段类型：`kind: 'select'` 的字段此前没有任何渲染/保存分支，会被 `Number()` 变成 NaN
  而**静默丢弃**（既有的 `backupAutoEnabled` 也受影响）。新增设置项时先确认该 kind 有 UI 分支。
