# 手机端视图审查与改造方案（2026-10-17）

## 范围与结论

范围是账本 Web 页面、Android/iOS Tauri 移动壳共用的 `apps/web` 视图。仓库已有手机适配、触控目标、安全区、弹窗和表格卡片化；`docs/mobile-web-adaptation-plan.md` 的批次 1–4 已实施，不能把其中的历史缺陷当作当前缺陷。今天的 Android APK 位于 `.runtime/builds/2026-10-17/`，但本机没有连接设备或 `adb`，本审查未声称 APK 真机运行验证。

**当前主要问题是信息选择**：桌面内容被纵向堆叠到手机上，某些卡片虽然没有横向溢出，用户仍需要经过太多重复指标、元数据和操作入口才能完成“看余额、记一笔、找一笔、处理待办”。现有布局测试侧重无溢出、44px 命中区、16px 输入框及页面总密度；没有约束列表单条记录的可见字段、首屏任务顺序、编辑详情的可达性和真机返回行为。

改造前构建产物的 `mobile-layout.spec.mjs` 已在本机 Chrome 通过 9 种视口 × 9 个账本页面的布局契约。其 390×844 密度测量为：设置 4.19 屏/65 控件，报表 4.38 屏/23 控件，日常收支 4.55 屏/71 控件。这些数字是测试账本和当时默认页签的基线，不代表全部账户模式或 APK 真机。

## 实施记录

### 局域网 HTTP 新账号修复（2026-10-18）

手机通过 `http://192.168.x.x` 访问时，浏览器仍提供 `crypto.getRandomValues`，但不提供 `crypto.randomUUID`。原实现的共享数据库事务和同步任务直接调用后者，导致注册成功后数据库初始化失败。已统一改用核心包基于安全随机数生成的 `newId()`，并修正 Web 账号错误恢复入口：重新验证账号，而不是让用户输入另一套“本机账本密码”。截图中的 `aes-gcm: invalid tag` 是进入旧本机密码页后使用账号密码解锁已有设备密钥包的结果，不应据此重置账号或本机数据。

已用非安全上下文的局域网 HTTP 端到端测试复现能力差异，并通过“注册 → 创建个人账本 → 开始记账 → 刷新恢复”完整流程。现有 `192.168.2.204:8787/app/` 返回的 Web 首页与本地新构建产物一致。

本轮已落地 Web 端的信息层级调整，Android APK 暂不重建：

- 新建账本中尚未配置“记账表单字段”时，手机新增交易默认使用核心字段；交易时间和附件移入“更多信息”。用户明确保存的字段偏好继续生效，编辑已有记录时有值字段仍自动显示。转账、退款等条件必填字段仍保持可见。
- 手机流水列表缩短为标题、金额、日期、分类和必要状态；详细地点、坐标、标签仍可从编辑详情查看。
- 手机总览把待办移到指标前，默认显示两项辅助指标，完整快照和指标可展开；无待办时不占空卡。
- 手机物品资产卡默认保留名称、状态和成本摘要，指标、耗材、目标、操作与时间线可展开。
- 手机报表先显示前五个分类，完整分类与流水明细分别可展开；桌面保持完整表格。
- 手机历史、游戏赛季的高级筛选默认收起；管理通用资料表变为可展开的记录卡，保留编辑和归档/合并入口。

同一份 390×844 测试账本上，报表默认页从改造前的 4.38 屏降到 2.45 屏，控件数从 23 变成 24（增加了明细展开入口）；日常收支仍为约 4.55 屏，但单条记录的附加信息缩短。以上是自动化样本的页面密度，不代替真实账本的可用性检查。阶段 0 的多币种、退款、附件、逾期与长赛季样本，以及手机浏览器实机操作，仍需在用户账本中验证。

验证结果：`npm run build:web`、`npm run lint` 和手机/平板 9 种视口 × 9 个页面的 `mobile-layout.spec.mjs` 已通过；390×844 新建表单可达性扫描、受影响页面的 86 项单元测试也已通过。完整 Web 单测为 682 项通过、2 项原生配置断言失败：测试仍期待旧的生物识别初始化写法和 `androidx.core.content.FileProvider` 字面量，这两个原生文件与本轮 Web 视图改动无关。Android 包、软键盘和真实账本情境留待实机验证。

## 手机信息规则

1. **默认可见**：做当前决定必需的字段，包括记录标题/金额/方向、时间归属、分类、必要的账户或资产单位，以及异常状态。金额不得被省略或用无法区分原币与折算币的缩写代替。
2. **条件可见**：只在有值或影响判断时出现，如外币、退款、待核实、拆分、缺价格、账单逾期、保修即将到期。编辑已有记录时，任何已填值都自动显示，不能因手机默认隐藏而被误改或丢失。
3. **详情可见**：精确坐标、技术 ID、完整汇率、成本核算解释、标签全量、历史 diff、所有附件、导出格式等保留在详情或“更多”中。隐藏只改展示，不删字段、数据、筛选或导出能力。
4. **浏览器与安装包共享默认规则**：布局由有效视口宽度决定，原生能力由 Tauri 平台决定。手机横屏和折叠屏不能仅依赖 UA；触控字号和命中区继续使用 `(pointer: coarse)`。
5. **关键状态不能折叠**：缺汇率、同步失败、草稿冲突、未保存内容、退款关联和对账限制必须保持明确可见。

## 具体页面设计

### 总览

- 首屏顺序：日期范围简写 → 净资产及估值完整性 → 最高优先级待办 → 两个辅助指标。无待办时不显示空的任务卡。
- “资产配置”展示前三类与合计占比，提供“查看全部”；不把投入/未实现盈亏在 hero、快照、KPI 三处重复展示。
- 当缺价格时，在净资产数值旁显示“已知部分”并保留补价入口，不能只用颜色提示。

### 日常收支

- 列表卡：第一行“描述或商家 / 金额+原币”，第二行“日期 · 分类 · 账户（必要时）”。退款、对账、待核实、拆分等以短状态标记加在卡片下方。点击卡片进入详情，选择模式仍能勾选。
- 筛选条只常驻“期间、类型、搜索”；其他筛选放入面板。已启用的高级筛选以可清除的 chip 留在列表上方，避免用户忘记筛选生效。
- 新增支出以金额为第一个焦点。币种/日期默认值提供单击编辑，不再占整行控件；账户只有在选择会改变结果时常驻。类型切到转账、退款时补出对应必填字段。
- 保留已有 `progressiveFieldGroups`、草稿、表单错误定位和字段偏好；调整字段分组和默认偏好时增加迁移/回退策略，不重置用户已保存的偏好。

### 资产转换、物品资产与游戏赛季

- 资产转换列表首层为日期、转换路径、实际到账、成本/盈亏状态；完整汇率、步骤账户和手续费进入详情。现有 `Convert.tsx` 已有详情弹窗，可复用。
- 物品资产列表采用紧凑卡，详情页承载当前 `ItemCard` 的指标、目标、耗材、配件、时间线及新增操作。保修到期和待处理耗材可提升到卡片首层。
- 游戏列表首层保留赛季、净收益与最近活动；效率分析和每笔记录在详情/展开区。优先验证真实有数据的长赛季。

### 报表、历史、管理与设置

- 报表保留当前已完成的顶部摘要和单一导出菜单。手机主表改成排行条目（名称、金额、占比/变化）；流水明细默认折叠并显示记录数，展开后仍可查看全部 8 字段。
- 历史默认列表只显示时间、对象、动作、可理解的变化摘要；技术 diff/设备信息继续放在现有详情中。导出和高级筛选不占首屏。
- 管理以可搜索目录和最近使用对象为入口；只有分类、账户、资产等具体目录内部才显示编辑/停用/批量操作。
- 设置已有分组与折叠，优先做真机可达性验收，不再整体重排。备份、恢复与安全状态要有明确入口和成功/失败反馈。

## 验收标准

- 常规手机 390×844：打开账本后首屏可见净资产与估值状态；日常收支首屏可见近期流水；普通支出打开表单后无需滚动即可看见金额、分类及保存操作（软键盘弹出时保存可触及）。
- 交易列表：无异常记录默认不超过两行主要文字；原币金额、日期和分类始终可见；含退款/外币/对账状态的记录可辨；点开能看到隐藏字段完整值。
- 编辑回归：保存含地点、标签、附件、成本核算字段的旧记录，不修改这些字段时保存前后完全一致。任何拦截性错误都能展开并聚焦对应字段。
- 设备矩阵继续满足现有 `mobile-layout.spec.mjs`、`mobile-form-sweep.spec.mjs` 的几何/行为约束，并增加“首屏关键数据、可见字段、详情全量、异常状态”断言。截图用于人工比较，不仅以像素差决定通过。
- 浏览器与 APK 使用同一账本完成记账、查找、编辑、备份/分享流程；在 Android/iOS 上另外验证系统返回和软键盘。未拿到设备前，原生项标记“待验证”，不视作通过。
- 通过 `npm run typecheck`、受影响 workspace 的 `npm test`、`npm run build:web` 和移动端 e2e；最终核对 APK 打包日期与前端构建版本。

## 参考产品与可借鉴做法

- [YNAB 官方：移动端新增交易](https://support.ynab.com/en_us/how-to-add-transactions-in-ynab-HyDwA_byi?mobile-help=true)：金额优先输入，交易类型决定后续字段，日期和附加项可修改。借鉴其“先完成高频动作，再给细节”的顺序。
- [YNAB 官方：搜索与筛选交易](https://support.ynab.com/en_us/searching-transactions-a-guide-r1gxyQryj)：搜索入口与可叠加筛选帮助用户找记录；适合作为本项目高级筛选收起后的可发现性参考。
- [Monarch 官方：入门与仪表盘定制](https://help.monarchmoney.com/hc/en-us/articles/360048393272-Getting-Started-Guide)：Web 与移动端仪表盘卡片可分别排序和禁用；本项目可先做移动端默认简化，之后再考虑用户定制。
- [Actual Budget 官方发布记录](https://actualbudget.org/docs/releases/)：近期专门重做移动账户列表以与交易列表一致，并添加移动端商户搜索/筛选；说明复杂账本在手机上需要独立的列表信息层级。
- [Android 官方布局与导航模式](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns)：手机主导航用底栏，低频操作放菜单，屏幕变宽后切换侧轨；本项目现有壳层方向基本一致。

以上是模式参考，不照搬对方的数据模型或财务口径。本项目的多币种原值、估值不完整、退款归属和可追溯历史必须保留。
