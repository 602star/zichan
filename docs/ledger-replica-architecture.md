# 账本副本架构与实施契约

状态：服务器同步组已完成本机三节点功能验证，仍待真实设备验收。旧的逐账本授权流程保留给未加入服务器同步组的部署；下文部分历史实施记录描述该旧流程。当前客户端桥接协议见 [event-sync-design.md](event-sync-design.md)。真实设备的待执行步骤见 [three-node-acceptance.md](three-node-acceptance.md)。

### 当前服务器同步组流程

单机节点无需组网。互联时，管理员在选定的主节点进入“系统设置 → 服务器同步组”，填写本站 HTTPS 地址并创建组；其他节点填写主节点地址、本站声明地址和一次性加入码。主节点维护节点目录、统一注册策略与一次性邀请码。各节点原有个人账本和新建个人账本由服务器自动发现并建立加密副本；附属节点主动连接主节点，主节点不必能主动进入局域网。账本提交、密钥包、控制事件与新版附件继续使用原有按账本增量复制和完整性核对协议。所有节点保存账本密文；主节点只是传播中继，不是唯一数据真源。

原有账号和新账号以签发节点及账号 ID 组成统一身份。附属节点的新注册先经主节点校验组策略、用户名和邀请码，完成注册时由主节点原子核销邀请码并保存签名密码凭据；其他节点拉取账号目录，因此尚未建立个人账本的账号也能在组内用原密码登录。节点会话仍各自保存，断开主节点后已缓存的账号可在本地登录、记账；新账号注册需要主节点在线。昵称、账号密码和账号加密密钥更新由签发节点签名并经组目录传播，目标拒绝旧版或同版不同内容。注册和邀请码只在主节点管理；每台节点的部署所有者仍分别管理本站设置。

主节点使用单次加入码登记其他节点；各账本复制授权由服务器自动签发、续期。账本 ID 或账号名冲突会停止该项组发现并在管理页记录错误，绝不自动合并。托管账本的解锁密钥经 TLS 和节点签名连接传给主节点、在各节点用本站托管密钥重新封存；私密账本传播保护模式和账号密码密钥包，恢复码不传给服务器。旧版逐账本链路可继续存在，但不能把未加入本服务器组的外部身份自动视为组成员。

本机验证已覆盖主节点及附属节点各自已有账本、第三节点后来加入后的全量回填、主节点和附属节点原账号在第三节点用原密码登录、附属节点使用主节点邀请码注册且邀请码只核销一次、无账本账号在组内登录、托管及私密账本保护资料传播。真实公网与两个独立局域网的互通、断线和长时间运行尚待部署环境验收。

### 旧版逐账本链路与仍需验收的边界

已获账本复制授权的节点，现在可沿主节点中继账号签发方签名的 OPAQUE 凭据、昵称与加密账号密钥包。目标节点保存独立会话，身份源 HTTP 服务不可用时，已收到凭据的账号仍可用原密码在目标网页新登录。附属节点新注册账号的凭据可先上报中继，再按增量目录转发到其他附属节点；此时可登录但没有账本访问权，网页明确提示账本尚未加入本站。所有者发放签名成员授权及密钥包后，已有账号才可解锁该账本。签名凭据按账号修订号和目录游标增量传播，目标拒绝版本回退和同版冲突；凭据变化或停用被目标收到后撤销旧会话。两端同名时，记账登录选择同步组账号，节点管理后台选择本站账号；不同统一账号撞名停止传播并报告错误。昵称和找回邮箱只在签发方修改。

源账本采用托管保护时，目标节点在签名节点连接上接收托管密钥，并用自己的托管密钥重新封存；组内获授权节点均可解密，不能称为端到端保密。新账号登录时自动以账号密码建立加密账号密钥包；成员账本优先以账号密码解锁，旧独立密钥密码可在签发节点迁移。私密账本把同一密钥额外封装为账号密码密钥包并经节点复制，恢复码仍单独保留。忘记账号密码后，私密账本必须用恢复码重新绑定；成员账号若也丢失旧密钥密码，须由账本所有者重新发放密钥，不能靠重置登录密码解密旧密文。旧版逐账本凭据传播以具体账本授权为界；服务器同步组另有全组账号目录与个人账本自动发现。账号能在组内登录不等于自动取得别人的账本成员权限。

身份源节点已验证邮箱且配置邮件发送渠道时，用户可在该节点申请一次性邮件重置码；管理员签发的重置码仍可独立使用。两者更新同一份登录凭据，目标收到后撤销旧会话。身份源不可达时重置暂不可用；附属节点的找回入口尚未代理到身份源。本站按账号记录客户端报告的完整同步轮次（已收敛、待续、失败），另计加密提交与附件正文的上下行流量和请求次数；流量不含 HTTP 开销、旧版历史流量或服务器间复制流量。节点链路另外累计后台工作轮次及就绪、追赶、失败结果，包含该轮分页复制和目录核验。收到经主节点签名的成员目录移出状态后，节点停用相应来源的本地账号映射并撤销会话；旧目录事件仍可推进游标但不能重新导入已移出的身份。

管理员可在“系统设置 → 访问安全”关闭“允许用户通过本站网页记账”。关闭后，健康检查明确报告该状态，记账网页禁用登录和注册，服务端拒绝普通记账会话的新登录、续期与账本 API；节点管理后台及服务器间复制继续工作。已有离线浏览器缓存不能由服务器隔空删除，重新访问本站服务器时会被拒绝。

公网或局域网只是部署地址类型，不决定节点能否独立运行。单台公网节点不必创建同步组。附属节点接收主节点的开放、邀请码或关闭注册策略；管理员仍独立控制各节点是否允许网页记账。服务器同步组中的邀请码由主节点一次核销，个人账本自动加入组；共享账本仍须由所有者签名授权后，其他账号才能读写和解锁。同名账号不自动视为同一人。

本机压力模式（`ZICHAN_REPLICA_STRESS=1`）已用三个服务实例、1,203 条加密提交和 1,000 个 V2 附件通过断网写入、分块续传、节点重启、目录收敛与样本解密验收。加入按块进度后，每个小附件都写一次计数的版本约用 184 秒；单块小附件按页合并写入后约用 139 秒。这是两次本机运行记录，不是受控性能基准，也不能推算公网传输时间。管理员页面打开时每约 3 秒刷新进度，大附件按块记录，小附件按页记录，并显示最近刷新间隔的平均速度。

同一演练可用 `ZICHAN_REPLICA_STRESS_BLOBS` 指定 3 至 10,000 个附件。2026-10-11 在本机以 3,000 个附件、1,203 条加密提交复验：公网节点中断后两端写入、分块续传、复制中重启、三端 3,000 个对象及目录摘要收敛、样本解密全部通过，整个测试命令约 288 秒。样本大多为 64 KiB 的重复填充数据，另含一个超过 5 MiB 的分块对象，传输时均为密文；此结果证明数千对象的本机协议流程，不代表真实照片或公网链路的吞吐量。

物理附件校验复用调度时已读取的目录快照，省去一次整账本目录读取；校验结束仍重新读取目录，并比对副本 ID、流世代、附件数量与摘要。写入校验结果时还会在同一事务内确认副本身份，个人账本替换或恢复会清除旧校验证据。期间新增附件或替换副本时，不会把旧快照认证为当前状态。节点间就绪核对保留前后两次独立目录读取，用于发现并发写入，不能用缓存结果代替。

Windows 便携桌面端已在真实 WebView2 窗口完成两本账往返切换、独立 SQLCipher/附件/备份/Stronghold 路径、关窗后离线冷启动解锁、离线写入后追赶，以及隔离副本的备份预检与恢复。证据和边界见 [native-desktop-acceptance.md](native-desktop-acceptance.md)；三台独立设备仍须按 [three-node-acceptance.md](three-node-acceptance.md) 实机验收。

同版本节点在签名目录或状态响应中声明 `packV1` 后，会把单块且不超过 256 KiB 的缺失 V2 密文附件按至多 20 个对象合成一个不超过 8 MiB 的签名包：推送方一次提交多个对象，拉取方一次读取多个对象。接收端仍逐对象校验清单、分块哈希、配额和删除状态；拉取方也核对包内清单与先前的签名目录。响应丢失后重试按对象去重，旧节点未声明能力时继续使用逐对象接口；大附件继续走缺块续传。协议测试分别确认两张小附件推送和拉取都只用一次包请求，逐对象请求为零。双向包传输的 1,000 附件本机压力模式约用 102 秒；此轮同时修正了测试对循环扫描游标的过严判定，时间不能与前面的 139 秒或 141 秒直接比较，跨公网的收益仍待实测。

浏览器 IndexedDB 保留离线记账和本地缓存。节点报告该账本已采用服务器后台复制后，浏览器就只与一台节点同步；该节点故障时改用另一已配置节点。这个路由选择在副本尚未 `READY`、链路暂停或页面重启后仍保持，浏览器不会重新承担节点间搬运。`READY` 仍由实时目录与物理附件核对独立判断。各节点的原始提交序号可能因隔离旧提交而不同，不能用序号相等代替签名目录核对。未核对的旧配置仍保留浏览器多服务器桥接用于迁移，V1 附件转换仍需有密钥的客户端。尚不能把本阶段显示为三个完整、可无条件互换的生产副本。多账本迁移细节见 [multi-ledger-account-migration.md](multi-ledger-account-migration.md)；网页路由和千附件本机验收见 [replica-routing-and-scale-acceptance.md](replica-routing-and-scale-acceptance.md)。

管理员可在网页对单条仍有效的链路执行“重扫并补传”。服务端先排空后台复制，再原子重置该链路的提交、成员、附件和删除状态扫描游标以及旧的就绪证据；原账本密文、附件、节点身份和复制授权不变。后台从头核对并按对象去重补传，完成物理校验后才能重新显示 `READY`。若账本文件本身损坏、节点世代变化或授权失效，重扫不会强行覆盖数据，仍需按备份与人工修复流程处理。

网页顶部的“客户端同步完成”仅表示最近一次客户端同步结束；服务器副本和附件完整性须看节点实时核对结果。未配置同步时的引导也会说明托管账本由服务器代管解密密钥，不再把所有服务器模式描述成服务器无法读账。

“我的账号 → 查看账本副本与状态”现在直接展示副本状态、加入、重扫和授权操作；新增节点所需的地址与管理员登录通过面板上的“配置节点连接”打开。“客户端同步与服务器连接”单独保留本机自动同步、连接凭据和旧配置迁移选项，不再把账本副本藏在该折叠区内。

旧 V1 密文对象 ID 包含上传时的节点和账号名。节点可向已获该账本读取权限的会话列出当前副本仍有 V1 对象的源账号名；客户端据此用已解锁账本密钥尝试旧路由，缺少本地正文时下载、校验并上传为账本范围 V2 对象。该路径已覆盖账号名变化及跨副本隔离测试。完成 V2 上传并核对后，客户端登记旧 V1 与新 V2 的关系；旧密文仍保留，只有新对象可用时旧对象才退出待迁移数量，新对象失效则旧对象重新出现。此关系不随服务端启动时的附件目录重建而丢失。手动同步显示旧附件检查、按对象完成的迁移数量、逻辑字节量和失败数量。自动同步先完成提交，再逐批上传新附件及转换旧 V1；批次以附件哈希游标续跑，完成整轮后才核对并发布承诺目录。分块上传失败后下轮按服务器缺块续传。转换仍需浏览器保持运行及拥有旧账本密钥；单个大附件的准确剩余时间估算、无归属记录处置和三节点故障验收仍未完成。

副本目录中的旧 V1 数量现在按整个副本槽位统计，包括已回填副本 ID 的其他旧账号对象；该数量非零时节点目录不得判为一致。`/api/v3/replica` 向有账本读取权限的会话提供当前节点的复制邻接摘要（节点 ID、副本世代、启停与最近结果），不暴露复制授权。浏览器只在整组拓扑近期核对通过后退出旧式多服务器搬运；本机保存组证明，临时断网时继续单节点同步。证明超过两分钟且所有节点可达时重新核对，若链路已停用或目录不再一致便移除旧证明；本机执行加入、停链路或撤销授权也会立即移除。新增或更换配置节点必须重新核对。离线时旧证明仅供浏览器选择单节点同步，不表示当前整组健康。

`/api/v4/ledger/readiness` 每次读取都会以节点签名请求重新核对已启用的对端目录，并比较核对前后的本地快照。原始提交序号必须从 1 到副本 head 连续、数量和账本归属一致；当前承诺目录、承诺附件、成员账号与密钥、旧 V1 数量、拒收写入、后台游标和本地 V2 逐块校验也都通过时才返回本节点 `READY`。授权撤销、对端失联或任一证据过期会降级。此结果证明查询时本节点和已启用出站链路的状态，不代替整组拓扑验收，也不能独立证明客户端从加密提交中没有漏报附件引用。

`/api/v4/ledger/group-health` 在中继节点以持久的账本副本组成员目录为预期名单，再核对本地 `readiness`、各成员每 10 秒签名上报的链路状态、物理校验与逻辑目录。成员首次获复制授权时登记并固定节点公钥；升级时从当时有效的授权回填。上报也保存在 SQLite。成员从未上报、超过 60 秒未上报、副本世代变化、目录不一致或授权撤销时立即降级；授权过期或撤销不会把成员悄悄移出。账本管理者须通过 `/api/v4/ledger/group-members/:nodeId` 明确移出，操作同时撤销该成员在中继的全部复制授权，旧节点及备份中的密文不会自动删除。接口先检查目标节点最近签名报告、与本节点的目录一致性、双方附件物理状态和本节点数据完整性；还要求移出后至少保留另一台已核实的组成员。任一项未核实则返回 `GROUP_MEMBER_NOT_VERIFIED`，只有提交匹配目标节点 ID 的 `confirmUnverifiedRemoval` 才能继续。网页要求管理员输入完整节点 ID。此检查仅表示最近一次可见状态，不证明离线目标没有独有写入；迁出前仍需停止目标写入并保存其数据直到核对完成。同一个节点 ID 换签名公钥会被拒绝；仍在组内的成员可用原公钥续签，明确移出的旧身份不能仅凭新授权恢复，须以新节点身份和空副本重新加入。两个局域网成员必须都就绪，三节点组才为 `READY`。中继现用节点签名响应向局域网节点下发含成员公钥及退休标记的组快照；局域网节点持久保存并拒绝目录回退，网页可在任一节点查询整组状态，快照超过 60 秒立即降级。此目录仍由中继管理，尚不是所有者签名的多节点控制链；浏览器“可互换副本组”仍要按实际配置的节点单独验收。

三节点自动化规模演练在单机上启动三个独立节点，先复制 401 条提交和 40 个 64 KiB V2 附件；中继断开时两端各新增同样规模，再恢复并在一端附件复制中重启。最终三个节点的 1,203 条提交与 120 个附件目录摘要一致，且从每个节点取回同一附件密文后可解密为原文。这验证了分页追赶和持久游标恢复，不代表跨公网带宽、海量图片或整机故障的生产性能结论。每页附件最多以 4 个独立对象并发传输；一项失败时等已开始的对象收尾，记录成功传输量、使本地物理校验失效，并保留整页游标供下轮去重续跑。演练还发现双向附件分页结束时间不同时会交替重开已完成方向的扫描；现由工作线程分别跟踪拉取与推送完成状态。节点请求按 IP 保留宽限流，并在签名授权验证后按授权单独限流，避免共用出口 IP 的合法副本互相挤占原有额度。

可选压力演练 `ZICHAN_REPLICA_STRESS=1 npm test -w @zichan/sync-server -- --run test/large-three-node-replica.test.ts` 将同一场景扩大到 1,000 个附件。初版全部为 64 KiB，约 64 MiB 原文量；2026-10-09 在单机运行约 100 秒，三端最终均有 1,000 个附件与 1,203 条提交，目录一致、双向游标归零，抽样密文可解密。压力演练发现跨后台任务的双向扫描会在超过单次 32 页上限时交替重启，导致对象虽已传齐却迟迟不能完成目录核对；现保留已完成方向的扫描状态，待另一方向追上后才开启新扫描。此耗时含测试数据生成、加密、复制和校验，不能推算真实公网部署的传输速度。

2026-10-10 将办公节点的一件样本改为约 5 MiB、分成六个加密块的图片量级对象，并在公网节点只预存首块后恢复连接。普通三节点演练和 1,000 附件压力演练都通过；后者本机约 122 秒，三端最终均有 1,000 个附件与 1,203 条提交，逐块取回并解密该对象的完整原文。此测试验证大对象缺块续传、断线后去重和整组目录收敛；其他 999 件仍为 64 KiB，不能代表数千张真实照片的跨网性能。

另有进程级演练将三个生产服务入口分别启动为独立进程，通过 HTTP 注册、开通同一账本并建立星形复制链路；关闭中继进程后，两个局域网节点各自写入；用原数据目录重启中继后，定时后台任务使三端提交目录收敛，且中继的节点 ID 和公钥保持不变。该演练验证服务进程边界、定时调度和重启恢复，仍不能代替三台真实设备的网络、磁盘和浏览器操作验收。

统一登录三节点演练使用公网节点签发所有者和成员身份，再将账本复制到家庭、办公节点。成员分别登录两个局域网网页，各节点创建独立会话；关闭公网节点的 HTTP 服务后，两个本地会话仍可刷新并各自写入。公网节点恢复后，三节点的两条离线提交收敛。另一个本机三节点 HTTP 演练让同一成员保留个人账本、加入共享账本，在家庭和办公节点分别登录两本账；身份节点离线时两站都向两本账写入，恢复后每本账的两条提交分别收敛到三节点，并在三节点分别解密核对记录。该演练发现身份节点原先错误要求受邀成员的默认个人账本路由指向共享账本；现在改由共享账本的成员控制链授权，未启用成员控制的旧单人账本仍只允许其所有者登录。本机 Chrome 演练还验证同一账号在公网、家庭、办公三个独立网站交替进入个人和共享账本：本机缓存按账本隔离，两个账本的支出记录互不混入；公网停服期间，办公网页向共享账本、家庭网页向个人账本继续写入；公网恢复后，两本账的提交数和目录哈希各自在三节点一致，公网网页分别读到断网记录。再次进入共享账本须重新解锁成员密钥，在非托管副本进入个人账本须输入恢复码。真实设备上的三站网页交替仍需验收。上述测试覆盖推荐的单一身份签发方拓扑；新的设备在身份签发方离线期间仍不能首次登录其他节点。

当前统一登录的身份签发节点必须就是目标副本直接连接的源节点。节点签名的账号身份和公钥记录只验证这个直接对端，公网中继不能替家庭节点转发其身份签名。因此采用家庭、办公只主动出站连接公网中继的星形拓扑时，公网节点现在必须承担内建身份签发方；“公网仅中继、另一个节点或外部 OIDC 签发身份”尚未实现。加入和登录接口会拒绝把中继冒充成原签发方，后续扩展需要可核验的签发方证明及独立登录路由。

已经从其他节点接入的联邦账号不能在本节点再次签发登录授权码；即使是升级前留下的授权码，节点换票接口也会拒绝将其改写为本节点签发。副本账号身份接口同样拒绝把联邦账号报告为本节点账号。这是单一直接签发方拓扑的明确安全边界；外部 OIDC 接入需要独立设计账号映射、登录回调及客户端密钥解锁流程。

浏览器三站演练使用同一台机器上的三个独立网站来源（`127.0.0.1`、`127.0.0.2`、`127.0.0.3`）：所有者先在公网节点创建账本并记账，再通过统一身份分别登录家庭和办公节点，解锁各站缓存并各记一笔支出。三节点后台复制后，提交数量及目录哈希一致；浏览器在办公和公网网站重新同步，均能看到三个网站录入的记录。随后关闭公网节点 HTTP 服务，家庭和办公网页使用各自既有会话再次记账并同步到本地节点；公网恢复后，三端目录重新一致，办公和公网网页都能看到断网期间的两笔支出。网页“我的账号”现提供“查看账本副本与状态”入口，演练通过该入口进入副本页。另一个 Chrome 演练从公网网页登录两个空节点的管理员账号，在界面核对各节点完整公钥，分别建立家庭和办公后台复制链路，要求三端提交目录一致、整组为 `READY · 3/3`，并在网页显示该状态。演练发现浏览器自动上传的加密备份仍用 V1 对象格式，曾被误计为待迁移的旧附件，使健康状态一直停在 `BOOTSTRAPPING`；现按备份目录排除该对象，真正的 V1 附件仍阻止 `READY`。该演练还发现局域网 HTTP 地址会被原静态 CSP 阻止；现仅在显式启用局域网 HTTP 的部署中放宽托管网页的 `connect-src`，应用层仍拒绝未经许可的公网 HTTP 地址。这些演练覆盖真实 Chrome 中不同来源的 Cookie、登录跳转、本地缓存、记账、网页配置与公网短时断线恢复，但仍不能代替跨三台机器的网络、证书、磁盘与长期运行验收。

登录后的网页在恢复会话和查看多个副本时会反复读取 `/api/auth/me`。单机多站浏览器演练发现原先每 IP、每分钟 20 次的统一认证接口限额会误伤正常重登；现在此只读接口的限额为 120 次，登录等敏感接口仍为 20 次。管理员从网页建立两条副本链路并往返三站后，普通 API 共用的 120 次限额也会误伤后续账本同步；普通 API 限额现为每 IP、每分钟 600 次，管理员、附件和节点签名请求仍使用各自限额。服务端限流测试与三站浏览器演练均已通过。

人工审核的浏览器演练先用真实网页创建账本、支出、账号加密密钥及签名成员控制，再向同一服务端归档一条加密的隔离提交。所有者在网页查看并校验密文，必须先选择变化字段的最终值并确认审核，才能创建新合并提交。演练验证服务端保存了 `replay` 签名处置，网页显示合并后的支出描述；这验证了交互路径，但不替代真实离线成员写入触发隔离的三节点演练。

旧成员写入处置的三节点演练先在公网节点接受旧代次密文提交，再于家庭节点移除该成员、轮换账本密钥并写入同一条资产的当前值。后台复制把旧写入隔离；所有者设备在当前修订上人工选择字段并生成新提交，家庭节点收到替代密文提交和签名处置后，公网与办公节点均收敛到相同的两条活动提交及控制链。此演练验证数据层、节点复制和签名处置的组合；网页字段选择另有真实浏览器演练，实际跨机器断网和整机重启仍需单独验收。

提交目录摘要按提交 ID、内容哈希、密钥代次和写入者计算；同一提交可以在不同节点分别随机加密，故密文及随机 IV 不参与跨节点目录一致性判断。客户端拉取时仍须解密提交并核验内容哈希。服务器只靠目录相同无法证明密文可解密，也无法从密文中发现从未上传的附件引用；这两项不能单独支持 `READY`。

## 阶段性实施记录（以下记录早于上表）

三节点自动化故障演练已覆盖公网中继断开期间两台局域网节点各自写入，以及中继恢复后的提交收敛和重复同步去重。此项只证明提交复制；真实部署中的附件、成员密钥轮换和整机重启仍需演练。受控账本的成员现可在新网站用自己的账号加密密钥和成员密钥包首次解锁，旧账本及尚未启用成员控制的所有者仍沿用原恢复流程。账号密钥可在身份节点用原密码重新加密，公钥和成员授权不变；已下载的旧密钥包不会因此失效。完整 `READY` 判定、多账本账号模型、旧附件迁移和过期写入处置仍未完成。

浏览器已在远端副本均有附件对象时延迟下载正文与缩略图；打开预览或导出时再按需取回。本地附件需要传给另一个尚缺对象的旧式浏览器同步目标时，浏览器仍会临时下载并转发。多账本账号的会话级迁移顺序见 [multi-ledger-account-migration.md](multi-ledger-account-migration.md)。

成员控制页会向所有者列出当前节点已拒绝的过期或无效提交。schema 20 对新发生的拒收在单条 16 MiB、每副本 512 MiB 的上限内归档密文；所有者可以取回、解密并核验提交内容。旧版已记录的拒收没有密文归档，仍须从发送节点及备份恢复。已知拒收提交 ID 不能经账号接口以当前身份自动重署；受控账本浏览器也不拉取旧代次提交或把远端来源提交转发给其他节点。所有者明确审核后，若原父提交齐全且相关聚合从原分支起没有变化，浏览器可生成新的本地提交并上传；若相关记录已变化，可在成员页逐字段选择当前值或隔离提交值，生成以当前修订为父的新提交。审核快照发生变化时会拒绝合并并要求重新核对。schema 21 将所有者的重放或放弃决定加入签名控制链，在每个节点保存派生处置索引。节点复制控制链后，把已处置的原提交从活动目录排除，但仍保留原密文以供审计；提交拉取接口返回仅含 ID 和哈希的隔离标记，节点和浏览器据此连续推进游标。未处置的拒收以及已签名重放但尚未收到替代提交都会阻止 `READY`。发送节点数据与备份仍须保留。

节点签名身份、按单个账号账本签发的限期授权、服务器后台双向提交复制、密钥包代次复制、账本范围 V2 附件分块复制及续传已经实现。V2 附件删除与显式恢复通过持久状态版本传播；并发同代次操作由删除优先，回收区清理不清除删除标记。链路独立保存双向提交、附件与状态扫描游标、对端公钥和副本世代；浏览器关闭后服务器每 10 秒重试，积压页在一次作业内连续追赶。新建链路可明确选择活动时自动续期的授权：只有未过期、未撤销授权下的有效节点签名请求才能把有效期从临近到期延长 30 天；旧授权仍按原到期时间结束。Web 同步设置提供建立、续签、停用、活动授权列表和撤销入口。旧服务器继续使用原有 V1 附件格式；新服务器上的旧附件由客户端读取并逐步重新上传成 V2。

默认记账流程仍按单账号启用；成员共享入口已接入但尚未完成多账本账号迁移和生产故障演练。服务端 schema 13 已建立独立的 `ledger_replica_slots` 与账号到副本的路由。提交拉取、写入、去重、所需能力和配额计算已按副本槽位进行；旧账号提交表仍作为原账号写入时的迁移影子，槽位的连续序号也回写旧副本头。已有同一 `replicaId` 的账号路由可以读取、写入同一提交序列，服务端已有签名成员授权校验，浏览器已接入成员密钥解锁与所有者授权入口；一个账号仍只能绑定一个账本副本。共享槽位不能由单个账号执行“替换整个账本”。密钥包仍是整个账本的旧密码封套，附件对象表仍保留用户名主键，V2 上传配额已按副本共享计量。同一 `ledgerId` 下原有的不同账号历史会保留为不同 `replicaId`，迁移时不自动合并。源节点的账本账号签发授权后，目标节点管理员可以在尚无该账本副本的节点上原子创建独立的统一登录账本账号、副本槽位、密钥包和复制链路；节点管理员自己的账号不获得该账本访问权。旧的预先注册、绑定同一 `ledgerId` 和密钥包的加入路径仍可用于迁移。已绑定的公网身份通过一次性授权码在目标节点建立本地会话，已有本地会话不依赖公网节点续期；自动开通账号只能通过身份节点登录，目标节点不提供本地密码登录或密码重置；受控账本成员可用自己的账号密钥在新站点解锁；旧账本仍需账本密钥恢复码。浏览器多服务器桥接只保留给未进入服务器后台复制的旧账本；已组网账本即使节点暂时未就绪也不会回退到桥接。节点会比较提交逻辑元数据、V2 附件清单、删除状态、密钥包、账本所需能力、账号身份、加密公钥、签名成员控制链及当前成员密钥封套的签名目录摘要，并记录最近一次一致或差异；每个已绑定副本都会在独立后台任务里逐块校验本地新版附件密文，目录变化时重扫，成功后每 24 小时重扫。损坏对象会退出可用目录并保留在 `blobs/quarantine/`，下一轮复制可从健康对端补回；补回后立即使旧校验结果失效并重扫。隔离区计入物理磁盘展示和服务器备份，但不计入当前账号的逻辑附件配额。这个结果只证明本地物理附件状态；控制链与当前成员封套已进入跨节点目录校验，但完整副本 `READY` 仍缺少成员开通与所有承诺附件的综合判定，过期写入也缺少处理流程。账本多成员权限与每成员密钥封套的底层机制已建立；浏览器已接入账号密钥建立、成员密钥解锁、所有者邀请与移除入口，但仍需多账本账号模型和生产环境故障演练。过期写入会被拒绝并记录元数据索引，所有者可在产品中查看；自动处理尚未完成。当前界面展示提交游标与两侧 head、V2 附件数量及密文字节、本轮已核对字节、已记录分块的累计传输字节与最近刷新间隔的平均速度、删除标记、旧版待迁移数量、最近完整扫描、物理校验结果和错误；大附件每个密文分块经对端确认或本地写入后立即持久累加，包含未完成对象的已确认分块；单块小附件按最多 20 个对象的页面合并写入以减少数据库开销。进程在页面结算前退出可能使统计少计小附件，失败重试造成的重复传输可能使统计多计，因此它是传输进度指标，不等于对象逻辑大小或链路总流量。已核对字节不是已传输字节，尚不能声明整本账本已 `READY`。不要把本阶段部署为可互相信任的多用户账本。

后续顺序：完成副本槽位附件存储及配额迁移，建立会话级多账本账号模型，补齐承诺附件和成员开通的 `READY` 判定，再完成过期写入修复并退出浏览器多服务器搬运主流程。每阶段都应验证独立备份、回滚和三节点故障恢复。

schema 12 升级到 13 会在 SQLite 内复制现有提交密文；附件文件不会在此步骤复制。启动前会按提交密文字节、记录数、索引和 WAL 余量检查 SQLite 所在磁盘可用空间，不足时停止迁移并保留旧提交。正式升级前仍须按维护命令创建并验证独立备份；迁移期间的提交空间占用会暂时接近两份，后续切换旧读写路径并经备份验证后才能清理旧表。

新上传的 V2 附件已使用账本副本槽位计算物理目录，不同账号即使绑定同一 `ledgerId` 也不会误用同一目录。旧 V1/V2 对象保持原目录，读取从目录索引取得实际路径；启动重建目录索引时保留该路径。附件索引和删除状态仍保留用户名主键，V2 对象通过副本 ID 共享；V2 上传配额已按副本计量。同副本成员可按相同密文清单接续未完成的 V2 分块上传，包括启动时回填了副本 ID 的旧上传；V1 或无法确认副本归属的上传仍限原账号。

附件对象目录、V2 删除状态和未完成上传现在记录可为空的 `replica_id`。新 V2 上传直接写入，旧记录在账号仍绑定同一账本时由服务器启动过程回填；无法确认归属的旧记录保持原样。服务器间的 V2 附件清单、删除状态列表、完整性目录和本地逐块校验已按副本 ID 查询；单对象读取、删除、恢复和新上传去重也能定位同一副本中的已有 V2 对象，原记录的用户名不会因另一成员操作而改写。旧版未标注记录仍限原账号读取。此步骤只更新 SQLite 元数据，不移动或复制附件密文；对象表与删除状态表仍以用户名为主键；V2 用副本 ID 计算总用量和账本宿主账号配额。旧 V1 对象及运维后台按用户名显示的容量仍需进一步迁移。

schema 14 增加按副本保存的初始所有者锚点、签名成员事件链和每成员密钥封套。初始事件须由当前账号签署，并匹配该账号已登记的加密公钥；后续成员增加还要匹配目标账号已登记的加密公钥。服务端保存前及重启时重验签名、连续序号、哈希和权限代次。封套内部读写限制为有效成员及当前代次，写入只能由账本所有者执行。控制链存在时，浏览器 v3 账本请求、提交读写和节点授权签发按成员角色检查；旧账本没有控制链时保持原有单账号行为。事件和封套已通过节点签名请求双向分页复制，控制链分叉会停止复制。登录账号可通过 `/api/v4/ledger/control`、`/api/v4/ledger/control/events` 和 `/api/v4/ledger/member-envelope` 创建、读取受权限保护的控制状态及密钥封套；有效成员可以经身份节点登录，在目标节点获得本地会话；各成员的加密账号私钥包也由身份节点签名接口复制。浏览器成员密钥解锁和首次远端恢复已接入；所有者可以把成员事件与新代次全部密钥包原子写入源节点。schema 15 保存提交密钥代次和写入者；受控账本的节点新提交必须匹配当前代次和成员密钥包，旧代次写入会被拒绝并记录待处理索引。尚不能据此开放多成员操作。旧版整账本密钥包和托管保护接口在成员控制链存在时仅允许所有者读取。

## 范围与拓扑

一个 `ledgerId` 可以在多台独立节点上拥有副本。每台节点均可提供 `/app/` 并接收本地客户端写入。公网节点是中继和可选身份入口，不是账本的唯一真源。家庭和办公室节点主动向公网节点建立出站连接；节点离线时继续接受已授权的本地写入，恢复连接后按提交 ID 收敛。各节点无需直接互连。

schema 16 增加由签名成员链派生的账号账本索引，并给节点会话记录当前副本 ID；旧会话和旧账本从原路由回填。已有个人账本的本地账号可以成为第二个受控账本的成员；服务端内部会话选择、提交和成员接口已支持按副本 ID 定位。公开切换接口仍未开放，旧保护设置、复制授权及浏览器隔离存储需要继续迁移。

目标是浏览器只与当前节点同步，节点之间的提交和附件复制由持久后台任务负责。现有浏览器多服务器桥接在迁移期继续可用；不得把它的成功结果当作节点间后台复制的健康证据。

手动加入已有账号副本时，服务器在创建链路的事务内检查目标副本是否已有提交、任何状态的附件、删除状态、未完成上传、成员控制链或待处理拒收写入；发现残留就拒绝自动加入，要求先处理原有数据。其他账号和其他副本的附件不影响空目标的加入。统一身份新建副本通过独立的原子开通流程加入。

## 身份、权限与信任

- `ledgerId` 是逻辑账本身份；`nodeId` 是持久节点身份。现有 `serverId` 在迁移期对应 `nodeId`，但 OPAQUE 登录公钥不能充当节点签名密钥。
- 每个节点持有独立的签名私钥。加入时账本所有者核对并固定目标节点的 ID 和公钥，签发限定 `ledgerId`、节点、权限和有效期的复制授权。节点间调用不能使用用户密码、浏览器会话或 refresh token。
- 网页首次建立节点复制前展示源节点和目标节点的完整签名公钥，要求管理员与各节点本机 `/api/health` 核对；确认后把公钥固定在连接资料及账本共享服务器目录。之后的登录身份检查、连通性测试和复制加入都会拒绝同一服务器 ID 下的签名公钥变化。此核对仍依赖管理员访问可信的节点本机环境。
- 自动续期只延长持续活跃的已授权节点；停用副本链路时立即停止本地复制，并保存远端撤销任务。源节点暂时离线时状态显示“撤销待确认”，恢复连通后后台使用节点签名请求重试；源节点对已经撤销的同一授权返回可验证的幂等确认。旧版已停用链路没有可验证的远端结果，仍显示“未知”，需要人工核对。撤销和过期均不能由节点请求自行恢复；重新加入必须取得新授权。
- 节点管理员管理部署、容量和副本作业；账本成员权限另行判定。节点管理员身份不自动授予账本解密或写入权限。
- 现有默认托管模式允许获授权服务器解密账本。任何界面或文档不得称其为端到端保密。私密模式也无法抵御由恶意节点提供的篡改后网页代码；这需要另行定义可信客户端分发边界。
- 全局账号以 `(issuer, subject)` 绑定稳定 `accountId`，节点会话本地签发且不复制。统一身份及多成员账本晚于单人节点复制交付。迁移期各节点使用独立账号，并显式绑定同一 `ledgerId`。
- 成员变更和密钥授权是受签名保护的控制数据，不能只把加密 `MemberRemoved` 事件交给无密钥节点执行。撤销在尚未收到新版权限的离线节点上不能即时生效；重新联通时必须按权限版本隔离过期写入，不得静默接受。
- 共享核心包已定义成员事件的签名、固定初始所有者、连续哈希链、所有者权限校验及移除时的密钥代次递增，并接入服务端持久化、节点复制与现有账号请求授权。离线过期写入已在接收节点被拒绝并留下待处理索引，但修复流程、多账本账号模型和生产环境三节点故障演练尚未完成，因此当前产品仍不能默认启用多成员账本。

## 数据与复制不变量

1. 节点加入的是一个空的**账本副本槽位**，并非要求整台服务器为空。已有不同 `ledgerId` 或独立提交历史的槽位不得自动覆盖或合并。
2. `commitId + contentHash` 唯一标识同一业务提交。现有随机 `commitId`、父提交 DAG 和加密提交格式保留；不要求改为内容哈希 ID。服务端可原样复制当前提交密文，因为提交 AAD 不含目标服务器；客户端仍须解密并验证内容哈希与业务约束。
3. 每条节点链路独立保存账本、对端身份、公钥指纹、流世代、连续拉取游标、确认状态、最近成功时间及错误。只有传输、持久化和确认完成后才能推进游标。重试可重复发送，不得重复写入或漏过序号。
4. 实时通知仅用来唤醒任务。正确性取决于周期性差异检查、缺失对象补传和可恢复的持久作业。一个节点失败不能停止其他健康链路。
5. 复制层传播密文及必要的路由元数据，不选择业务冲突赢家。客户端按现有 DAG 规则校验、隔离无效提交并处理冲突。
6. 附件对象须使用账本范围的密钥化 ID 和独立格式版本；不得直接暴露明文 SHA-256。V2 的分块密文和 AAD 不得包含节点 ID 或节点用户名。保留现有 4 MiB 分块、块哈希及缺块续传，并允许旧格式与 V2 在迁移期间共存。
7. 提交收敛、附件补齐、备份归档和客户端缓存是不同状态。删除副本先撤销未来复制授权并停止写入，再按独立的保留策略处理节点数据；离线节点及已有备份无法保证即时物理删除。

## 副本状态

`JOINING → BOOTSTRAPPING → CATCHING_UP → VERIFYING → READY`。链路阶段保存在服务器 SQLite；后台复制完成后再次核对目录、成员、密钥、承诺附件及本地物理状态才进入链路 `READY`，超过 60 秒未复核的旧 `READY` 对外显示为 `VERIFYING`。停止链路先进入 `REVOKING`，远端授权确认撤销后才进入 `REVOKED`；旧版停用链路若没有远端确认记录则显示 `STOPPED`。失败保留错误和可恢复游标。这里的链路状态与本节点实时完整性状态、整组健康状态是三种不同证据；链路 `READY` 不能单独证明所有节点都完整。节点在提交及授权就绪、附件仍在搬运时可以显示“可记账，附件补齐中”，但不得显示为完整副本。健康页分别展示提交数、附件数、待传字节、最后一次成功复制时间和身份/授权错误。

### 附件承诺目录

服务器无法读取加密提交中的附件引用，因此客户端在完成某个提交前沿的拉取、应用和上传后，应发布该前沿的附件承诺目录。目录列出正文和缩略图的账本范围 V2 密文对象 ID，按 ID 排序并记录数量和摘要；不上传明文文件名或内容哈希。大目录按页暂存，全部页面到齐后才原子发布。发布时再次核对提交数量和逻辑目录摘要，拒绝过期前沿；同一前沿出现不同附件目录时报告冲突，不以最后写入者覆盖。新前沿的目录可替换旧目录，旧目录在新目录完整发布前继续保留。节点之间用签名请求分页复制目录和前沿信息。

完整副本状态须同时满足：承诺目录覆盖当前提交前沿、目录中的每个对象在本节点为可用 V2 对象且完成逐块物理校验、节点间目录一致、成员账号及当前密钥包齐备、没有待处理的过期写入或旧版附件。未发布目录、目录上传中或目录落后时只能显示“完整性待核对”。该目录是已认证客户端对解密后账本的声明；服务器不能单独证明客户端没有漏报引用，客户端生成时必须从全部已应用提交及未决冲突计算引用，并在完整同步后发布。

## 分期与验收

| 阶段 | 交付 | 最低验收 |
| --- | --- | --- |
| 1. 规则 | 本文、版本与迁移约束 | 用三节点断网/重连、冲突、错账本、撤销和大附件案例审查行为 |
| 2. 节点身份 | 持久签名密钥、身份固定、按账本授权 | 身份变化、签名重放、错账本和已撤销节点均被拒绝；备份恢复保留身份 |
| 3. 提交复制 | 节点出站作业、游标、差异补传 | 关闭所有浏览器后，三节点写入经公网中继收敛；断网重启后无漏传 |
| 4. 附件复制 | 账本范围 V2 密文、后台分块搬运 | 数千附件和中断续传完成校验；浏览器不承担节点间流量 |
| 5. 界面 | 加入向导与分层健康状态 | 用户能区分可记账、附件补齐中、完整副本及失败 |
| 6. 统一身份 | 全局账号、各节点会话及现有账号映射 | 同一账号可在三站登录；公网身份入口不可用时已有有效本地会话继续工作 |
| 7. 多成员 | 账本权限、每成员密钥封套和代次轮换 | 权限与节点管理隔离；撤销者无法读取未来新代次，过期离线写入被隔离 |

生产数据迁移必须为追加式并可回滚：先备份并验证原服务器身份、账号、密钥封套、提交及附件；新旧协议并存期间不得重置 `ledgerId`、提交 ID 或加密密钥。三节点真实故障演练、类型检查和受影响工作区测试通过后，才可默认启用相应阶段。
