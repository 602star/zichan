# 账号模式实施状态

以 2026-09-12 当前设计为准，不迁移旧浏览器账本或旧用户密钥。本文替代早期分批实施计划；详细验收见[交付记录](release-readiness.md)。

## 已接入的流程

- Web 使用账号入口；桌面保留本地和服务器模式。账号缓存按服务器和稳定 accountId 隔离，数据库、附件、草稿、备份、设备身份与密钥使用账号作用域。
- 支持托管的主服务器默认托管密钥，注册后直接初始化账本，新设备登录后自动恢复。私密模式使用独立恢复码，账号改密不会改变恢复码。详见[账本保护](ledger-protection.md)。
- 附加服务器默认仅中继密文；绑定后可按服务器能力明确授权托管。不同服务器使用独立账号与设备会话。
- 部署者在独立 `/admin/` 页面显式创建唯一 Owner，普通注册不会取得管理员权限。管理 Cookie 与记账入口隔离，角色和会话在服务端校验。详见[管理后台](server-admin.md)。
- 同站会话使用 HttpOnly Cookie，跨站连接使用 Bearer 会话。账号密码不持久化，Stronghold 保存设备会话和包装后的本机密钥材料。
- 可主动记住设备七天或设置本设备离线密码；生产 Web 安装静态缓存后支持离线冷启动，更新等待全部旧页面关闭。详见[离线应用](offline-app.md)。
- 设置页支持主动改密和撤销自己的其他设备；唯一 Owner 可在停止服务器后通过本机维护命令取得限时一次性恢复码。详见[账号安全](account-security.md)。
- 同步使用提交 DAG；本地写入触发调度，多服务器中继、冲突处理与远端账本替换各自有明确流程。远端替换不是独立账本合并。

## 后续能力

独立账本安全合并按用户要求可后续实现：需要预览、引用 ID 重映射、来源记录、保护备份、目标版本校验、附件恢复及统一成本重算。现有可移植导入的 merge 和远端替换不能当作这项能力。

## 验证与部署

使用 `npm test`、`npm run typecheck`、`npm run lint`、`npm run build:server` 和 `npm run test:e2e:account` 验证代码。具体结果、原生 Windows 与手机视口覆盖范围见交付记录，不以历史测试数作为当前版本证明。

生产及公网部署使用可信 HTTPS；开发、localhost 与显式开启 ALLOW_INSECURE_HTTP 的私有局域网可使用 HTTP。HTTPS 部署恢复演练只操作隔离实例，正式服务升级仍需部署者安排。服务器当前 schema 为 `server_key_custody_v10`，备份必须包含托管主密钥 `custody.key`。
