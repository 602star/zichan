# 正式版账号模式重构实施记录

2026-09-09 新版入口及账号缓存隔离已接入主流程，详见 [Web 账号 v2](web-account-v2.md)。本记录下方的旧本地兼容、仅限原账号重登录等阶段性限制已被新版替代；不再迁移旧浏览器账本。

目标：Web 同站账号优先；桌面保留本地使用；共用加密提交同步、离线缓存和加密备份。独立账本必须经过预览确认并统一重算，不能以原 ID upsert 或替换数据库冒充合并。

## 第一批：已实施的基础

- 服务器提供稳定的随机 accountId，随登录、刷新和 auth/me 返回。账号缓存身份使用 origin + serverId + accountId + ledgerId，不使用显示用户名。
- 服务端 schema 7 增加身份表。对当前紧邻 schema 6 只做事务性增加 ID，不清空凭据、绑定或业务数据；这不是承诺兼容所有开发期数据。
- 空服务器必须用部署者本地 owner-setup.secret 显式创建所有者。普通访客不能抢先取得管理员。认领与用户创建同事务；并发只有一个成功，初始化秘密不进入日志、共享链接或浏览器持久存储。
- 同站 Cookie 会话已接入首次连接和同步页登录。刷新秘密不返回页面脚本，访问令牌仅内存。Origin、自定义头和 Cookie/JSON 传输分离；生产 HTTPS 的 Cookie 使用 Secure + HttpOnly + SameSite=Strict。
- 后台与附件同步不再要求密码。刷新失败不会自动密码登录。网络错误保留待重试会话；认证失败提示重新登录。身份检查仍逐个覆盖备用地址，同一会话刷新共享单次执行。
- 浏览器不持久化账号密码或邀请码；Stronghold 改存刷新令牌及会话 ID。过期异步认证不得覆盖已退出或改变的本机会话。
- 新增不可变 AccountScope 和 AccountCache。独立 IndexedDB 名称隔离账号；数据库密文认证上下文包含完整作用域。缓存接口已测试，但尚未切换主启动流程，现有单库数据不会被自动迁移或清理。
- 修复同时托管 Web 且带子路径时，GET 账号接口被 SPA 回退误返回 HTML 的问题；覆盖子路径 API 与网页路由回归。

## 尚未实施，不能视作已交付

2026-09-09 补充：独立 `/admin/`、Owner/Admin/Member 权限、用户管理、限期邀请和事务审计已接入；详见 [服务器管理后台](server-admin.md)。服务端当前 schema 为 8，下面的账本启动与同步项目仍未因此完成。

1. Web AccountBootstrap：移除模式选择，一次密码输入同时完成 OPAQUE 认证、本机解锁和账本密钥解包；创建账本的服务端绑定与初始密钥需要原子初始化。
2. 将数据库、附件、草稿、备份、设备身份和密钥包全部接入同一个 AccountScope；不允许只切数据库却继续使用全局密钥或草稿。
3. TrustedDeviceVault：明确勾选、期限最多 7 天，保存包裹后的随机密钥材料，不保存密码；失效、退出、离线以及加密缓存保留语义必须完整。
4. 统一改密：OPAQUE 记录和账号密钥包可恢复原子更新。账号模式不得保留仅修改账本密码的入口；密码找回和 Passkey 不在此批范围。
5. 离线静态资源缓存与安全更新流程；当前只有数据缓存，不能保证离线冷启动。
6. SyncRuntime：本地提交后的快速调度、运行期间 dirty drain、手动/自动共用运行时、退出中止旧请求、远端变化通知以及区分记录与附件的真实确认状态。
7. MergeCoordinator：pull-only 预览、引用 ID 重映射、来源 receipt、统一成本重算、源/目标保护备份、目标版本 CAS、附件预上传与幂等恢复。旧 replace/join 和 portable merge 仍不能当作此功能。

## 测试和运行

- `npm test`：全工作区单元与接口集成测试。
- `npm run typecheck`、`npm run lint`。
- `npm run build:web`、`npm run build -w @zichan/sync-server`。
- `npm run test:e2e:account`：先构建，再在隔离浏览器上下文验证真实同站登录、HttpOnly Cookie、令牌轮换、退出和存储中无密码。可用 `PLAYWRIGHT_EXECUTABLE_PATH` 指定本机 Chrome 或 Edge，不读取个人浏览器配置。

2026-09-08 本机验证：569 项单元/集成测试通过，类型检查、Lint、Web 与服务器构建通过。Chrome、Edge 各通过真实同站账号流程测试。账号浏览器测试已加入 CI，但尚未运行远端 CI。Web 构建仍有账本包体较大的警告，不影响本次构建通过。

首次部署先启动服务器，由部署者从日志给出的本地路径读取 owner-setup.secret，在初始化界面填写。不要把秘密放入 URL、二维码或公共文档。当前不支持 Web Cookie 通过普通 LAN HTTP 工作；生产与 LAN Web 请配置可信 HTTPS，开发可使用直连 localhost。

本轮不部署远端、不自动重启用户正在运行的服务、不清理现有数据库。源码完成构建后，仍需在合适时间由用户重启现有服务才能使用新端点。
