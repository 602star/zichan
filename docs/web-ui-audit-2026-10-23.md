## 已确认的问题

### P1 · 第三级文字在多数主题中对比度不足

- **位置：** `apps/web/src/theme.ts` 的 `--fg-subtle`；`apps/web/src/styles.css` 的 `--text-tertiary`，被页面说明、图表辅助标签和记录元数据反复使用。
- **证据：** 对内容表面计算得到赭石、鼠尾草、梅子浅色主题分别为 **2.77:1、2.59:1、2.91:1**；赭石和梅子深色主题分别为 **4.21:1、4.43:1**。这些文字通常是 11–12px，低于 WCAG 1.4.3 对普通文字的 4.5:1。
- **影响：** 金额旁的时间、状态、说明及图表标签难以阅读，尤其在浅色主题和低亮度屏幕上。
- **建议：** 调整各主题的 `--fg-subtle`，逐一核对其在 `--surface`、`--surface-2` 和 `--bg` 上的对比度；不要仅提高字号来掩盖问题。可用 `$impeccable polish` 修改并复测六套主题。

### P1 · 默认浅色主题的主按钮及成功状态文字对比度不足

- **位置：** `apps/web/src/theme.ts` 默认浅色主题的 `--accent`、`--on-accent`、`--positive`；`apps/web/src/styles.css` 的 `.zc-btn--primary`；`apps/web/src/ui/FirstServerConnectionGate.tsx` 的服务器状态。
- **证据：** 白字对赭石主按钮为 **3.90:1**；登录页 detector 实测到绿色状态文字对表面为 **3.8:1**。普通大小文字均未达到 4.5:1。390px 与 1280px 扫描结果一致。
- **影响：** 登录等关键动作及服务状态信息的文字难以辨认。
- **建议：** 为浅色赭石主题选更深的主操作色或更深的按钮文字，并为浅色主题选更深的正向文字色；同时检查悬停、禁用和其他表面组合。可用 `$impeccable polish`。

### P2 · 多处 ARIA 标签页缺少对应的键盘行为与面板关联

- **位置：** `apps/web/src/screens/SettingsPage.tsx`、`Convert.tsx`、`Manage.tsx` 与 `apps/web/src/admin/SettingsPage.tsx` 的 `role="tablist"`/`role="tab"`。
- **证据：** 标签页使用 `aria-selected`，但没有方向键切换、激活项的 roving `tabIndex`；除“其他资料类别”外，大多数标签页也没有 `aria-controls` 与 `tabpanel` 关联。键盘用户仍可逐个 Tab 到按钮并点击，所以任务并未完全受阻，但语义与常见标签页键盘模型不一致。
- **影响：** 键盘和屏幕阅读器用户需要穿过每个标签页，难以判断标签与当前内容的关系。
- **建议：** 抽出统一标签页组件，补齐方向键、Home/End、焦点管理及面板关联；或者在无需标签页复合控件语义的地方改用普通按钮组。用 `$impeccable harden` 处理。

### P2 · 内置图标选择按钮在触控设备上可能只有 40px

- **位置：** `apps/web/src/styles.css` 的 `.zc-icon-options button`，用于 `apps/web/src/ui/EntityIconEditor.tsx`。
- **证据：** 该规则设 `min-height: 40px`，选择器优先级高于全局粗指针 `button { min-height: 44px; }`；网格最小列宽也是 40px。其他共用按钮和管理后台控件已有 44px 触控基线。
- **影响：** 密集图标网格较易误触，尤其是手机上编辑分类或交易对象图标时。
- **建议：** 在粗指针模式将图标格实际命中区提高到至少 44 × 44px，保持图标本身可继续较小。用 `$impeccable adapt` 处理。

### P2 · 部分 JS 块较大，首轮加载成本需实测

- **位置：** `apps/web` 生产构建。压缩前 `ledger` 块 **543.32 kB**，入口块 **422.50 kB**；SQL WASM **659.73 kB**。Vite 对大于 500 kB 的块给出警告。
- **证据边界：** 多个页面已用 `React.lazy` 拆分，这些数字不能直接相加当作首屏传输量；此次未测网络下载、解析或交互延迟。
- **影响：** 较慢设备与网络可能在首次打开或首次进入账本时等待更久。
- **建议：** 先记录登录、首次打开账本、首次进入重型页面的实际网络和交互指标，再定位入口依赖和可延迟加载的模块。用 `$impeccable optimize` 处理。

## 需要留意的实现细节

- `apps/web/src/styles.css` 用全局 `0.01ms !important` 处理 `prefers-reduced-motion`。当前可见的动态效果不多，但以后增加承载状态反馈的动画时，这条规则会同时抹去反馈；宜改为逐项提供减少动态效果的状态呈现。
- Impeccable detector 对 `apps/web/src/admin/admin.css` 两处以及 `apps/web/src/styles.css` 一处左侧强调边框报警。管理后台两处确实用颜色区分日志或账号状态，不能仅因规则命中就删除；资产转换标题的边框可在视觉审查时再判断。detector 对暖纸底色的提示与当前明确的设计文档相冲突，视为误报。
- 登录页 390 × 844 时文档宽度与视口一致，没有横向溢出；桌面和手机 detector 均发现同样的主按钮/状态文字对比度问题。管理后台入口还测得鼠尾草浅色主题品牌副文案 **2.6:1**，与第三级文字 token 问题一致。

## 做得较好的部分

- `DialogShell` 有焦点进入、Tab 包裹、Escape 关闭和返回原焦点的处理。
- 账本有跳转主内容链接、状态播报，以及按页面加载的结构。
- 移动端导航、窄屏记录卡、粗指针 44px 基线与 16px 输入字号已在样式中明确处理。
- 三套主题均提供浅色与深色 token，图表分类色与收支状态色分离。

## 建议顺序

1. `$impeccable polish`：修正六套主题的辅助文字、默认主按钮和正向状态文字对比度。
2. `$impeccable harden`：统一标签页键盘模型与面板语义。
3. `$impeccable adapt`：修正图标网格触控目标，并在真实触控设备上复核关键表单。
4. `$impeccable optimize`：基于实际性能数据处理大块依赖。
5. `$impeccable polish`：修改完成后复核视觉细节，再重跑 `$impeccable audit`。
