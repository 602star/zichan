### 0.1 一处算术纠正

上一轮我说支出页的范围切换「多 2 个控件」——**这个数是错的**。
密度探针逐个计数「可见的 `button, select, input, textarea`」（`tools/e2e/account-tests/mobile-layout.spec.mjs:235`），
所以：

- 3/6/12 做成**3 枚胶囊按钮** → **+3 控件**
- 3/6/12 做成**1 个原生下拉** → **+1 控件**

报表页 A 方案的账按按钮个数算是成立的：**23 − 3（粒度按钮）+ 2（环形/条形分段）= 22**。

支出页建议用**原生下拉**（+1），与报表页 A 的粒度下拉同形；理由不只是省控件，还因为
`docs/web-visual-density-plan.md` §4 已经指出「三种筛选语义用同一种胶囊外观表达」是问题本身。

## 2. 报表页改动（P0，A 方案）

改动最小、且当场能过护栏，所以放第一批。

1. **粒度控件换形态**：`TimeTrendChart` 头部的 3 枚胶囊按钮（`:756`–`:758`）→
   1 个原生 `<select aria-label="报表时间粒度">`。`GRANULARITIES`（`:41`）保留为选项源。
   −2 控件。
2. **构成图加环形/条形二选一**：`ReportChart` 在**日常收支页签**下，标题右侧放
   2 枚按钮的分段控件（`role="tablist"`，与粒度控件同一形态语言）。
   +2 控件。**切换在同一张卡片内部**，边框面数量不变（11）。
3. **环形图规格**
   - 数据：已有 `table`（`transactionTableFromAggregates`）里的分类行，不新增查询。
   - 取 **Top5 + 「其他」**；「其他」= 剩余全部类别之和，**不可下钻**。
   - 中心：支出总额（大字）。图例每行：`色块 · 分类名 · 金额 · 占比%`。
   - 点段 / 点图例行 = 点条形行 = 现有 `drillTransactions(category, effectiveRange)`（`:234`），
     下钻后的可移除 chip（`:347`–`:355`）行为不变。
   - **只在「日常收支」页签出现**：定投是累计曲线、物品是单位成本、转换与赛季是净变化，
     都没有「一个明确总额 + 若干构成」的语义，用环形是错的读法。
4. **不做**：不加「折线」等第三种形态（趋势用折线是另一件事，且会再花控件）；
   不把环形搬到主表位置；不改下钻与饼的联动逻辑。

**控件账**：23 − 2 + 2 = **22**（预算 24，留 2 格余量）。
**待实测**：环形比 Top8 条形矮还是高，直接决定 4.24 屏 → ? 屏；若逼近 4.5 屏，
优先把图例从「每行一个分类」压成两列或省略占比（占比移到 `title`）。

## 3. 支出页改动

### 3.1 位置（决策 1）与其代价

图区**保留在列表下方**。代价要写清楚：手机上列表可能很长，图区在第 3 屏以后，
「记账后顺手看一眼」的即时反馈价值基本拿不到；桌面端因为两图并排，影响较小。

如果以后要补，**不改位置**也能补：在列表头部筛选行右端加 1 个锚点按钮
「趋势与构成 ↓」（+1 控件，滚动到图区），比搬动整块图区风险小。

### 3.2 趋势卡升级

| 项 | 现在 | 改后 |
| --- | --- | --- |
| 窗口 | 固定 6 个月 | **3 / 6 / 12 可切**（原生下拉，+1 控件），默认 6 |
| 口径 | 无筛选（全部流水） | **不变**（决策 2）：仍读无筛选的 `summaryAggregates` |
| 标题 | 「近 6 个月趋势」 | 「**全部流水**趋势 · 近 6 个月」——口径写进标题，不写就等于埋坑 |
| 刻度 | 无 | 柱顶标金额（点击 / 悬停显示，DOM 文本可断言） |
| 净额 | 每根柱下一行小字 | 移入柱顶或删掉（决策 6 保留双柱，则净额不再是图的主角） |
| 双柱 | 收入 / 支出 | **不变**（决策 6）；补一个「收入 / 支出」图例，避免轻量模式下空柱被误读 |

#### 3.2.1 读路径（决策 2 之后已大幅简化）

口径**维持无筛选**，所以趋势继续读 `store.transactionReportAggregate(...)`
（`Transactions.tsx:323`–`:328`）——不需要把浏览范围与趋势窗口并集、也不需要切两刀。

唯一要动的是**窗口**：现在固定 `sixMonthRange(month)`（`month-5-01 ~ 当月末`，`Transactions.tsx:320`）。
3/6/12 可切之后，窗口按选中档位取 `3 / 6 / 12` 个月：

- 这条读同时供「本月 KPI 三数」与「本月分类 Top3」（`selectors/transactions.ts:969`–`:998`），
  所以窗口取 `max(选中档位, 当月)` 即可，**读次数不变**（仍是 3 条）。
- 代价：默认 6 个月与现状相同；切到 12 个月时这条聚合的扫描范围翻倍
  （行数按 `日期 × 币种 × 方向 × 分类` 增长），要实测一次响应时间。

> **上一版设想的「浏览范围 ∪ 趋势窗口 合并成一次 `transactionBrowseAggregate`」已作废**
> —— 那份复杂度全部来自「跟随筛选」，口径维持不变后它就没有存在理由了。

#### 3.2.2 口径一致性（决策 2 之后已无矛盾）

趋势维持无筛选，「本月支出」KPI 也是无筛选（`selectors/transactions.ts:969`），
**两者本来就同口径**，原先担心的「同屏两个数互相矛盾」不再存在。

剩下要做的是**把口径写在用户看得见的地方**：趋势卡标题直接写「全部流水趋势 · 近 N 个月」。
今天退款那个坑的教训不是「数字错」，而是「两个数都对、却没有可见解释」——
用户在设了筛选、发现趋势不动时，必须一眼能看出这是设计而不是 bug。

### 3.3 构成环（新增）

- 时间范围：**本月**（无筛选），与「本月支出」KPI **同一个数据源**。
  理由（这条推翻了上一版）：`vm.filteredTopExpenseCategories`（`selectors/transactions.ts:999`）
  确实已算好，但它带着**分类筛选** —— 用户筛了「食堂」之后环里只剩一段（100% 食堂），
  「钱花在哪」这个问题就自我矛盾了。构成图必须**跨分类**聚合，所以不能跟分类筛选。
- 数据：改用 `vm.topExpenseCategories`（同样**已算好**，`selectors/transactions.ts:998`，
  目前只喂 KPI 卡的那张 Top3 文字列表）。把截断从 Top3 放宽到前 6
  （`slice(0, 3)` 两处：`:303`、`:903`）→ 给 `aggregateExpenseCategories` 加 `topN` 参数，
  Top3 沿用（KPI 卡不变），构成环传 6，**零新查询、不引入第二条聚合路径**。
- 图：环形（`conic-gradient` + 中心圆孔），中心放**本月支出总额**（即 KPI 卡 1 的数字 ——
  中心数字与上方 KPI 相等，本身就是口径一致的自证）；
  取 Top5 + 「其他」（「其他」不可下钻，与报表页同一规则）。
- 标题写「**本月支出构成**」，副标题注明「不随上方筛选变化」。
- 备选（若要「跟时间范围、但不跟分类」）：需要一条只按日期范围聚合的读，
  现在没有 —— 等于新增/扩宽一条读，建议放 P3，本轮不做。
- 下钻（决策 3）：点段 / 点图例 → 跳流水页并带分类筛选。
  参考现有实现：报表页把筛选写进 `accountSessionStorage` 的
  `zichan.transactions.filterPreset` 后派发 `zichan:navigate`（`Reports.tsx:642`–`:645`），
  支出页在 `:253`–`:274` 读取并应用。跳转时时间范围固定为**本月**（与环的口径一致）。
- 手机：环形 + 图例控制在 1 屏内；若超，图例压成 2 列。

### 3.4 版式

- 桌面：趋势与构成并排（约 1.1 : 1）。
- 手机：上下堆叠；12 个月时柱距 44px + 隔月显示标签（横滑看全，`zc-trend-grid` 已有 `overflow-x: auto`，`styles.css:596`）。

## 5. 验证清单

1. `npm run typecheck` / `lint`。
2. 单测（`apps/web/test/`）：
   - 新 selector：Top5 + 其他、占比合计 = 1、金额合计 = 总额、单类别、空数据、缺汇率时标「未完整折算」；
   - **突变验证**：去掉「其他」聚合必须让断言失败（沿用今天退款修法的做法）。
3. `tools/e2e/account-tests/mobile-layout.spec.mjs`：
   - 报表页密度预算（≤24 控件 / ≤14 面 / ≤4.5 屏 / ≤35% 加粗）**必须仍绿**；
   - 触控：新增按钮高度靠 class（**不要写内联 `minHeight`**，参照 `2f2f388`）；
   - 支出页目前**不在预算里** → P0 先测基线，再把 `transactions` 加进 `DENSITY_BUDGET`，
     阈值定在「实测 + 1~2 控件」的余量，否则支出页就是下一个按钮墙。
4. 跑 e2e 前先 `npm run build:web`。
5. 手动核对：轻量模式 3 / 6 / 12 三档各切一次；筛选一个分类后确认三件事：
   （a）趋势柱**不动**且标题写着「全部流水」；（b）构成环中心数字与「本月支出」KPI 相等；
   （c）同屏不出现两个都自称「本月支出」却互不相等的数字。

## 7. 明确不做

- 不引图表库 / 不新增依赖。
- 不加「通用图表类型开关」（把选图责任推给用户，趋势画饼是错读法）。
- 不改 `ScreenId` / 路由，不加顶层「统计」页。
- 不做轻量模式「单序列 + 环比」（决策 6）。
- 不改汇总口径本身（只加只读 selector 参数与字段）。
- 不把图塞进 PDF（`report-pdf.ts` 是纯表格报表）。
