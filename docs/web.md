# Web 应用 `@zichan/web`

独立服务器后台通过 `/admin/`（支持部署前缀）进入，不依赖账本初始化；详见 [服务器管理后台](server-admin.md)。用户端的管理页面、管理跳转和本机服务器控制面板均已移除。

React + Vite 单页应用，延续设计原型（`资产记账系统.dc.html`）的视觉语言与 3 套主题，
数据全部来自 `@zichan/core` 的计算 + `@zichan/db` 的本地持久化。这是三端（web/桌面/移动）
共享 UI 的 web 壳。

当前网页版以 [Web 账号 v2](web-account-v2.md) 为准：加载账本前验证本站登录会话，账号注册需确认密码，缓存按账号分区；不再读取或迁移旧本地账本。以下旧本地模式说明仅适用于历史实现；桌面版继续保留本地入口。托管账号登录后自动解锁，私密账号使用恢复码；离线冷启动与更新见 [离线应用资源](offline-app.md)。独立账本合并属于单独流程。

## 运行

```bash
npm run dev   --workspace @zichan/web   # 开发服务器 http://localhost:5173
npm run build --workspace @zichan/web   # tsc 类型检查 + vite 生产构建
```

首次使用会在数据库初始化前选择“纯本地使用”或“连接同步服务器”。初始界面分别显示本地加密存储接口能力和浏览器防自动清理保护状态，后者不代表任意磁盘文件访问权限。IndexedDB、WebCrypto、WASM、Web Locks 是本地存储的必需能力；持久存储 API 不可用或申请未获批准时，可由用户勾选风险确认后继续普通本地模式，该选择仅在当前 Origin 保存，刷新重开仍有效，重置时清除。确认风险不等于取得授权，普通本地模式持续提示浏览器外备份。已有账本失去保护且未确认风险时先进入只读恢复，可重试、导出加密 `.zcbak`、确认风险后继续或改连服务器。实际数据库读写/加密错误仍阻止正常打开，不因风险确认而忽略。服务器模式允许使用可被清理的本地缓存，但默认开启自动同步并在每次账本写入后防抖执行增量同步。

Chrome、Edge 通常自动决定是否授予持久保护，不弹授权窗口；普通存储可能被浏览器自动清理，无痕窗口关闭后数据通常会丢失。持久保护不能防止用户主动清除网站数据。浏览器内部自动备份也可能一起消失，应把加密 `.zcbak` 导出到浏览器外并妥善保管密码。

服务器模式先显示“当前网站 / 本机 / 局域网 / 公网”地址向导、完整 URL 与高级拆分字段；完成服务器身份检查和账号注册/登录后才创建本机加密存储。账号已绑定远端账本时，首次流程要求账本加密密码，在隔离数据库完整验证提交图后直接恢复；未绑定账号才进入“直接开始记支出 / 导入备份 / 体验演示 / 高级创建”。主入口一键创建人民币轻量支出账本、系统分类和 10 个无金额支出模板，随后直接打开快速支出弹窗；不会创建账户、余额、持仓或业务流水。其他币种和更深的录入深度留在高级创建中；该处的「记账模式 · 录入深度」与设置页同名同义，只改变录入表单的深度与用词，不决定显示哪些模块。演示数据只在用户显式选择时由 `src/db/seed.ts` 创建，并持久显示“演示账本”标识。

浏览器数据保留在当前 Origin 的 IndexedDB；清理网站数据会删除纯本地账本，切换 Origin 或浏览器等同新设备。由于 sql.js 会整体导出 SQLite 快照，浏览器从打开数据库到关闭期间持有独占 Web Lock，
同一账本只允许一个标签页运行，避免两个内存副本先后覆盖。缺少 Web Locks API 或检测到其他标签页占用时会拒绝打开并给出明确提示。
Windows 便携桌面直接使用 EXE 同级 `data/ledger` 中的原生 SQLite；移动端使用平台应用目录。

## 数据链路（本地优先，按平台选择 SQLite 驱动）

```
React 组件
  └─ useSnapshot()  ── 读一批实体 ──▶  SqlLedgerStore (@zichan/db)
  └─ 选择器/派生    ── 计算 ──────────▶  @zichan/core (traceChain / seasonSummary / …)
                                          │ SqlDriver 端口
                      ┌───────────────────┴────────────────────┐
              SqlJsDriver (browser)                   TauriSqlDriver
             sql.js → IndexedDB                 Rust SQLCipher 命令桥
                                                   → ledger.sqlite
```

- **`SqlJsDriver`**（`src/db/sqljs-driver.ts`）—— 用 sql.js（SQLite 编译成 WASM）实现
  `@zichan/db` 的 `SqlDriver` 端口，于是浏览器**复用同一套 schema 与仓储**。数据库在内存中，
  顶层写入或事务提交后按顺序导出为字节，并等待 IndexedDB 落盘完成（`src/db/idb.ts`）；
  `src/db/browser-ledger-lock.ts` 在驱动整个生命周期内持有跨标签页独占锁，驱动关闭后才释放。
- **`TauriSqlDriver`**（`src/db/tauri-sql-driver.ts`）—— 桌面与移动端走原生
  `ledger.sqlite`，支持绑定到同一原生连接的事务和嵌套 savepoint；不会读取 WebView IndexedDB 旧库。
- **设备桥接**（`src/device-capabilities.ts`）—— 移动 Tauri 调用生物识别、扫码、定位和原生文件分享；浏览器保留 Web Share / Geolocation 回退。通知只使用运行环境实际提供的标准 Web Notification 接口，不授予未使用的原生通知插件权限。
- **`StoreProvider`**（`src/db/store.tsx`）—— 打开驱动、验证当前 schema 基线并判断初始化状态；未初始化时渲染三选一向导，
  只有创建或恢复完整提交后才执行附件恢复、幂等维护、定期任务与自动备份，
  向下提供 store；Repository 发布实体类型变更，`useSnapshot(scope)` 只订阅当前页面依赖的集合并重载对应数据。
  发现开发期旧 schema、未加密/损坏的旧浏览器快照，或快照不属于当前本机数据密钥时，不做猜测性转换，
  也不会自动改写或删除旧数据。初始化错误页提供“重置本机开发数据”“重新尝试”和“返回解锁”；重置前会明确提示
  将删除本机账本、附件和表单草稿；浏览器模式还会删除浏览器内备份，Windows 便携模式则保留 `data/backups` 中的加密历史归档。
  恢复只能依赖仍保留的 `.zcbak` 或服务器副本。解锁、首次初始化和重置
  都有同步 single-flight；重置先暂停并排空自动备份，再关闭 Store、锁定设备密钥并删除平台数据，避免晚到任务重新写回旧数据。
- **`derive.ts`** —— 共享派生：余额（经 `postingsFrom*` + `computeBalances`）、资产/价格查找。
  加密持仓以 **lots** 为权威口径，法币/稳定币用过账余额；期初入金用一个「外部/权益」账户
  做复式记账，算现金时排除该账户。

**每个屏的计算都提取为可测的纯 selector**（`src/selectors/{dashboard,convert,transactions,game,fixed,reports}.ts`）+
`derive.ts`，组件只负责渲染。`apps/web` 有 vitest 单测覆盖 derive、format 和
主要屏幕 selector（用 `fixtures.ts` 构造快照）。十个主页面通过 `React.lazy` 按需加载；
快照集合以 400 行分页读取，行数使用 SQL `COUNT`，不会再为每次页面写入无条件重载整库。
设置页快照只读取资产、设置和轻量分类目录，不加载全量流水或附件。数据自检使用游标遍历全部有效附件；
“清理测试流水”由 SQLite 在描述、商户和备注中分页定位 `测试 / test`，只读取命中流水及其附件，再于单个审计事务中作废和移除附件。
Dashboard 也不再加载全量流水、拆分与退款分配：仓储层返回精确十进制余额聚合、所选期间收支聚合和最多 6 条
最近流水，选择器继续用 `decimal.js` 完成求和与汇率换算，并用新旧读模型结果一致性测试守住原有口径。

### 统一日期浏览

`ui/DateRangeBar.tsx` 提供今天、本周、本月、上月、近 3 月、今年、全部时间和自定义区间；
自定义“从 / 至”均包含边界日。`ui/TimelineExplorer.tsx` 复用物品资产的列表、年度、月历、
单日钻取体验。流水、账单、资产转换、游戏记录、物品资产和操作历史使用同一套视图；总览、
报表、同步冲突、服务器日志和价格标记使用同一套区间语义。ISO 时间戳按本地日历日显示，
查询日志时转换为“本地开始日零点（包含）至结束日次日零点（排除）”。

报表折算会选择记录日期当日或之前最新的价格标记，绝不使用未来价格。账户流水按区间显示时，
仍先累计区间开始日前的过账以得到正确期初余额；月度账单按原始锚点展开，1 月 31 日不会逐月漂移。

### 多设备同步（`Sync` 页 + `src/sync-orchestrator.ts`）

同步页只使用真实 HTTP 服务器，不再提供 localStorage 演示云。连接以规范化完整 URL 为唯一保存值，拆分字段仅用于编辑；公网必须 HTTPS，认证与同步请求拒绝跨 Origin 重定向。同一 `serverId + OPAQUE 公钥` 的不同地址合并为备用地址，公钥变化会在发送账号密码前阻断。服务器自带 Web 的 `/app/` 地址会自动还原为外层 API Base Path；HTTPS 页面若被浏览器阻止访问普通 HTTP 局域网地址，界面会引导改用可信 HTTPS、服务器自带 Web 或 Windows 便携版。

`sync-orchestrator.ts` 为全部启用连接创建 `httpCommitTransport`，遇到一次 401 只尝试受控刷新，失效后要求重新登录，不再自动用保存的密码登录。账号密码不写入浏览器存储或 Stronghold。同站 Cookie 登录的访问令牌仅留内存；附加跨站连接仍以标签页 token 会话运行。每台服务器拥有独立账号与设备会话；多台服务器绑定同一账本后在同一轮拉取、合并、推送，实现局域网与公网服务器桥接。账本加密同步只携带经过身份固定的共享服务器目录，不包含用户名、密码或 refresh session；新设备从任一服务器恢复后，其余连接显示为“需要登录”。
已固定身份的连接可生成链接和离线二维码；载荷只包含应用入口、服务器完整 URL、`serverId` 与 OPAQUE 公钥 SHA-256 指纹。导入后客户端先核对 ID 和指纹，再允许发送独立账号密码。
随后 `syncReplicas()` 以 pull-all、apply、push-all、re-pull 的统一轮次让所有健康服务器收敛。

提交收敛后，`attachment-sync.ts` 单独同步正文：从账本附件密钥按服务器、账本和账号作用域派生不透明对象 ID 与
AES-GCM 密钥，4 MiB 分块支持断点续传。缩略图自动补齐，大正文按查看、保存、备份或服务器中继需求取回；
同步结果会显示每台服务器的可用副本、上传、下载、配额和失败状态。

提交以聚合为单位端到端加密，服务器只保存密文。冲突箱展示同一业务聚合的本机和多个远端分支，
可保留本机、选择分支或逐字段合并；选择结果产生可继续同步的 merge commit。转换冲突解决后会重建
lot 与消耗并运行自检。浏览器和原生端都使用跨启动稳定的 `deviceId`。

若账号已经绑定另一个 `ledgerId`，页面只显示风险说明，不会自动覆盖。用户必须输入“替换本机”并提供
远端账本加密密码；应用先以只读方式确认副本仍绑定目标账本、取得并解锁远端密钥封套，再在隔离的 sql.js
数据库中拉取全部密文提交直至收敛，执行提交身份、一致性、备份载荷和唯一活动设置预检。预检期间不会绑定副本、
回写变化/缺失的远端密钥封套、清空或改写本机账本；已收敛但含无效领域提交的远端流同样会被拒绝。全部验证通过后先创建本机设备级保护备份，再于一个 SQLite 事务中替换账本和设备同步状态，
随后采用远端密钥、整理附件并持久化匹配的服务器副本身份；任一步失败都会恢复原账本、原设备状态、原密钥和原服务器配置，而不是留下半个远端账本。
服务器地址向导仍支持本机、局域网和公网域名；连接测试、账号验证、独立账号密码、账本加密密码和管理员入口保持分离。

主题（`theme.ts`）色值直接取自原型，通过根容器上的 CSS 变量切换，与设计稿视觉一致。

### 响应式壳

- “设置 → 侧边栏与模块”保存账本级模块显示与顺序；日常收支和设置是固定入口，隐藏其他模块只移除导航，不删除业务数据。轻量账本默认只启用总览、日常收支、物品资产和设置（与记账模式无关），其余模块由用户按需启用或从手机「更多 → 未启用模块」直接打开。
- 记账模式与导航彻底解耦：它只决定录入表单的深度与用词（账户、转账、对账是否出现，以及「日常收支/日常支出」「报表/支出报表」的措辞），**不参与模块显隐**。因此设置页该项标注为「记账模式 · 录入深度」并附一行说明，避免被读成控制整个壳层的开关。切换模式不会隐式增删任何导航项，需要更多模块时仍是在「侧边栏与模块」里显式启用。
- 手机 `<768px`：隐藏左侧栏，底部导航按用户顺序显示前 3 个模块并保留快记与“更多”；其余已启用模块、主题、导入导出与存储状态进入“更多”抽屉，抽屉底部额外列出**未启用模块**并可直接启用，不必再绕到设置页。
- 平板 `768–1023px`：96px 导航轨，图标下方带 10px 文字标签（纯图标轨难以辨认）；`1024–1199px` 保持 84px 图标轨；桌面 `>=1200px` 使用完整 260px 侧栏。三档都按同一配置渲染。
- 触控基线与断点解耦：44px 最小命中区与 16px 表单字号绑在 `(pointer: coarse)` 上，而不是只写在 `max-width: 767px` 里。平板竖屏与手机横屏因此同样是 44px 目标、16px 输入框（避免 iOS 聚焦自动放大）。行内 checkbox 本体仍是 18px，真实的 44px 命中区由 `.zc-check-target` 包装盒提供。
- 所有壳层使用 `100dvh`、`viewport-fit=cover` 和安全区 inset。表单弹窗在手机全屏，头尾吸附、正文独立滚动，并声明 `interactive-widget=resizes-content` 适配软键盘。
- 滚动容器是 `documentElement`，不是 `<body>`：`html { overflow-x: clip }` 只裁掉横向溢出，不会把 body 变成嵌套滚动容器，因此 `window.scrollY`／滚动位置读写仍然有效。弹窗打开时按引用计数同时锁定 `documentElement` 与 `body`。
- 日期范围、月历、流水、报表表格、同步配置、分类双栏和物品时间线均有手机重排或受控滚动。长表格（历史列表、报表主表、报表流水明细）在手机上走 `.zc-card-table` 卡片化：桌面保留真实 `<table>` 语义，手机用表头文字作为 `data-label` 渲染成标签／值两列卡片，而不是要求横向滑动。
- 手机端回归由 `tools/e2e/account-tests/mobile-layout.spec.mjs` 守住：真实数据 + 320/360/390/414/844/768/1024 七种视口 × 10 个页面，断言无横向溢出、无超出视口元素、命中区 >=44px、表单字号 >=16px、滚动到底后内容不被底部导航遮挡。`apps/web/test/responsive-contract.test.ts` 提供快速静态护栏（含“内联网格必须有 class 钩子”）。

## 通用表单框架

`ui/DialogShell.tsx` 是统一的 portal 弹窗基础，提供完整 `dialog` 语义、焦点锁定、Escape/遮罩关闭、关闭后焦点恢复，
并通过引用计数保证嵌套弹窗不会提前释放页面滚动锁。确认、实体表单、资产转换、对账、批量编辑、导入提示和移动端
“更多”抽屉均复用此基础。`AppErrorBoundary.tsx` 包裹整个应用初始化与页面树；渲染失败时保留数据库，提供重试、
返回总览及复制不含账本正文的诊断信息。

`ui/EntityFormModal.tsx` 是一个**字段定义驱动**的弹窗：给它一个 `EntityFormSpec`（字段列表 +
`toValues`/`fromValues` 映射）+ 可选 `initial`，就能渲染新增/编辑表单，并在传了 `onDelete` 时
显示删除按钮。各实体的 spec 在 `forms.tsx`（`assetForm`/`accountForm`/`priceMarkForm`/
`dcaPlanForm`/`categoryForm`/`payeeForm`/`transactionForm`/`transactionSplitForm`/
`budgetCategoryForm`/`scheduledTransactionForm`/`gameForm`/`gameAccountForm`/`gameSeasonForm`/`gameRecordForm`/
`fixedAssetForm`/`fixedEventForm`），
依赖已有数据的下拉（资产/游戏/赛季/账号）从快照取选项。所有实体的增删改都复用这一个组件。

**必填只对看得见的字段生效。** 校验规则集中在 `src/form-validation.ts`：`required: true` 表示「显示时必填」，
`hidden` 或 `visibleWhen` 为假的字段不再参与保存校验；「更多信息」里被「字段显示」关掉的字段同样不拦保存，
而 `required` 与 `lockedVisible` 字段会被强制留在可见集合内，不允许被关掉。提交被拦时，弹窗会
自动展开「更多信息」、打开被关掉的字段，把首个出错字段滚动到视野中央并获得焦点，并在底部列出可点击的
字段标签直接跳转；领域层抛出的 `DomainValidationError` 带 `field` 时按同一路径定位。必填的下拉还没有可选项
（例如一个游戏都没有时）会就地提示「还没有可选项，请先新增」，而不是让用户提交后才发现选不了。

## 录入与数据管理（原型没有的部分）

  “创建该备份时的账本加密密码”执行校验、演练或恢复；密码只用于本次内存中的解锁流程，不写入备份目录。
- **日常支出页**：默认“轻量记账”只展示和新增支出，不要求维护账户。页面“+ 记支出”和模板打开完整的仅支出表单，保留日期、时间、分类、币种、描述、商户、地点、标签、备注、附件和拆分能力（描述可留空，列表和账本用分类兜底展示）；新账本默认显示常用附加字段，也可在弹窗内切换“仅核心 / 常用 / 完整”。只有侧栏/移动端“快记”和首次引导使用具有实体背景的金额优先弹窗，其中金额是唯一必填项，分类、日期、时间和币种均自动带入。快记按“显式模板 → 未提交草稿 → 近 60 天同类日、同时段个人习惯 → 早餐/午餐/晚餐/夜宵时间规则 → 最近有效分类 → 待分类”选择默认值，并显示推荐原因；个人习惯至少需要 3 笔且占同时段样本 60%，金额始终留空。餐类细分只在用户已启用时使用，否则落到默认堂食餐饮，不会隐式启用分类包。推荐读取独立的近期支出集合，不受流水页当前筛选影响。新账本内置午餐、外卖、买菜、咖啡奶茶、公交地铁、打车、日用百货、房租、水电燃气和其他支出 10 个无金额模板；两种弹窗中的模板都只预填，不会立即落账。草稿仍自动保存并可在误关后恢复。
  切换到“账户记账”或“完整资产账本”后，再开放收入、账户转账、交易状态、预算、账单和对账能力。输入新商户时会记忆为 `Payee`，

  阻止一笔流水被重复超额分配。删除来源时只自动作废由该来源创建的流水，不会误改用户手工关联的流水。

  年度、月历、单日和物品时间线可查看购买、维修、耗材、残值、卖出、报废、清退及赠出。
- **管理页**：作为唯一“分类与资料中心”，按收支分类、物品分类、标签与商户、其他资料分区；收支分类再分“结构管理”和“快捷显示与排序”。分类、账户、商户和物品分类不提供直接删除，改为先预览引用后归档或合并迁移；排序和隐藏仍在分类中心完成。账户管理只在账户/完整模式显示。
- **资产转换页**：展开链路可编辑或作废；作废记录单独查看并恢复，所有动作都会重建后续成本影响。

已端到端验证：日常收支会进入余额和 Dashboard；退款保存/撤销、流水作废/恢复、转换影响预览、
转换作废后的持仓回算与恢复均通过；真实流程烟测还覆盖资产、定投、卖出、物品资产、游戏记录和同步冲突。

## 验证方式

`npm run build:web` 通过即类型 + 页面分块打包无误（sql.js 的 `.wasm` 会随构建复制到 `dist/assets`）。
`npm test` 运行全工作区单测；`npm run test:coverage` 使用官方 V8 provider 并执行阈值；
`npm run test:e2e` 用 Playwright 验证轻量记账重载、快记时间推荐与实体背景、草稿恢复、自定义导航、分类包停用和有效 PDF 下载。

## 备注（sql.js 的两个坑）

- sql.js 是 CJS 包：`vite.config.ts` 用 `optimizeDeps.include: ['sql.js']` 让 Vite 预打包
  （CJS→ESM）。若误加到 `exclude`，开发模式会卡在初始化。
- `.wasm` 通过 `import wasmUrl from 'sql.js/dist/sql-wasm.wasm?url'` 以资源 URL 方式加载。
