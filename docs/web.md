# Web 应用 `@zichan/web`

React + Vite 单页应用，延续设计原型（`资产记账系统.dc.html`）的视觉语言与 3 套主题，
数据全部来自 `@zichan/core` 的计算 + `@zichan/db` 的本地持久化。这是三端（web/桌面/移动）
共享 UI 的 web 壳。

## 运行

```bash
npm run dev   --workspace @zichan/web   # 开发服务器 http://localhost:5173
npm run build --workspace @zichan/web   # tsc 类型检查 + vite 生产构建
```

首次解锁空数据库后会显示向导，明确选择“创建空账本 / 导入 `.zcbak` / 体验演示”。空账本只创建用户所选基础币种、
账本设置和系统分类；演示数据只在用户显式选择时由 `src/db/seed.ts` 创建，并持久显示“演示账本”标识。
浏览器数据保留在 IndexedDB；由于 sql.js 会整体导出 SQLite 快照，浏览器从打开数据库到关闭期间持有独占 Web Lock，
同一账本只允许一个标签页运行，避免两个内存副本先后覆盖。缺少 Web Locks API 或检测到其他标签页占用时会拒绝打开并给出明确提示。
Tauri 桌面和移动端直接使用应用数据目录中的原生 SQLite。

## 数据链路（本地优先，按平台选择 SQLite 驱动）

```
React 组件
  └─ useSnapshot()  ── 读一批实体 ──▶  SqlLedgerStore (@zichan/db)
  └─ 选择器/派生    ── 计算 ──────────▶  @zichan/core (traceChain / seasonSummary / …)
                                          │ SqlDriver 端口
                      ┌───────────────────┴────────────────────┐
              SqlJsDriver (browser)                   TauriSqlDriver
             sql.js → IndexedDB                    tauri-plugin-sql
                                                   → ledger.sqlite
```

- **`SqlJsDriver`**（`src/db/sqljs-driver.ts`）—— 用 sql.js（SQLite 编译成 WASM）实现
  `@zichan/db` 的 `SqlDriver` 端口，于是浏览器**复用同一套 schema 与仓储**。数据库在内存中，
  顶层写入或事务提交后按顺序导出为字节，并等待 IndexedDB 落盘完成（`src/db/idb.ts`）；
  `src/db/browser-ledger-lock.ts` 在驱动整个生命周期内持有跨标签页独占锁，驱动关闭后才释放。
- **`TauriSqlDriver`**（`src/db/tauri-sql-driver.ts`）—— 桌面与移动端走原生
  `ledger.sqlite`，支持绑定到同一原生连接的事务和嵌套 savepoint；不会读取 WebView IndexedDB 旧库。
- **设备桥接**（`src/device-capabilities.ts`）—— 移动 Tauri 调用生物识别、扫码、定位和原生文件分享；浏览器保留 Web Share / Geolocation 回退。通知只使用运行环境实际提供的标准 Web Notification 接口，不授予未使用的原生通知插件权限。
- **`StoreProvider`**（`src/db/store.tsx`）—— 打开驱动、验证当前 schema 基线并判断初始化状态；未初始化时渲染三选一向导，
  只有创建或恢复完整提交后才执行附件恢复、幂等维护、定期任务与自动备份，
  向下提供 store；Repository 发布实体类型变更，`useSnapshot(scope)` 只订阅当前页面依赖的集合并重载对应数据。
  发现开发期旧 schema、未加密/损坏的旧浏览器快照，或快照不属于当前本机数据密钥时，不做猜测性转换，
  也不会自动改写或删除旧数据。初始化错误页提供“重置本机开发数据”“重新尝试”和“返回解锁”；重置前会明确提示
  将删除本机账本、附件、表单草稿和浏览器内备份，恢复只能依赖浏览器外的 `.zcbak` 或服务器副本。解锁、首次初始化和重置
  都有同步 single-flight；重置先暂停并排空自动备份，再关闭 Store、锁定设备密钥并删除平台数据，避免晚到任务重新写回旧数据。
- **`derive.ts`** —— 共享派生：余额（经 `postingsFrom*` + `computeBalances`）、资产/价格查找。
  加密持仓以 **lots** 为权威口径，法币/稳定币用过账余额；期初入金用一个「外部/权益」账户
  做复式记账，算现金时排除该账户。

## 页面（`src/screens/`）

| 页面 | 计算来源 |
|---|---|
| `Dashboard` 总览 | 净资产/配置快照 + 可选期间的投入、已实现收益、游戏、日常收支和动态；期间指标与基准日快照明确分开 |
| `Convert` 资产转换 | **按资产分组折叠**的持仓概览 + 操作类型/起止日期筛选 + 时间线/年度/月历/单日视图 + 链路回溯编辑/作废/恢复 + 新增 |
| `Transactions` 日常收支 | 默认轻量模式显示收入、支出、退款、时间线、预算和账单；账户模式再显示账户、转账、对账，并保留区间前发生的期初余额 |
| `Game` 游戏赛季 | 赛季概览 + 起止日期/账号/类型筛选 + 记录流/年度/月历/单日；筛选期间不虚构无法按记录分摊的赛季时长 |
| `Fixed` 物品资产 | 二级分类与搜索 + 资料/图片/发票/保修 + 用量/耗材/目标 + 概览/年度/月历/单日/物品时间线 |
| `Reports` 报表 | 五个页签分别保存起止日期；日常收支提供本期/上期/去年同期、月度预算偏差、前三变化驱动和流水下钻；全部报表支持按日/月/年趋势与 PDF/CSV/Markdown/Mermaid 导出 |
| `History` 操作历史 | `operation_log` + 批量操作 + 冲突解决记录；时间区间下推 SQLite 查询，并提供列表/年度/月历/单日、详情和 CSV/JSON 导出 |
| `Manage` 管理 | 统一“分类与资料中心”：收支分类、物品分类、标签与商户、其他资料；价格标记列表支持起止日期筛选 |
| `Settings` 设置 | 全局报表及四模块默认币种 · 记账模式 · 分类选择器默认范围 · 默认匹配方式 · 报表基准日 · 备份/恢复 · 数据自检/重算 · 重置 |
| `Sync` 同步 | 首次配置向导 · E2E 提交图 · 多服务器统一同步 · 多分支冲突合并 · 新设备替换确认 · 管理员日志时间筛选 |

**每个屏的计算都提取为可测的纯 selector**（`src/selectors/{dashboard,convert,transactions,game,fixed,reports}.ts`）+
`derive.ts`，组件只负责渲染。`apps/web` 有 vitest 单测覆盖 derive、format 和
主要屏幕 selector（用 `fixtures.ts` 构造快照）。十个主页面通过 `React.lazy` 按需加载；
快照集合以 400 行分页读取，行数使用 SQL `COUNT`，不会再为每次页面写入无条件重载整库。
设置页快照只读取资产、设置和轻量分类目录，不加载全量流水或附件。数据自检使用游标遍历全部有效附件；
“清理测试流水”由 SQLite 在描述、商户和备注中分页定位 `测试 / test`，只读取命中流水及其附件，再于单个审计事务中作废和移除附件。
Dashboard 也不再加载全量流水、拆分与退款分配：仓储层返回精确十进制余额聚合、所选期间收支聚合和最多 6 条
最近流水，选择器继续用 `decimal.js` 完成求和与汇率换算，并用新旧读模型结果一致性测试守住原有口径。

### 统一日期浏览

`ui/DateRangeBar.tsx` 提供今天、本周、本月、上月、近 3 月、今年、全部时间和自定义区间；
自定义“从 / 至”均包含边界日。`ui/TimelineExplorer.tsx` 复用物品资产的列表、年度、月历、
单日钻取体验。流水、账单、资产转换、游戏记录、物品资产和操作历史使用同一套视图；总览、
报表、同步冲突、服务器日志和价格标记使用同一套区间语义。ISO 时间戳按本地日历日显示，
查询日志时转换为“本地开始日零点（包含）至结束日次日零点（排除）”。

报表折算会选择记录日期当日或之前最新的价格标记，绝不使用未来价格。账户流水按区间显示时，
仍先累计区间开始日前的过账以得到正确期初余额；月度账单按原始锚点展开，1 月 31 日不会逐月漂移。

### 多设备同步（`Sync` 页 + `src/sync-orchestrator.ts`）

同步页只使用真实 HTTP 服务器，不再提供 localStorage 演示云。`sync-orchestrator.ts` 为全部启用配置
创建 `httpCommitTransport`，遇到一次 401 会重新登录，并将服务器身份、游标、延迟和错误写回配置。
随后 `syncReplicas()` 以 pull-all、apply、push-all、re-pull 的统一轮次让所有健康服务器收敛。

提交收敛后，`attachment-sync.ts` 单独同步正文：每台服务器按自己的身份和密码派生不透明对象 ID 与
AES-GCM 密钥，4 MiB 分块支持断点续传。缩略图自动补齐，大正文按查看、保存、备份或服务器中继需求取回；
同步结果会显示每台服务器的可用副本、上传、下载、配额和失败状态。

提交以聚合为单位端到端加密，服务器只保存密文。冲突箱展示同一业务聚合的本机和多个远端分支，
可保留本机、选择分支或逐字段合并；选择结果产生可继续同步的 merge commit。转换冲突解决后会重建
lot 与消耗并运行自检。浏览器和原生端都使用跨启动稳定的 `deviceId`。

若账号已经绑定另一个 `ledgerId`，页面只显示风险说明，不会自动覆盖。用户必须输入“替换本机”，
应用才会清空本地业务、审计和同步数据，未引用附件正文先移入本机回收区，再从远端重建。服务器地址向导仍支持本机、
局域网和公网域名；连接测试、账号验证、独立密码和管理员入口保持分离。

主题（`theme.ts`）色值直接取自原型，通过根容器上的 CSS 变量切换，与设计稿视觉一致。

### 响应式壳

- 手机 `<768px`：隐藏左侧栏，使用“总览 / 账本 / 快记 / 资产 / 更多”底部导航；低频页面、主题、导入导出与存储状态进入“更多”抽屉。
- 平板 `768–1199px`：保留 84px 图标导航轨；桌面 `>=1200px` 使用完整 260px 侧栏。
- 所有壳层使用 `100dvh`、`viewport-fit=cover` 和安全区 inset；手机控件至少 44px。
  表单弹窗在手机全屏，头尾吸附、正文独立滚动，并声明 `interactive-widget=resizes-content` 适配软键盘。
- 日期范围、月历、流水、报表表格、同步配置、分类双栏和物品时间线均有手机重排或受控滚动。

## 通用表单框架

`ui/DialogShell.tsx` 是统一的 portal 弹窗基础，提供完整 `dialog` 语义、焦点锁定、Escape/遮罩关闭、关闭后焦点恢复，
并通过引用计数保证嵌套弹窗不会提前释放页面滚动锁。确认、实体表单、资产转换、对账、批量编辑、导入提示和移动端
“更多”抽屉均复用此基础。`AppErrorBoundary.tsx` 包裹整个应用初始化与页面树；渲染失败时保留数据库，提供重试、
返回总览及复制不含账本正文的诊断信息。

`ui/EntityFormModal.tsx` 是一个**字段定义驱动**的弹窗：给它一个 `EntityFormSpec`（字段列表 +
`toValues`/`fromValues` 映射）+ 可选 `initial`，就能渲染新增/编辑表单，并在传了 `onDelete` 时
显示删除按钮。各实体的 spec 在 `forms.tsx`（`assetForm`/`accountForm`/`priceMarkForm`/
`dcaPlanForm`/`categoryForm`/`payeeForm`/`transactionForm`/`transactionSplitForm`/
`budgetCategoryForm`/`scheduledTransactionForm`/`gameForm`/`gameAccountForm`/`gameSeasonForm`/`gameRecordForm`/
`fixedAssetForm`/`fixedEventForm`），
依赖已有数据的下拉（资产/游戏/赛季/账号）从快照取选项。所有实体的增删改都复用这一个组件。

## 录入与数据管理（原型没有的部分）

原型是只读的，这里补上写入：

- **新增转换**（`AddConversionModal`）走 `@zichan/db` 的**服务层**：买入/定投 → `recordConversion`
  （自动建成本批次 lot）；卖出 → `recordSell`（选 FIFO/LIFO/平均，匹配 lot、写消耗、回填已实现
  盈亏、扣减 lot 剩余量）。来源/目标金额可分别选择成交或账户口径；支持多条来源、目标、第三资产费用，
  即时展示本金/实扣/毛额/实收、成交率/有效率。链路不经过投资记账币种时要求冻结账面折算。
- **编辑转换**复用同一弹窗，保存前先展示受影响的后续链路、lot 和卖出匹配数量；确认后整体重建。
  历史超卖会拒绝保存。转换采用可恢复作废，不再暴露硬删除入口；转换与关联 DCA 执行同事务保存或回滚。
- **导出 / 导入加密备份**（顶栏）：`.zcbak` 二进制归档内含 Argon2id 密码包装的密钥封套，正文由独立备份密钥 AES-GCM 加密；
  新设备只需文件和账本加密密码即可解密。导入会依次执行密码解锁、SHA-256 校验、业务预检、临时库恢复演练和导入前备份，
  再展示新增/更新/未变。归档按 1 MiB 帧流式加密，附件不转 Base64；可移植账本默认合并，完整设备备份默认精确恢复账本身份、审计、同步和附件状态。
- **日常收支页**：默认是“轻量记账”，录入收入/支出/退款、二级分类、币种、商户、交易时间、地点、标签和备注，不要求维护账户；
  切换到“账户记账”后才显示账户转账、交易状态和对账。输入新商户时会记忆为 `Payee`，
  下次可自动带默认分类，账户模式下也可带默认账户。`TransactionSplit` 支持把一笔消费拆到多个分类，预算和 Top 分类按拆分统计。
- **退款与撤销**：原支出行可直接发起全额或部分退款，多次退款累计不能超过原金额。退款增加现金但不增加收入；
  创建时按原单比例或指定项目冻结分类路径、拆分金额、原日期和币种，之后修改原支出不会改变历史退款报表。
  设置页可选择回冲原消费日期或按退款日期统计。预算、日历、趋势、分类报表与导出统一读取冻结 effect；
  报表明细同时显示归属日和实际发生时间。流水和转换均可作废/恢复，并在保存后提供 10 秒全局撤销。
- **基础资料维护**：个人账本只按当前内置 ID 补齐系统收支分类与物品分类，不自动写入模板、预算或定期交易；只有显式演示账本会补齐演示标签、地点和预设。不读取或转换旧版实体。
- **查询 / 时间视图 / 批量整理**：流水页支持保存筛选条件；高级查询用“组内 AND、组间 OR”表达复杂条件；
  列表、年度、月历和单日视图按天展示收入、支出、净额和流水数量；列表多选后可批量修改分类、商户、账户、状态、地点和标签。
  基础筛选、高级查询和批量修改的分类下拉只展示二级分类。批量修改会写入 `audit_batches`，
  历史页按批次折叠展示，并保留每条流水的字段 diff；应用前预览会显示前几条流水的改前/改后。
- **大量分类滚动**：记账分类选择器和分类中心的“快捷显示与排序”均使用有界双栏滚动区；一级、二级列表独立滚动，开启全部隐藏分类后仍能访问完整列表。
- **操作历史**：左侧“历史”页展示实体新增/修改/作废、批量操作和同步冲突解决记录；默认“用户相关”
  视图隐藏系统初始化和无业务变化日志，仍可切到全部来源审计；支持按时间、记录类型、操作类型、
  实体、来源和关键词筛选，右侧查看改前/改后详情，并可导出 CSV/JSON；最新且版本未变化的本地流水可安全反向操作。
- **报表导出**：日常收支、定投、资产转换、游戏赛季和物品资产都支持预设或自定义日期范围与按日/月/年趋势；
  当前报表可导出真实分页 PDF、CSV、Markdown 表格和 Mermaid 饼图源码，流水明细可单独导出 CSV，文件名包含实际区间。
  缺汇率时仅显示已估值小计和未估值资产，不显示精确净资产占比。
- **日常收支对比**：有完整起止日期时，同时展示收入、支出和净收支的本期数值、相对上期环比及去年同期同比，并给出金额差和百分比；基期为 0 时不伪造百分比。
  进行中的本月/本年等范围先截断到账本 `asOfDate`，上期和去年同期再使用相同进度，避免将本期半程与完整历史期间直接相比；自定义范围的上期是紧邻的等长区间。
- **预算偏差与驱动下钻**：预算以“月份 + 分类”分行，同时展示原定、含结转可用额、实际支出和偏差，不跨月重复累加结转。
  “前三变化驱动”按各收入/支出分类相对上期的净收支影响绝对值排序；每项可分别打开本期或上期流水，预算行也可下钻对应月份与分类。明细每次从 SQLite 分页读取 200 笔，不依赖页面的全量流水快照。
  下钻分类会直接进入 SQLite 查询与流式 CSV 导出条件，而不是先分页读取全部流水再在前端过滤；清除下钻会恢复主报表的日期范围。
- **附件 / 图片**：交易和物品表单支持图片/PDF；同步元数据只保存大小、明文 SHA-256 和缩略图信息，不保存本机路径。
  浏览器与 Tauri 分别使用 IndexedDB/Tauri 文件目录中的内容寻址对象；图片预览、文件保存和备份会按需从健康服务器取回并校验正文。
- **标签 / 地点 / 模板**：标签实体支持分组（如项目、报销、场景），地点先做文本记录，交易模板可一键生成常用流水。
- **账户 / 对账**：专用对账弹窗输入账单截止日和银行期末余额，按账户分录逐笔勾选已清算流水；系统显示上次期末、本次勾选、核对后余额和只读差额。差额为零才可完成，也可显式创建不进入收支报表的余额调整；详情保存本期流水，且只能从最新一期逆序撤销。
- **预算 / 账单**：预算冻结创建时币种，支持不结转、仅结余结转和结余/超支结转，按交易日期价格折算并提示缺汇率。定期交易支持月末锚点、时区、自动执行、漏期全补或只补最近一期；只在应用打开、回到前台及保持运行时幂等补齐，不承诺应用关闭后的后台执行。页面展示积压预览、成功/跳过/失败历史、指数退避时间和立即重试。
- **卖出的手动选批次**：卖出时匹配方式选「手动选择批次」，会列出该资产的开放 lot（日期/剩余/单位
  成本），按勾选先后顺序作为 `selectedLotIds` 传给 `recordSell`。
- **设置页**：分别设置全局报表、日常记账、投资成本、物品资产和游戏结算默认币种（仅预填新记录，不追溯修改历史）、记账模式、记账弹窗默认显示高频/全部分类、默认卖出匹配方式、报表基准日、
  分层加密备份库（手动/导入前固定保留，自动按小时/日/周保留）、演练、下载、精确/合并恢复、数据自检 / 重算缓存、测试流水清理和重置数据。清理前固定创建手动备份；流水作废后保留拆分以支持审计和恢复，附件元数据进入删除流程。分类设置提供摘要和分类中心入口；默认范围、最近自检和恢复演练状态写入账本设置，随备份和同步迁移。
- **定投计划**：管理页维护计划；总览根据频率和最近执行日提示下一次执行/逾期。
- **附件**：管理页显示本机正文、回收区和每台服务器的副本/错误状态，可手动取回正文；删除先提交元数据，
  再由文件日志移入可恢复回收区。便携备份会补齐并嵌入正文，导入前校验大小、SHA-256 和缩略图，失败不留下暂存文件。
- **游戏赛季页**：新增/编辑/补偿删除游戏记录（点记录行编辑）、新增赛季。充值、提现、购买、出售和手续费可选择仅登记、关联已有流水或同时创建规范流水；只有流水影响账户余额，避免游戏记录与流水重复计入。
- **物品资产页**：记录购买、品牌型号、序列号/条形码、保修、图片/发票；残值只由用户输入，可选“当前残值”或“累计损耗”，不自动折旧。
  购买、维修、升级、耗材和出售都支持“仅登记、关联已有流水、同时创建流水”；后两种冻结资金方向、金额和实际汇率，
  阻止一笔流水被重复超额分配。删除来源时只自动作废由该来源创建的流水，不会误改用户手工关联的流水。
  可建立按次数/公里/手动小时/自定义单位的指标和用量记录，管理耗材寿命提醒，并创建冻结成本基数的单位成本或使用量目标。
  年度、月历、单日和物品时间线可查看购买、维修、耗材、残值、卖出、报废、清退及赠出。
- **管理页**：作为唯一“分类与资料中心”，按收支分类、物品分类、标签与商户、其他资料分区；收支分类再分“结构管理”和“快捷显示与排序”。分类、账户、商户和物品分类不提供直接删除，改为先预览引用后归档或合并迁移；排序和隐藏仍在分类中心完成。账户管理只在账户/完整模式显示。
- **资产转换页**：展开链路可编辑或作废；作废记录单独查看并恢复，所有动作都会重建后续成本影响。

已端到端验证：日常收支会进入余额和 Dashboard；退款保存/撤销、流水作废/恢复、转换影响预览、
转换作废后的持仓回算与恢复均通过；真实流程烟测还覆盖资产、定投、卖出、物品资产、游戏记录和同步冲突。

## 验证方式

`npm run build:web` 通过即类型 + 页面分块打包无误（sql.js 的 `.wasm` 会随构建复制到 `dist/assets`）。
`npm test` 运行全工作区单测；`npm run test:coverage` 使用官方 V8 provider 并执行阈值；
`npm run test:e2e` 用 Playwright 验证轻量记账重载、草稿恢复和有效 PDF 下载。

## 备注（sql.js 的两个坑）

- sql.js 是 CJS 包：`vite.config.ts` 用 `optimizeDeps.include: ['sql.js']` 让 Vite 预打包
  （CJS→ESM）。若误加到 `exclude`，开发模式会卡在初始化。
- `.wasm` 通过 `import wasmUrl from 'sql.js/dist/sql-wasm.wasm?url'` 以资源 URL 方式加载。
