# 账本保护与离线访问

新部署统一采用服务器托管账本密钥。账号注册或首次创建个人账本时，服务器生成随机账本凭据，并用部署的 `custody.key` 加密保存。获授权的同步组节点接收该凭据后各自封存；用户使用同一个账号密码登录任一可访问节点，客户端取得账本凭据并打开账本。独立服务器由用户浏览器连接并传送账本密钥，仍由目标服务器托管。

账本提交、附件与备份继续加密存储和传输。托管服务器具有解密能力，管理员后台的只读预览受权限及审计约束。本项目不再提供“私密模式”、恢复码或按服务器切换托管方式。成员共享账本仍使用成员权限和账号加密密钥，这些是共享授权所需的内部机制。

## 默认离线访问

用户用账号密码在线登录并打开账本后，本机会自动把解锁资料用该账号密码加密，按账号和副本隔离保存。断网或服务器临时不可用时，已安装的网页或桌面应用可用同一个账号密码打开**本设备已有**的账本缓存，继续本地记账；恢复连接后再同步。用户无需设置第二个离线密码。可选的“记住此设备七天”仅用于免输密码。

首次登录、没有本机账本缓存、浏览器清除网站数据，或网页静态资源尚未安装时，都需要联网。401/403、账号变化或服务器身份变化不会触发离线入口。主动退出会清除本机离线解锁授权；重新登录后自动创建。服务器暂时不可达时无法验证远端的密码变更或设备撤销，因此已经保存的离线副本仍可能用旧密码打开，直到设备再次联网或本机授权被清除。

Web 离线冷启动依靠生产构建的 Service Worker 缓存公共静态资源；API 响应和用户账本不放入 Cache Storage。本机加密账本保存在账号分区的 IndexedDB。详见[离线应用](offline-app.md)。

## 服务端与恢复

`CUSTODY_KEY_PATH` 默认指向 `DATA_DIR/custody.key`。服务器备份必须包含对应的主密钥；有托管记录而主密钥缺失时，服务器拒绝启动。`ACCOUNT_PROTECTION` 和 `CUSTODY_ENABLED` 配置已移除，所有新账本使用托管模式。

账号密码找回更新账号凭据，不改变账本身份或托管密钥。新密码在线登录后会重新创建本机离线解锁资料。导入备份沿用当前账号和账本的托管身份；导出的加密备份仍需其导出流程要求的解锁材料，不会额外生成私密模式恢复码。
