# 账本保护：云端托管与私密模式

本设计以新账号为准，不迁移旧账号密钥或旧浏览器数据。同步继续使用加密提交 DAG、密文附件和加密 `.zcbak` 归档；保护方式决定谁持有解密凭据。

## 默认体验

支持托管的主服务器默认使用云端托管。用户注册或登录后，客户端取得随机托管凭据，自动解锁本机缓存和账本。新账号直接进入账本初始化；新设备自动预检并恢复已有远端账本，不要求另外设置本机密码或填写账本密钥。

注册表单的“高级：账本保护方式”可选择私密账本。客户端生成 256 位随机恢复码，要求用户在设备之外保存后继续；服务端仅取得密码包装的密钥包，不取得恢复码。后续登录仍需恢复码，或用户主动开启的有效设备授权。

“当前网站”不等于官方服务器。服务器通过 `/api/health` 宣告 `ledger-protection-v1`、可选的 `managed-key-custody-v1` 和默认账号保护方式。客户端按已固定的服务器 ID、公钥及真实能力操作，不按域名外观判断信任。

## 用户设置

设置页及同步页的“账本保护”提供：

- 查看备份恢复码：保存在应用之外，可独立解锁导出的备份。托管模式也提供此入口，避免服务器不可用时外部备份无法打开。
- 切换私密模式：先创建保护备份，再轮换数据、附件、备份密钥，保存新恢复码后确认。历史密钥只用于读取历史提交、附件及备份。
- 切换云端托管：明确授权主服务器解密，使用新的随机托管凭据重新包装密钥。
- 记住此设备七天：浏览器以不可导出的 Web Crypto 密钥保护授权材料，密钥与密文放入账号分区的 IndexedDB；不是系统硬件隔离保证。
- 设置独立离线密码：仅在本设备保存密码包装的授权材料。账号密码不参与此过程，也不被持久化。
- 关闭离线访问：删除离线密码授权和记住设备授权。

主动退出清理内存、离线授权及会话。跨标签退出覆盖尚在准备密钥的页面。网络错误可以使用已有离线授权；401/403、账号或服务器身份改变不开放离线入口。生产 Web 静态资源缓存安装成功后支持离线冷启动，更新等待全部旧页面关闭。缓存仅含公共静态资源，不含 API 响应。

原生服务器模式用账号保护凭据解锁包装后的随机 Stronghold 密码，Stronghold 密码不等于账号密码或恢复码。更改账本保护方式只重新包装此随机密码，不改变本机 SQLite 数据密钥。本地使用模式继续保留独立设备密码。

## 附加服务器

附加服务器默认只接收密钥封套、密文提交和密文附件，不自动取得托管凭据，不增加密钥输入步骤。

同步页选择连接后，在“此服务器的保护方式”检查实际能力。首次同步绑定成功后，可明确勾选“允许此服务器解密账本”授权托管；服务器未开放托管时不提供此操作。私密账本不能直接授权附加服务器托管，需要先更改账本保护模式。

撤销某台服务器托管只删除该服务器当前保存的凭据，不能证明对方没有保留副本。需要撤销未来解密能力时，切换整个账本到私密模式并轮换密钥；附加服务器下次同步接收新密钥封套并撤销旧托管，离线服务器持有的旧凭据无法解密新密钥。历史已知数据无法追溯保密，同一内容的历史附件仍按历史对象读取。

## 服务端配置和存储

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `ACCOUNT_PROTECTION` | `managed` | 主账号默认 `managed` 或 `private` |
| `CUSTODY_ENABLED` | `true` | 关闭后只支持私密初始化和密文中继 |
| `CUSTODY_KEY_PATH` | `DATA_DIR/custody.key` | 独立 32 字节主密钥的十六进制文件路径 |

托管凭据为每个账本随机生成，与 OPAQUE 账号密码无关。`sync_key_custody` 仅保存 AES-256-GCM 包装后的凭据；AAD 绑定服务器 ID 和稳定 accountId。主密钥独立于认证用 `server.secret`，不写入数据库、日志或健康接口。生产可将其放在独立受控挂载中；有托管记录却缺少主密钥时停止启动，不能生成替代密钥掩盖丢失。

服务端 schema 为 `server_key_custody_v10`。身份校验、HTTPS、访问令牌、OPAQUE 登录及角色隔离保持原有机制。管理后台不提供直接读取用户密钥的接口；托管的信任边界仍是服务器具备解密能力，不能声称端到端保密。

## API 与失败恢复

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v3/protection` | 认证后读取保护方式、版本、账本身份及封套；仅托管模式返回凭据 |
| POST | `/api/v3/protection/initialize` | 原子初始化稳定账本身份、密钥包和保护方式；并发初始化返回同一结果 |
| PUT | `/api/v3/protection` | 版本 CAS 原子更新封套与托管状态；托管必须确认且凭据必须能解密封套 |
| POST | `/api/v3/protection/replace` | 明确确认旧账本身份及“替换旧账本”，原子替换为空的新账本及保护方式 |

保护方式更新与当前文档所有同步串行执行；服务端事务再次检查当前会话。密钥代次更新撤销其他设备会话。客户端在请求之前暂存用新凭据包装的本机存储密钥，因此即使服务端已成功而响应丢失，重新登录后仍可打开原缓存。客户端会只读核对不确定结果，不盲目重复变更。

私密恢复码遗失时，页面可显式重新开账本：先保存新恢复码，再确认删除旧同步记录和本机缓存。账号保留，其他设备退出；旧附件和旧备份继续保留，但仍需原恢复码读取。托管账号找回密码后直接恢复原账本，不需要重新开账本。

账号模式导入备份只恢复账本内容，保留当前账号的账本身份、托管方式和密钥；不把外部备份的设备身份或密钥接管为当前账号密钥。本地模式保留完整设备恢复能力。

## 备份和运维

服务器备份包含 `custody.key`。若部署使用外部 `CUSTODY_KEY_PATH`，备份命令使用相同配置，把主密钥复制为归档中的 `custody.key`；恢复后应指向恢复的密钥文件。验证会检查托管记录是否能被归档中的主密钥解开，缺少或错误的主密钥不能通过验证。

托管服务器可解密自己持有的账本和备份。迁移到私密模式不会删除运维备份中已有的历史托管材料，因此只能保护轮换之后的新内容。

本次开发不部署或重启实际服务器，不读取或清理实际账本。验证使用隔离的临时服务器、测试账号和浏览器资料。
