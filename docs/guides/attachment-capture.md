# 从附件提取交易信息

日常收支的新增与编辑共用同一个附件入口。添加图片后，点击该图片旁的“提取信息”，无需再次选图。电脑端以独立双栏弹窗打开（左栏预览与隐私遮盖、右栏核对识别结果），手机端进入全屏双页签处理页；原记账表单与滚动位置保持不变，不再撑开主表单。

## 使用步骤

1. 在“附件 / 图片”选择文件、拍照，或在附件区域拖入文件、粘贴截图。普通附件沿用原有保存和下载方式。
2. 点击对应 PNG、JPEG、WebP 图片或 PDF 的“提取信息”（已处理过的显示“重新提取”）。PDF 在本机转换全部页，最多 6 页；同一时间处理一份附件，可在标题栏取消识别或重新识别。
3. 右侧默认只展示本次实际识别出结果的字段（如实付金额、付款日期／时间、商家、描述、订单号等），未识别或与当前表单相同的币种统一收在“手动补填其他字段”折叠区。所有候选均可直接编辑，修改后自动勾选回填。已有表单手填、主动清空及其他图片已回填的字段默认保留；应用时会再次检查字段值和修改版本，冲突字段需重新核对。
4. 按需选择出口应用：
   - 若只想快速识字填表、不想存截图，直接点击底栏**“仅填入信息（不留图）”**，一步将勾选字段写入表单并移除临时附件，无需核对打码。
   - 若需留存脱敏凭证，核对左侧黑框遮盖预览后直接点击**“已核对打码并应用”**一步生成脱敏 PNG 并回填（也可在“附件保留与隐私”切换为保留原图／原 PDF）。这一步只更新当前表单与附件草稿，仍须通过“保存”或“保存并继续”完成流水。

手机先显示“核对信息”，金额突出，日期与时间并排；底部可直接点“仅填入信息（不留图）”，或点“下一步：核对打码”切换到“图片与隐私”页签后一键应用。两个页签之间切换保留手改值与隐私设置。字段可点“依据”显示本次原图局部及提取理由，号码可直接复制，不改变保存图片的遮盖。原图依据仅用于当前处理会话，不另存原图副本。

未识别字段继续保留对应的结构化输入，不自动写入备注。完整 OCR 文字、姓名、电话和地址也不会自动拼入备注。

## 三种保留方式

| 方式 | 应用后结果 |
| --- | --- |
| 保留脱敏图片（默认） | 检查全部图片后确认，生成实色遮盖 PNG，原位替换该附件，不增加重复附件 |
| 保留原始图片 | 不打码，当前原图按普通附件参与存储、同步和备份 |
| 不保留图片 | 移除该附件，已确认回填的交易字段保留 |

切换方式不会立即修改或删除附件。打码设置在当前处理会话内保留。暂不处理或放弃时，未应用的结果不进入表单；主表单保存前会提示先处理当前会话。

## 隐私遮盖与下载

本机 OCR 和码图检测提出敏感区域建议，默认选择全部检测区域。可取消单项、全选、恢复默认、查看原图与脱敏预览，以及框选新增区域。坐标编辑可调整区域位置和尺寸、删除手工区域；自动区域可转换为可编辑区域。手机框选时进入全屏编辑区域，结束后返回处理页。

存在未选敏感区域时会提示；全部取消且未加手工框时，明确显示图片未打码。修改区域后，整图核对确认失效，必须重新确认。自动检测可能遗漏，请检查姓名、电话、跨行地址、账号、头像及码图。

脱敏输出会把遮盖写入图片像素，重新编码并清除不必要的隐藏文字／EXIF；缩略图和下载均使用处理后的图片。生成失败不会静默改存原图。未处理附件与选择保留原图的附件下载当前原图。不会删除设备相册或源目录的原始文件。

## 业务号码

日常收支提供订单号、物流单号与发票字段。若用户未在“资料管理 → 记账字段”中将它们勾选为常用，OCR 回填、草稿恢复或编辑已有记录时这些单据字段保持收在“更多字段”折叠区内，不在常用主表单自动铺开，折叠标题会提示“更多字段（N · 已填：订单号…）”供按需展开核改。保留前导零，与流水一起参与同步、审计、备份和导出恢复；不拼入描述或备注。

不再提供独立“本机留存”设置。图片号码是否打码与业务字段是否回填相互独立：选择不保留图片，也可以保留已确认号码。此前版本独立私密库中的记录不会自动搬入普通流水或发布到同步端；本轮不删除这些旧记录。

## 平台规则与发票

通用解析之外已添加淘宝／天猫、京东、拼多多、抖音、快手、闲鱼、美团、饿了么、唯品会、苏宁、1688、小红书与微信／支付宝账单字段规则。平台布局和文字可能变化，规则命中并不代表所有截图都能准确识别，仍需核对。

发票显示“价税合计”，不把税额或不含税金额当付款总额；开票不代表付款。发票号码、代码、开票日期独立保存在流水，不覆盖订单号或交易日期，不拼入备注。数电票无代码时留空。红字、作废、多票冲突不直接作为普通支出回填。

PDF 保留脱敏图片时，用包含全部页的 PNG 原位替换，清除 PDF 隐藏文本与元数据；保留原始 PDF 时按普通原文件保存。损坏、需密码、页数或像素超限时提示处理，附件不丢失。适配范围、规则表、验证样例及官方票面依据见[平台订单与发票提取规则](capture-platform-rules.md)。

## 本机识别与离线

识别本身不上传截图或完整 OCR 文字。公开模型、WASM 与脚本从当前应用同源按需准备，约 46 MiB，每个资源经过大小与 SHA-256 校验。支持持久缓存且应用已缓存时可离线识别；HTTP、缓存被拒或容量不足时改用本页临时资源，仍可本机识别，刷新后可能需要重新准备。

确认后的普通交易字段以及选择保留的附件，按既有同步与备份配置处理。因此“本机识别”不表示用户选择保存的原图或业务号码不会同步。

如果提示识别资源缺失，先刷新页面后重新提取。公开清单会随构建改变，客户端每次准备时重新校验清单，服务器不对该清单设置长期不可变缓存；大模型文件仍单独缓存。404／410 会列出缺失文件并提示检查更新与服务器资源，其他 HTTP 错误也会显示状态码，不能据此直接判断手机没有网络。

## 保存、编辑和恢复

新建日常记账默认打开空白记录，不弹出草稿恢复阻断，不影响添加附件。旧草稿与附件独立保留在“未完成草稿”列表，选择“恢复这份草稿”即可继续；切换前会先保存当前已修改的内容。每份新记录使用独立草稿，保存流水仅清理其对应草稿。此规则适用于日常记账，其他业务维持原有恢复方式。

在“设置 → 记账 → 记账草稿”勾选“新建记账时自动恢复最近草稿”，可改为自动恢复。本机按账号保存该偏好，默认关闭。

已确认字段和附件参与本机草稿恢复；识别中间结果不作为账本字段保存。移除附件不清空已回填字段。编辑已有流水可读取当前附件重新提取、原位替换；已经覆盖的原始版本不保证能够恢复。保存失败时保留草稿供重试；保存并继续不沿用上一笔图片、识别状态、订单号或物流号。

账本 schema 131 增加订单／物流两个可空文本字段；132 再增加发票号码、代码、开票日期三个可空文本字段。已知 127～131 增量升级保留原记录，客户端和服务端应一起更新。
