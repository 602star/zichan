# 账本快速打开与性能统计

网页版优先打开本机加密账本，新设备使用服务器预先准备的加密 SQLite 快照。界面可用后，账号续期、增量同步、附件整理、资料维护和自动备份继续在后台执行。

## 打开路径

| 场景 | 可以记账前必须完成 | 后台执行 |
| --- | --- | --- |
| 新设备、已有服务器账本 | 登录、解锁账本及本机密钥、下载和验证快照、持久化本机数据库 | 从快照游标增量追平、附件目录整理、资料维护、计划交易、备份、准备本机授权 |
| 本机有缓存且快速授权有效 | 验证本机授权作用域和期限、恢复内存密钥、打开本机数据库 | 服务器身份检查、会话续期、同步及整理 |
| 本机授权到期或没有授权 | 在线会话恢复／登录并解锁；服务器不可达时可用已准备的离线密码 | 打开后的同步及整理 |
| 显式退出 | 重新登录 | 退出清除本机授权，不删除原账本或未同步记录 |

新设备仍需联网完成必要的身份验证和密钥解锁。不能在未授权时下载或展示私人数据。有效本机授权允许先读写本设备已有数据；网络暂不可用不阻止打开。后台确认登录失效时暂停同步并显示重新登录入口，本机账本仍可继续记账；恢复登录后同步保留的记录。

Web 在线成功打开后在空闲时准备 7 天本机授权。授权包含加密后的账本及设备密钥会话，按服务器、账号和副本隔离，HTTPS 使用浏览器不可导出的 CryptoKey 加密，不重复执行密钥派生。到期时间从准备时计算，缓存打开不会自动续期。显式退出会清除授权；共用设备使用结束后需要退出。设备的系统应用锁仍独立验证。原生 App 保留原有离线授权方式。

## 服务器快照

- 仅为服务器托管密钥的主副本构建，接口为 `GET /api/v4/ledger-open-snapshot`，需要有效记账会话和账本读取权限；管理会话不能下载。
- 服务启动时预热，接收提交后安排增量更新，每 30 秒补查一次。构建全局串行去重；历史回放在 SQL 操作之间让出事件循环，压缩使用异步 gzip。
- 首次从加密提交构建内存数据库，保留完整提交依赖、冲突、确认记录和副本游标。后续从上一个快照继续应用新增提交，不重新回放全部历史。
- 数据库仅在受控内存中解密，压缩后用账本密钥认证加密，缓存存入 `DATA_DIR/ledger-open/`。通过临时密文文件原子替换，不生成明文数据库文件；此目录是可重建缓存。
- manifest 绑定服务器、账号、账本、副本、提交流 epoch、schema、密钥代次、长度和 SHA-256；全部纳入加密认证上下文。版本或密钥代次改变后重建；已有缓存损坏时从原提交重建。原提交流不被修改。
- 浏览器检查作用域、认证密文、解压大小、摘要、schema、账本设置和同步游标。解压后上限为 256 MiB；超限或验证失败会明确报错，不能跳过验证后继续写入。
- 快照可以稍落后于服务器最新位置，打开后按保留的真实同步基线追平；新记录使用本设备身份提交，可与追平并行。完整历史仍在快照中，因此下载大小随账本历史增长，后续可再评估压缩与历史分段。
- 安装过程与本机写入串行，并原子检查所有业务表、审计日志和提交记录。只允许安装到空库；其他标签页已安装或已有本机数据时拒绝替换。只有加密持久化成功后才发布账本。

没有可用快照时接口返回 202，客户端显示准备进度并重试，最长等待 120 秒；构建失败返回明确错误并记录 `ledger_open_snapshot_failed`。首次升级后的大账本可能需要等待一次预热；不能把这段准备时间当成已经消除。上线前应在真实数据规模的测试副本上完成预热与耗时验收。

## 登录恢复

登录／续期响应一次返回账号、主副本和托管保护信息，减少随后串行调用 `/me` 与保护查询。已确认的服务器身份仅在当前文档短暂复用；地址或固定公钥不同不能复用。

记账 Cookie 改为 `zichan_session_v2`，管理 Cookie 独立不变。旧版不同 Path 遗留的同名 `zichan_session` 不再干扰新登录；升级后旧记账会话需要重新登录一次，本机数据不清空。新版同名 Cookie 出现歧义仍拒绝认证。刷新失败日志区分 Cookie 缺失／歧义、会话不存在、用户不存在、禁用、撤销、过期及刷新凭据不匹配。没有生产请求和对应日志时，不能仅凭 `Session refresh failed` 判定某个具体原因。

### 登录验证与来源地址

自 0.7.2 起，OPAQUE 登录不再要求 `start` 与 `finish` 两次请求的 IP 相同：CDN 节点切换、IPv4／IPv6 或移动网络切换均可能改变地址。IP 继续用于审计与限流，认证仍检查 OPAQUE 密码证明、凭据版本、60 秒有效期和一次性消费；管理员两步验证独立执行。验证通过时的地址变化记录为 `login_source_changed` 信息事件，不计为密码错误。

错误证明返回 `401 INVALID_CREDENTIALS`；凭据在握手期间变化返回 `401 LOGIN_CREDENTIALS_CHANGED`；状态缺失、已消费或并发重复返回 `409 LOGIN_STATE_INVALID`；状态超时返回 `410 LOGIN_STATE_EXPIRED`。客户端保留机器可读错误码和 HTTP 状态，登录界面直接显示中文原因，不自动重复提交登录。新登录日志分别记录原因代码；旧版已经持久化的历史事件不会被批量重写。

真实访客 IP 在受信任代理层恢复，配置见[Cloudflare 与 1Panel 部署说明](../deployment/production-deployment.md#cloudflare-经-1panelopenresty-转发)。该修复自 0.7.2 提供；公网需实际运行新版，反向代理配置另按部署文档核对和应用。

## 性能入口与口径

管理后台侧栏 **运维中心 → 打开性能**（`/startup`），运行概览也提供入口。支持近 7／30／90 天和自定义 UTC 日期范围、自动刷新、样本数、平均值及近似 P50／P95。单独列出首次快照恢复、本机快速打开、失败等待及后台追平。

新版总耗时从页面导航起点到本机账本已发布、界面设置加载并经过绘制机会后记录，包含静态资源和人工登录页停留；不能直接和旧版从保护查询开始的样本比较。首开后的后台任务另行记录，重叠阶段不能相加，后台追平不延长打开总耗时。此处测量的是界面可记账；不代表每个页面全部查询或所有附件均已加载。

当前标签页的 `sessionStorage` 键 `zichan.startup-timing.v1` 保存阶段计时。匿名样本上报失败会留在本机有界队列（最多 20 条），在线／后续登录后重试，只有 HTTP 成功后移除。统计只保存已接受样本的每日直方图，不保存单次账号、设备或账本身份；失败样本也是后续登录后补报。离线、关闭后未返回、浏览器清理数据、限流和丢失响应可能造成缺失或重复，因此样本数不能作为严格访问数或成功率。

性能目标需要按公网带宽、设备性能和账本规模验收；本机小账本结果不能作为公网打开时间承诺。
