# 后台可观测性

后台按可观测性设计基线 v1.1 扩展现有 SQLite 服务，复用管理登录、权限、审计、任务和告警，无需新增监控容器。界面与账本共用文楷、文献纸、朱色操作、深墨侧栏、三种纸张和浅深色偏好。

## 排查入口

- 运维中心：运行概览、访问与请求、运行监控、数据库、告警中心。“访问与请求”页内切换请求分析与访问分析；“运行监控”页内切换应用自身、系统资源、指标目录、主机与容器、采集任务。旧页面地址保留，并高亮对应父入口。
- 日志管理：侧栏一个入口，页内切换系统、访问、登录、操作、任务、容器六类记录。六类使用同一套字段配置、筛选、游标分页、详情与导出；保留旧分类地址。
- 用户、设备、邀请、存储备份、同步、维护、安全和系统设置继续使用原有流程。

请求分析支持近 15 分钟、1 小时、24 小时、7 天、30 天和 90 天。点击路由缩小范围；访问日志按规范化路由、HTTP 状态、IP、Request ID 查询，详情可复制 Request ID 或关联系统日志。每页 50 条，按时间和 ID 游标翻页；追踪只刷新最新页。

### 自定义历史区间

请求分析、访问分析、运行趋势和六类日志直接共用现有时间范围控件：快捷下拉、从／至日期及时分、应用、清除始终显示，宽屏同排，手机顺序换行。不需要先选自定义才能改日期；手动修改后下拉显示自定义，点击“应用”才更新 URL 与查询。刷新保留已应用区间，同工作区切换视图保留时间；修改尚未应用时保留提示。自定义必须同时提供起止时间，最多 90 天，清除恢复近 24 小时。查询按本地输入转换为 UTC。

请求与访问分析统一为 90 天上限，切换时保留完整自定义区间及 30／90 天快捷值，不再缩短为 7 天。

请求统计近 7 天保留分钟聚合，更早转为小时汇总，最长保留 90 天；包含小时汇总或超过 7 天的区间按完整 UTC 小时覆盖边界，长区间按天展示趋势。运行趋势按完整分钟／小时采样桶覆盖自定义边界，页面显示实际起止；不能从聚合记录还原部分分钟或小时。页面访问按真实事件时刻筛选；自定义区间中的“5／30 分钟活跃”以该区间结束时刻为基准。账本打开耗时只有 UTC 日汇总，自定义覆盖完整 UTC 日期，并限制结束日，不能提供精确时分样本。升级前已被旧策略清理的数据无法恢复，90 天范围要随新版本逐步积累；空区间不代表历史没有请求。

数据库、独立主机状态和采集器心跳仅为当前快照，明确说明不提供历史区间。运行监控的顶部即时读数也不随历史筛选回溯，只有下方趋势受区间影响。

## 日志工作区

| 分类 | 列表与详情 | 筛选 |
|---|---|---|
| 系统 | 时间、级别、组件、消息、请求、IP；实例、服务、环境、堆栈、脱敏上下文 | 级别、组件、请求、事件、账号、IP、实例、关键词 |
| 访问 | 方法、规范化路由、状态、耗时、IP、请求；Origin、UA、响应头提交耗时、实例 | 方法、路由、状态、IP、请求、实例、耗时上下限、关键词 |
| 登录 | 账号、结果、认证方式、设备、原因码、IP、请求；账号 ID、安全摘要、第二因子和 UA | 账号、结果、IP、认证方式、事件、请求、关键词 |
| 操作 | 操作者、操作时角色、对象、动作及中文说明、成功/失败、IP、请求；原因与变更前后值 | 操作者/对象的名称或 ID、动作、结果、IP、请求、关键词 |
| 任务 | 任务名/ID、开始/结束、状态、耗时、尝试次数、实例；错误、阶段、进度、重试来源与最近 100 条事件 | 任务名/ID、状态、实例、请求、关键词 |
| 容器 | 时间、容器、stdout/stderr、内容与原文 | 白名单容器、输出流、关键词 |

六类均支持时间范围，默认近 24 小时，最长 90 天；旧来源已裁剪的数据不会补造。每页默认 50 条、最多 200 条，按时间与 ID 倒序游标分页。追踪新日志每 5 秒刷新第一页，隐藏标签页、打开详情或固定结束时间时停止。详情支持键盘关闭与焦点返回，Request ID 可关联其他日志，任务操作统一进入任务中心。登录失败来源与限流汇总收在登录日志中，汇总范围与逐条记录分别标明。

统一接口为 `/api/admin/log-workspace/:category`，类别为 `system/access/login/operations/tasks/containers`；导出追加 `/export?format=json` 或 `csv`。查询与导出遵循同一筛选，导出最多 5,000 条，超出显示截断提示并返回 `X-Log-Export-Truncated`；JSON 含 meta、fields、rows、truncated，各类 CSV 使用自己的字段表头。导出写入管理审计，敏感字段递归脱敏并防 CSV 公式注入。

认证事件在 `obs_login_events` 独立持久化、保留 90 天，不随系统日志 5,000 条上限删除；初始化回填仍可用的旧认证事件。操作成功和失败共用检索，历史未记录的角色、设备、请求和实例显示“未记录”。请求上下文由服务端生成并通过异步上下文传递，任务执行实例由实际领取者记录，不继承其他请求。

运行概览仅保留跨模块摘要，请求分析与访问分析共享侧栏父入口，运行监控和数据库各有独立任务入口。`/resources` 跳转数据库；旧 `/monitor?view=overview/traffic/service/resources` 分别归并到请求、访问、应用自身、系统资源。数据库维护不再出现在运行监控；账本打开遥测统一归访问分析。

## 指标口径

| 数据 | 口径与边界 |
|---|---|
| API 请求 | 响应完成时计数，排除健康探针、静态资源、页面上报和新运维 API 自身；不记录 URL 查询参数 |
| 5xx 错误率 | 同窗口 5xx / 全部有效响应；4xx 单列，HTTP 错误率告警也改为 5xx |
| QPS | 所选统计窗口的响应数 / 窗口秒数；与错误率、延迟共用范围，分钟／小时边界以页面回显为准，趋势首尾桶使用实际覆盖时长 |
| P50/P95/P99 | 固定非累积直方图，先合并计数再求分位数；显示命中桶上界，超过 10 秒显示溢出桶下界 10000 ms，属于近似值 |
| PV | 浏览器有效页面进入及 SPA 模块切换；带 eventId 的事件在服务端幂等，兼容旧客户端 |
| UV | 窗口内服务器 HMAC 派生的浏览器标识去重；不是 IP 或精确人数，清除存储、跨设备会产生误差 |
| 会话 | 同一浏览器空闲至少 30 分钟开始新会话；计数窗口内开始的会话，边界前回看 30 分钟 |
| 近 5/30 分钟活跃 | 近期有页面浏览的浏览器数；停留阅读不持续上报，属于活动估算，不是实时连接人数 |
| 地区 | 仅信任已配置可信代理覆盖的国家代码，缺失归未知；选择地区同时过滤趋势、页面及汇总 |
| Node 资源 | RSS、堆、external、ArrayBuffer 和事件循环分别呈现；CPU 单核 100% 基准，允许超过 100% |
| 容器资源 | 现有系统采集器读取 cgroup；无内存限额时分母为空，不使用宿主机总内存代替 |
| 数据库 | 真实 SQLite PRAGMA、轻量探针耗时、页面容量、WAL 与原有备份证据；慢 SQL/BUSY/查询 P95 未接入时明确说明 |

浏览器尊重 Do Not Track 与 Global Privacy Control，关闭统计时不写访客标识。服务端排除常见 Bot User-Agent，无法识别所有机器人。桌面壳与管理员账本预览不增加业务页面统计。原始 IP 不进入页面分析表；访问和登录安全日志单独受管理员权限限制。

## 数据来源与可靠性

新运维接口位于 `/api/admin/ops/`，沿用服务器认证和角色校验，拒绝普通成员与未认证请求。响应带 `generatedAt`、`dataAsOf`、`source`、`stale` 和采样周期。刷新失败保留旧数据并标为过期；没有样本显示未采集；已采集的空窗口显示 0 请求，延迟与错误率为空。

| 接口 | 数据 |
|---|---|
| `requests/summary` | 同窗口摘要、直方图、路由排行与趋势 |
| `runtime/current` | 当前实例 Node 指标，启动时更新实例 ID |
| `database/current` | SQLite 引擎能力及轻量 PRAGMA 读取 |
| `jobs/heartbeats` | 状态、最近成功、最近失败、耗时与积压 |
| `logs/access` | 错误或至少 1 秒的 HTTP 明细 |
| `notifications/deliveries` | 最近 100 条投递、次数与重试状态 |
| `host` | 固定状态文件中的独立宿主机探测；缺失或不可读时为未采集 |

请求在内存聚合，最多 2,000 个维度桶及 500 条异常明细，每 30 秒批量事务写入；写入失败不阻塞响应，丢弃和失败数可见。请求报表在 SQLite 对保留的分钟表与小时表完整聚合，分别查询总量／直方图、前 50 路由及趋势，不再用 50,000 行原始明细截断后计算。分位数先合并直方图再计算，小时与日汇总不平均 P95。重启前未落库统计可能丢失，不用于账务核对。

采集心跳分别记录 Node/数据库汇总、系统资源和 HTTP 写入。最近失败优先于旧成功；运行超过 30 秒为超时，完成超过 90 秒为过期。实例 ID 随启动更新，查询默认包含窗口内历史实例。

新增 `obs_http_buckets`、`obs_http_hour_buckets`、`obs_http_events`、`obs_heartbeats`、`obs_traffic_ids` 与 `obs_notification_deliveries` 为可重复执行的附加建表。请求分钟桶保留 7 天，再以每轮最多 2,000 个源行原子搬移到小时表；小时计数、耗时与直方图合并后才删除源行，可查询尚未全部搬移的两类数据且不会重复计数。小时表保留 90 天，旧版尚存的分钟数据同样可逐步搬移。异常明细与幂等键仍保留 7 天，投递历史 90 天，原有指标、页面事件、系统日志和审计沿用原保留配置。

告警沿用连续异常/恢复、最小样本、知晓、静默和阈值设置。触发与恢复先写持久化 outbox，再发送；失败最多 5 次，按 1、2、4、8 分钟退避，重启后继续。投递按启用渠道汇总，部分失败保留说明；整次投递重试可能使先前受理的渠道重复收到通知。Webhook/Bark 最长 8 秒，不跟随重定向。Bark 成功只代表服务受理，不保证手机展示。

## 独立宿主机探活

`scripts/linux/observability-check.mjs` 是一次性宿主机脚本，必须由独立调度启动。它探测 `/readyz`、数据卷空间/inode，以及白名单内最多六个容器的 running、health、OOMKilled 和重启次数。连续两次异常激活、连续两次成功恢复，同类通知冷却 15 分钟；失败投递下次重试。

在宿主机准备权限为 600 的 `/etc/zichan/observability.env`，按实际部署填写：

```ini
OBS_HEALTH_URL=http://127.0.0.1:8787/readyz
OBS_DATA_PATH=/实际的宿主机数据目录
OBS_STATE_FILE=/实际的宿主机数据目录/host-observability.json
OBS_CONTAINERS=实际应用容器名
# 可选：允许读取日志的容器名，逗号分隔、最多六个。
OBS_LOG_CONTAINERS=实际应用容器名
OBS_LOG_STATE_FILE=/实际的宿主机数据目录/container-logs.json
OBS_BARK_URL=https://你的Bark服务域名
OBS_BARK_DEVICE_KEY=从Bark应用读取
# 使应用能读取状态文件；填写应用的宿主机映射 UID/GID。
OBS_STATE_UID=1000
OBS_STATE_GID=1000
```

数据目录须已存在并允许应用访问；脚本只修改状态文件属主。修改 `.service` 的 `ExecStart` 为实际 Node 和脚本路径；测试机 Node 可使用 `/opt/zichan-node-26.13.0/bin/node`。将 service/timer 安装到 systemd 单元目录，先运行 `systemd-analyze verify`，再 `systemctl daemon-reload`、`systemctl enable --now zichan-observability.timer`。

检查器账号须具备必要 Docker 读取权限；业务容器不挂载 Docker Socket。Bark 密钥只进 HTTPS POST JSON，不写状态文件或输出。状态文件通过现有数据卷在应用内显示为 `DATA_DIR/host-observability.json`。超过三分钟未更新标为过期，未安装不显示假正常。

容器日志桥接使用同一 timer 调用 `container-log-snapshot.mjs`，对每个白名单容器固定执行 `docker logs --timestamps --since 24h --tail 200`，最多各保留 200 行、每行 4,096 字符。状态文件原子替换、权限 600，并应用上述 UID/GID。业务应用只读取固定的 `DATA_DIR/container-logs.json`，文件上限 6 MiB；未配置、格式错误、超过三分钟未更新分别提示。stdout 与 stderr 分开保存，可查询、详情、导出和追踪；它是有界快照，无法恢复更早或已轮转日志。

`/livez`、`/healthz` 只表示进程可应答，`/readyz` 检查数据库读操作，不暴露内部拓扑。同机脚本不能保障整机停电/断网时的通知；这种需求须在异机单独配置目标和状态目录。本次只提供脚本与单元，没有自动安装到生产服务器。

## 当前引擎与验收边界

仓库实际使用 `node:sqlite`，没有 PostgreSQL 业务驱动，不增加虚假的引擎切换、PG 连接池或 Redis/BullMQ 指标。统一 SQL 包装层的慢查询和锁错误统计尚未接入。容器日志通过宿主机白名单快照读取，后台不挂载 Docker Socket。

系统日志和认证审计继续使用项目现有日志实现，没有切换成 Pino，也没有将安全审计放入可丢弃指标队列。环境/服务选择、多实例领导者锁、任意告警表达式和 PostgreSQL 适配不在本次单机 SQLite 扩展中。生产容量、真实 Bark 设备送达和恢复演练须在目标部署验收，不能以本机页面测试代替。
