# 五逻辑节点跨机预验收（2026-10-28）

## 环境

- 两台物理机器：Linux 测试机运行四个 Docker 容器，Windows 本机运行一个原生同步服务。五个节点使用独立持久数据目录、独立节点身份和不同端口。
- 本次仅使用隔离的测试账号与测试账本。复制入口使用临时测试 TLS 证书；浏览器页面通过局域网 HTTP 访问并显式开启测试用不安全传输。
- 四个 Docker 节点各限制 768 MiB 内存。节点地址从另一台机器可达。

## 代码验证

- `npm run build:server`、`npm run typecheck` 通过。
- `npm test` 通过：1,454 个测试通过，1 个仅限 Linux 的锁测试在 Windows 测试主机跳过。Linux Docker 的强制停止与重启已在上表单独实测。
- 三站浏览器回归测试通过，并明确断言恢复后 `READY 3/3`。

## 验收中修复的问题

1. 组内统一账号绑定按同步组 ID 存储，而副本目录核对原先按账本 ID 查找，造成实际数据已经复制、健康状态却持续 `CATCHING_UP 1/5`。目录核对现按账号唯一绑定读取；新增回归测试。
2. Docker 容器强制停止会留下备份执行器锁。新容器的 PID 再次为 1 时，旧代码误判为同一执行器，无法启动。Linux 锁现记录进程启动身份；同 PID 的旧进程锁可安全回收，仍会拒绝同时运行的执行器。

## 仍需独立验收

本次只有两台物理机器，四个 Docker 节点共用 Linux 主机，因此不能证明三台独立主机同时故障隔离。临时证书不能代替生产域名和受信任证书。尚未执行整机重启、跨公网长时间运行、独立磁盘故障、备份恢复和节点退役演练；这些步骤继续按 [three-node-acceptance.md](three-node-acceptance.md) 完成。
