# 重构实施记录

本轮基于当前代码逐项复核后实施；本记录不是“全项目重构已经完成”的声明。不修改用户账本，不自动重置数据库，不部署远端服务。

## 已落地

1. **质量门禁可复现**：将覆盖率配置放入 Vitest 的 `test.coverage`；忽略规则仅忽略根目录报告，不再忽略 `tools/coverage` 源文件；补齐 ESLint 锁文件；安装统一使用 `npm ci`。三个独立工具目录均通过离线锁文件安装。尚未在另一台机器做完整干净检出。
2. **金额维度**：游戏金额按结算资产和手续费资产分别选择；未指定币种而包含多币种时拒绝直接相加。DCA 报表要求相同计划、本位币和目标资产；剩余成本 API 支持显式币种选择，默认拒绝混币。
3. **转换连续性**：逐步核对前一步目标净入和下一步来源实扣，包含来源与目标手续费。余额保留或额外投入必须拆成独立转换。修正演示数据及旧测试中的毛额/净额混用，不改最终卖出收入。
4. **定投服务边界**：新增 `saveConversionAggregate`，从页面移出原有事务流程；校验计划资产匹配，编辑时使用重算后的执行版本，切换计划时按新计划分配期次，保留备注。测试覆盖回滚、编辑和切换计划。
5. **重算读放大**：复用 `listStepsByChains` 批量取步骤，以 Map 替代持仓、消耗记录及转换的重复线性查找。仍然全量重放，尚未实现历史后缀增量重放。
6. **代理边界**：提取请求来源模块，支持 IP/CIDR、右向左验证代理链；不受信任来源的转发头无效；代理转发的回环地址不能取得本机 HTTP 豁免。保留 `private` 显式兼容选项，后续部署配置仍需收紧。
7. **分页竞态**：流水和账户分页增加请求代次与同步防重入保护，筛选改变、刷新或卸载后旧响应及错误不再覆盖当前状态；含异步逆序完成单测。
8. **诊断日志隔离**：单个 sink 的同步异常不影响业务和其他 sink；内存日志默认仅保留最近 1000 条，可配置正整数上限。
9. **构建上下文**：新增 `.dockerignore`，过滤环境配置、运行时目录、密钥、SQLite 文件和生成物。未宣称已经完成容器权限、镜像固定或发布签名加固。

## 复核时纠正的假设

- 游戏 Web 页面已经使用按日期汇率折算；本轮只替换其非财务活动汇总调用，没有另行改变页面折算规则。
- 转换与定投执行原本已在页面的同一事务中保存；问题是业务流程落在页面、缺少匹配校验及编辑版本处理，不是“两次提交”。
- 原覆盖率配置层级无效，不能将旧报告的约 31% 当作真实源码基线。修复配置后的基线为 55.25%；本轮代码回归报告为 55.44% 行覆盖率。

## 验证

- 原基线：522 项测试通过。
- 本轮最新覆盖率运行：82 个文件、544 项测试通过；行 55.44%、分支 72%、函数 80.35%，已配置的门禁正常生效。
- Lint、全工作区 typecheck 通过。
- 发布一致性及 21 项发布测试通过；Web 和同步服务构建通过。Web 仍有大 chunk 警告，尚未完成首屏包体优化。
- 三个工具目录通过 `npm ci --offline --ignore-scripts`；这不是网络漏洞审计结论。
- 浏览器回归使用本机 Chrome 的独立测试上下文，11 项通过（26.3 秒，退出码 0）。沙箱内首次运行用例全部通过但收尾未退出，取消并确认子进程退出后，在提升权限环境完成重跑；没有使用个人浏览器配置。
- 本轮没有修改 Rust，未重新执行 Rust/SQLCipher 全套验证；没有运行 Docker 构建。

## 兼容性与上线前检查

- 先导出加密备份，再对已有账本运行数据自检。旧转换若本来存在未明确记录的中间余额，新连续性校验会报告错误，也可能阻止重算/导入；不要用“重置账本”解决，应核对原始成交记录后显式修复。现有数据不会被自动改写。
- 本轮仍是 schema 116，没有数据库升级或历史数据迁移。新增约束的迁移与旧数据修复工具尚未交付，因此不应直接作为生产升级发布。
- 被配置为可信代理的连接必须提供单一的 `X-Forwarded-Proto: https`；直接本机访问需要不把自身当作代理，或通过已配置的 HTTPS 入口访问。默认 Compose 的宽泛 `private` 信任尚待替换。
- `seasonSummary`、`buildDcaReport` 和 `remainingCostBasis` 的混币输入现在会报错，二次开发调用方需先分组或显式选择币种。

## 后续顺序与验收条件（未完成）

1. **数据兼容层**：固定 116 基线，建立正式前向迁移和迁移失败回滚；旧转换诊断与批量显式修复；DCA 链唯一约束和导入/同步关系校验。要求 Node SQLite、sql.js、SQLCipher 同契约，并验证旧备份恢复。
2. **服务器首次所有者认领**：设计一次性、独立秘密的领取流程，覆盖 CLI、Docker 和桌面启动；保留已存在所有者；空服务器默认不对任意首个注册者授予管理权。要求并发领取只有一个赢家，失败/重启不绕过认证。
3. **崩溃恢复和桌面边界**：数据目录排他锁；服务与维护命令使用同协议；SQLite/文件双写操作日志；桌面默认监听与 LAN 选择、IPC 大小/hash 校验及 SQL 权限控制。要求逐故障点注入与重启恢复测试。
4. **运行时数据校验**：统一未知输入解析、结构/引用关系错误报告，覆盖 DB 读取、导入、同步和冲突解决，禁止静默丢弃损坏子记录。
5. **模块拆分**：按转换、流水、定期、物品、游戏、备份等领域提取服务；仓储组合拆分且保持同一事务上下文；定期任务作为依赖注入试点。不在机械拆分时顺带改业务语义。
6. **前端数据层**：统一查询/失效机制；为增长型数据建立分页读模型；启动状态机、Transactions/Settings/Sync 模块拆分；增加实际组件与浏览器交互回归，尤其是筛选切换时的延迟分页响应。
7. **性能与交付**：增量重放与全量算法对照；懒加载/子路径导出；首屏包体预算；容器最小权限、固定镜像、签名与供应链校验。公开发布签名依赖实际证书及发布凭据，不在缺少凭据时伪造完成。
