# 管理后台：操作路径与后续能力

## 本阶段交付

后台按六个稳定领域组织：总览、用户与访问、数据与备份、运行与维护、事件与记录、系统设置。桌面端所有页面入口常驻侧栏；手机端直接排列全部入口，不需要打开菜单。已有页面 URL 保持不变，个人账号安全放在顶部。

2026-09-29 根据用户反馈推翻折叠式方案：以直接访问和清晰的空间布局降低操作成本，不再用隐藏入口减少视觉信息。参考 [Tabler 开源项目](https://github.com/tabler/tabler)的[页头与布局](https://docs.tabler.io/ui/layout/page-layouts)，以及 [React-admin](https://github.com/marmelab/react-admin)的[列表工具栏](https://marmelab.com/react-admin/List.html)。采用紧凑页头、常驻导航、直接操作与响应式信息面板；保留现有 React 技术栈，自行实现界面，没有引入模板框架或复制外部代码。

- **总览**：服务结论 → 待处理事项与常用操作并排 → 数据保障 → 趋势与资源并排。技术趋势、管理员登录、维护表单直接显示，页头分区链接可直接定位。状态未加载或过时明确显示未知；从未触发的采样规则不显示为待办；暂停通知、标记已知晓不等于恢复。
- **待处理事项**：活动告警优先，严重级别优先；保留真实的观察中异常。告警引导到对应用户、备份、同步或资源页。失败管理操作可按请求 ID 进入日志；失败/中断任务可直接查看具体结果，仍需核对是否已重试。
- **用户支持**：用户操作前置在详情页顶部；账号访问、最近同步请求、容量、记账预览条件集中显示，账号与配额在桌面并排。无同步记录不推断为故障，最近一次请求成功不代表所有设备已收敛。关联页面继续带账号筛选。
- **备份执行状态**：状态摘要后直接展示备份记录与行内操作，计划与空间信息在桌面并排。分别展示计划、最近执行、成功/校验记录及自动执行器的未知状态。摘要不受列表筛选或分页影响；保留清理、恢复演练和未执行的计划不能充当新备份成功的证据。
- **设置**：备份计划、告警通知、访问安全、记录保留、高级阈值分组。每组说明何时需要调整，保存前展示变更；仅提交本组设置。刷新生效值保留其他组草稿，放弃操作只作用于本组。环境覆盖项不可编辑；默认值、允许范围、部署信息直接显示，保存栏在滚动时保持可达。分组写入 URL。

## 当前能力边界

### 2026-09-29 逐页补齐

| 页面 | 本轮交付行为 |
| --- | --- |
| 用户列表与详情 | 列表直接显示预览、启停、两类配额、角色、会话操作；信息分组展示，确认表单紧跟当前账号；连续操作后清理旧表单 |
| 设备与会话 | 筛选常驻，批量撤销与刷新位于页头 |
| 注册与邀请 | 策略与生成并排，邀请码列表在增长统计之前 |
| 同步诊断 | 失败/会话失效快捷筛选前置，记录在错误分类说明之前 |
| 任务中心 | 创建后自动定位详情，详情在顶部，任务列表保留完整宽度，防止重复创建 |
| 运行日志与管理审计 | 页头刷新/导出，日期筛选直接可用；审计详情紧邻所选记录 |
| 告警历史 | 状态视图写入 URL，行内知晓、暂停通知、恢复通知；仍区分恢复与通知状态 |
| 安全事件、资源、账号安全 | 统一页头与刷新位置，资源和安全设置按工作区域排列，未知数据不伪装为零 |
| 总览、备份、设置 | 保留上一批直接可达布局，统一页头 |
| 手机列表 | 转为带字段名的记录卡片，默认保留全部字段和操作，不再要求展开次要列 |

敏感操作仍保留必要确认，私密账本仍受原有解密能力约束。列偏好、分页、权限、审计与只读预览继续有效。下面的未来能力不属于本轮完成范围。

1. 自动备份执行器已在后续批次实现：标准服务器入口自动管理监督进程，支持维护窗口、停服备份校验、恢复启动、持久化去重与心跳。自动备份默认关闭，详情见 [执行器说明](backup-executor.md)。缺少心跳、失联和接口失败仍明确显示异常或未知。
2. 待处理事项复用已有告警确认、通知暂停及恢复检测；未引入工单分派、处理备注和独立事件生命周期。历史失败任务不自动标为已修复。
3. 本批不增加账本修改、自动修复、生产恢复、自动升级功能；管理员账本预览仍只读并记录原因。
4. 通知渠道沿用已有配置格式；可视化渠道编辑器安排在后续，不将 JSON 输入宣称为已完成的表单化配置。

## 后续建设顺序

| 阶段 | 能力 | 归属 | 完成条件 |
| --- | --- | --- | --- |
| 下一批 | 首次配置检查 | 总览 | 区分必须、建议、可选；以真实执行证据判定备份保障，完成后可收起 |
| 已交付 | 备份执行器接入 | 数据与备份 | 报告执行器身份/心跳、最近尝试、下一次计划、失败与校验结果；失联显示异常；服务重启不重复执行。保持停服全量备份，自动备份默认关闭 |
| 下一批 | 通知渠道表单 | 系统设置 | 支持现有渠道类型与试发结果，保持秘密脱敏与配置兼容，不丢失已有高级字段 |
| 后续 | 事件处理过程 | 事件与记录 | 告警、任务、请求可关联；支持处理备注；确认/通知/恢复状态独立，后端权限与审计齐全 |
| 后续 | 同步健康与诊断包 | 用户与访问、运行与维护 | 使用已有证据区分离线、拒绝、失败、版本不兼容；诊断包默认不包含正文与凭据 |
| 后续 | 恢复向导、隔离演练 | 数据与备份 | 预检查、影响预览、执行、验证闭环；正式恢复与演练明确区分，失败后有可验证恢复路径 |
| 后续 | 数据完整性中心 | 数据与备份 | 每类检查显示覆盖范围、时间和问题；修复动作需独立设计及故障恢复测试 |
| 后续 | 容量趋势与版本兼容 | 运行与维护 | 样本不足不预测；升级检查涵盖版本、备份、空间与维护条件 |
| 后续 | 配置历史与回退 | 系统设置 | 记录前后值、操作者与生效方式，仅支持可安全回退的配置 |
| 有需求再做 | 细粒度权限、组织、工单分派、多服务器、订阅计费 | 对应领域 | 出现真实分工、隔离、多部署或商业化需求后再设计，当前不展示空菜单 |

## 后续开发约定

- 新功能先确定所属领域及用户任务，再新增二级页面；避免继续增加平铺的一级入口。
- 长任务复用任务状态与审计，排障链接携带账号/请求上下文，保留直接链接与刷新能力。
- 状态区分未配置、未执行、执行失败、已完成、已校验与未知，不能从开关值推断执行成功。
- 每项交互验收实际点击入口，覆盖返回、刷新与窄屏。API 测试不替代页面入口测试。
- 测试基线与本次交付证据见 `docs/worklog.md`；运行日志、截图和临时数据不纳入版本库。
