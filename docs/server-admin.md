# 独立服务器管理后台

> 当前账号保护采用[云端托管与私密模式](ledger-protection.md)：托管账号登录后自动解锁，私密账号使用恢复码。最新验收见[交付记录](release-readiness.md)。


新版用户入口以 [Web 账号 v2](web-account-v2.md) 为准：不再兼容旧浏览器本地账本，按账号隔离缓存，用户端不再提供服务器管理页面或跳转。

## 入口与初始化

同一服务器提供 `/app/` 记账应用和 `/admin/` 管理后台。设置 `BASE_PATH=/ledger` 后，入口分别为 `/ledger/app/`、`/ledger/admin/`。需要同站 Web + API 部署，远程访问默认使用可信 HTTPS；显式设置 `ALLOW_INSECURE_HTTP=1` 后可改用私有局域网明文 HTTP。

首次打开 `/admin/`，在 Web 引导中设置管理员用户名和密码即可，不再要求读取或填写初始化密钥。没有内置 admin 用户或默认密码。已有所有者直接登录，不重新初始化；初始化写入为原子操作，只允许一个所有者创建成功。新部署请先完成此设置，再对外开放服务。旧版自动化的密钥接口暂时兼容，但不是 Web 初始化的前置条件。

管理后台不经过 StoreProvider，不创建或解锁账本、不打开账本 IndexedDB、不申请账本持久存储或磁盘文件权限。页面明确说明这些边界；管理身份不授予用户账本解密权限。

## 角色权限

| 行为 | Owner 所有者 | Admin 管理员 | Member 普通用户 |
|---|---|---|---|
| 进入后台、查看状态/用户/审计 | 可以 | 可以 | 拒绝 |
| 管理普通用户状态、设备、配额 | 可以 | 可以 | 拒绝 |
| 管理其他管理员状态、设备、配额 | 可以 | 拒绝 | 拒绝 |
| 调整所有者自身配额 | 可以 | 拒绝 | 拒绝 |
| 任免管理员、修改注册策略 | 可以 | 拒绝 | 拒绝 |
| 禁用所有者或更改所有者角色 | 不开放 | 拒绝 | 拒绝 |
| 撤销自己账号的其他会话 | 可以（需最近 5 分钟登录） | 可以（需最近 5 分钟登录） | 不适用 |

角色变更要求所有者在最近 5 分钟内登录，刷新访问令牌不延长该窗口。过期时需退出后台、重新登录再操作。角色变更撤销目标现有全部会话；禁用账号同样立即撤销会话，但保留数据。启用账号不复活旧会话。

新服务器默认仅邀请注册，Node、Docker、Windows 启动脚本及桌面内置服务器一致；已有数据库中的注册策略保持不变。Windows 脚本保留显式环境变量覆盖。

## 页面与路由

管理后台是独立的单页应用，每个页面都有自己的 URL；刷新、返回/前进和分享链接都会回到同一个页面与同一组筛选条件。筛选条件写入 URL query，不保存重置码等敏感内容。服务端已对无扩展名路径回退 `index.html`，所以路由不需要改服务端，也没有给 Web 包引入路由依赖。`BASE_PATH=/ledger` 时前缀同样生效（`/ledger/admin/users`）。旧的单页 tab 界面不再保留，也不需要兼容旧地址。

| 页面 | URL | 内容与操作 |
|---|---|---|
| 运行概览 | `/admin/overview` | 服务状态（正常/降级）、运行时间、服务版本、最后采样时间与有效会话；核心指标（请求量、错误率、平均耗时、提交推送、附件请求，支持近 1 小时/24 小时/7 天）；数据保障（磁盘余量、最近成功备份、最近数据库与附件校验、最近清理及释放空间）；待处理事项（告警、最近失败的管理操作、失败或中断的维护任务）与下一步入口。默认每 30 秒刷新一次，标签页不可见时暂停；刷新失败保留上一次成功数据并标注“数据已过期”。 |
| 用户管理 | `/admin/users`、`/admin/users/:accountId` | 列表按 25 条游标分页，支持用户名/accountId 搜索与角色、启用状态、保护模式、配额状态筛选；每行提供“详情”，以及就地展开的快捷处理（启用/禁用、撤销全部可管理会话）。详情页汇总账号信息、容量与配额、会话、同步情况、操作记录，并集中所有写操作。 |
| 设备与会话 | `/admin/sessions` | 按会话分页（每页 25 条会话，不再按账号展开），可按用户名/accountId/设备名搜索并筛选状态与会话类型，区分管理后台会话与记账会话。支持撤销单会话与“撤销当前页可撤销的会话”，批量操作前说明范围并逐项报告成功、失败与无权限项。 |
| 同步诊断 | `/admin/sync` | 错误分类表（类型、页面解释、下一步）与诊断记录：账号、设备、服务端接收时间、操作类型、提交数量、传输字节、耗时、结果代码、原因分类。可按时间范围与分类筛选，请求 ID 可跳到运行日志。页面注明只覆盖服务端可见结果。 |
| 注册与邀请 | `/admin/invites` | 注册策略直接回显服务端生效值，所有者修改后立即保存；关闭注册时明确说明邀请码也不可用。生成 1–30 天有效期的单次邀请码，新码在本页显示并可复制；列表支持状态筛选与翻页，可撤销/重新启用未使用的邀请码。 |
| 存储与备份 | `/admin/storage` | 空间组成分列显示数据库、WAL、有效附件、回收站、暂存上传、备份目录与磁盘余量；清理状态显示最近运行、结果、连续失败次数与释放空间；备份记录可发起校验与恢复演练任务（仅所有者），并说明备份/恢复必须停服由部署侧执行。 |
| 任务中心 | `/admin/jobs` | 用预定义任务类型（数据库完整性校验、附件校验、附件清理、日志裁剪、指标裁剪、备份校验、恢复演练）创建任务，可限定账号或备份记录；列表按状态与类型筛选，详情显示阶段、进度、参数、结果摘要与执行记录，运行中的任务每 5 秒刷新，可请求取消或在安全边界后重新执行。 |
| 运行日志 | `/admin/logs` | 按级别、请求 ID、时间范围筛选，100 条分页；请求 ID 可点击作为筛选条件，便于从错误提示直接定位。 |
| 管理审计 | `/admin/audit` | 服务端筛选（关键字、动作、操作者 accountId、目标 accountId、时间范围）与 50 条分页；默认显示可读句子，原始前后值在详情展开；受控导出 JSON/CSV 并遵循当前筛选；同页展示失败的管理操作。 |
| 系统设置 | `/admin/settings` | 允许在线修改的设置清单，逐项标注生效值、来源（环境变量/数据库/默认值）与允许范围；环境变量覆盖项只读。另显示版本、访问令牌与会话时长、密钥是否已配置，以及数据目录、基础路径、注册策略、账号保护等运行环境信息。 |

管理变更有确认对话框或提交前说明。管理操作只在独立后台；用户端同步页的管理标签、管理链接和设置页本机服务器控制面板均已移除。用户端仍支持“设置 → 管理同步服务器”配置多台本机/局域网/公网同步目标；这不授予服务器管理权限。

读取失败时不显示可编辑的空表单：用户详情读取失败会显示错误并提供“返回用户列表”，配额与状态保存按钮在读取成功前不可用；连接检查失败时登录页提供“重新连接服务器”，不需要刷新整页。健康检查、管理数据请求和退出请求有 30 秒超时，后台不会自动重复写操作；写请求超时不等于失败，须先刷新核实服务器结果。这些超时不改变现有账号认证库的登录/刷新协议。

配额操作与禁用/降权保护分开校验；所有者可以调整自身提交、附件配额并恢复服务器默认值。降低上限不删除已有内容，但可能限制新上传。用户名叫 `admin` 不等于角色为 Admin，请以后台显示的角色为准。并发修改通过数据版本检测：提交携带 `expectedVersion`，其他管理员已修改时返回 `STALE_WRITE` 并提示刷新，不静默覆盖。

`GET /api/admin/invites` 默认返回 25 条，支持 `limit`（1–100）、`cursor`（数字，来自上一页 `nextCursor`）、`state`（available/used/revoked/expired）。筛选在分页前执行，按创建顺序倒序，继续读取须跟随 `nextCursor`，不能再假设一次返回全部邀请码。游标不包含邀请码秘密。已使用优先于撤销，撤销优先于过期，与页面状态一致。

网页版每次打开记账入口先验证本站账号会话；失效时显示账号密码登录，不选择本地模式或填写服务器地址。登录与注册分开，注册需确认密码，邀请模式注册需邀请码。未初始化服务器提示联系部署者。桌面版继续保留本地/服务器选择；旧浏览器账本不读取或迁移。账本加密解锁仍独立于账号认证。

## 任务中心与维护

附件校验、数据库完整性校验、清理与日志裁剪都可能耗时，因此不再在 HTTP 请求内完成：接口创建任务并返回 `202`，由单执行器分批执行，执行期间登录与同步保持可用。

- 状态统一为“排队中 → 执行中 → 成功 / 失败 / 已取消 / 执行中断”，任务记录类型、发起人、目标范围、参数、开始/结束时间、阶段、已处理数量与结果摘要，另有执行记录条目。
- 取消只在批次边界生效；重新执行会创建一个新任务并记录 `retryOf`。
- 服务在任务执行期间退出时，重启后把失去执行者的任务标记为“执行中断”，只有带检查点的扫描（附件校验）从中断点续跑，其余保持中断状态等待人工决定。
- 任务只接受预定义类型与参数（例如限定 `accountId` 或已登记的备份记录 ID），不接受命令或任意文件路径。
- 写接口支持幂等键：同一键与同一参数返回同一次结果（带 `replayed` 标记），同一键换参数返回 `IDEMPOTENCY_KEY_REUSED`，键格式不属于 `[A-Za-z0-9._:-]{8,128}` 时返回 400。幂等记录有保留窗口与条数上限。
- 健康检查 `/api/ready` 只做轻量探测（`SELECT 1` 与迁移行数），不再每次执行全库检查；`quick_check` 与深度 `integrity_check` 都由任务执行。

## 指标、诊断与告警

- 请求指标按分钟与小时分桶，内存累加、每 30 秒落库一次，避免每条请求都写库；指标与诊断事件各有独立保留策略，不受运行日志裁剪影响。
- 同步诊断只记录服务端实际接收到的同步请求及其结果代码，按错误分类给出下一步建议。
- 告警规则覆盖容量、备份失败与逾期、校验问题、清理连续失败、持续同步错误与磁盘空间：连续两次异常才生效、连续两次恢复才解除，同类合并并记录首次/最后发生时间、次数与确认人。
- 概览与告警使用轻量缓存快照（由采样任务刷新），`/api/health` 只返回身份、协议、能力与注册策略等常量，不再做账号/会话/提交的聚合。

## 会话与审计

- 管理 Cookie 为 `zichan_admin_session`，记账 Cookie 为 `zichan_session`，互不覆盖。独立显式请求头选择刷新与退出上下文；Origin 校验阻止跨站 Cookie 操作。
- 管理 Cookie 使用 HttpOnly、SameSite=Strict、会话 Cookie；生产 HTTPS 下为 Secure。服务端仍使用最多 7 天的会话有效期；后台不提供记住设备或离线管理。
- 访问令牌仅内存，不把账号密码、刷新令牌或管理数据写入 Web Storage/IndexedDB。浏览器自身密码管理器不属于应用存储。
- 并发请求共享刷新，多标签页序列化刷新。管理登录切换/退出通过 BroadcastChannel 通知其他管理标签页清空界面（在一个标签页退出后，其他标签页会明确提示并回到登录页）。旧管理请求取消或丢弃结果，不能重新填回旧数据。
- 离线退出先清空本页；若服务端撤销未确认，页面明确提示，不声称已撤销远端会话。
- 会话按会话本身分页并区分管理后台会话与记账会话；所有者会话与其他管理员的会话受保护，管理员不能管理它们。自己账号的会话可以由本人撤销（需要最近 5 分钟内登录），当前会话只能通过退出结束。
- 角色、账号状态、设备撤销、注册策略、邀请和两类配额，与审计在同一 SQLite 事务提交。审计失败会回滚变更；被拒绝或失败的尝试写独立表，不与已回滚的事务审计混在一起。
- 审计记录操作者/目标 accountId、时间、动作、原因和前后值，默认渲染成可读句子（例如“管理员李四将用户张三的附件配额调整为 5 GiB。原因：容量申请。”）。审计可按动作、操作者、目标与时间范围在服务端筛选，并受控导出 JSON/CSV：不导出邀请码、重置码、令牌和密钥。
- 邀请码仅以 SHA-256 指纹关联，不写入可用秘密；运行日志遮盖邀请 URL 中的秘密。

早期原记账 E2E 曾在用例通过后发生 Windows 测试服务退出等待，核对测试 PID 与启动时间后仅停止该测试进程。新版已改为每例独立的进程内服务器 fixture，不复用用户服务，也不依赖外部进程树清理。

## 后续范围

本轮补齐（一期末期）：管理后台按页面拆分并拥有独立 URL；用户详情页集中写操作；审计服务端筛选与受控导出；会话按会话分页并逐项报告撤销结果；任务中心与异步校验；指标、同步诊断、告警与系统设置页；管理登录不再创建记账会话。

网页版设置提供“退出记账账号”，锁屏提供“退出并切换账号”：撤销记账 Cookie、清理内存凭据、关闭账本并锁定密钥，保留配置及分账号加密缓存，不撤销管理 Cookie；其他记账标签页同步锁定。断网退出标记服务端撤销未确认。现已接入主存储账号分区，退出后可以登录其他账号，不需清除网站数据。

记账 E2E 已改为真实账号注册、登录和缓存解锁，不再模拟旧本地模式。账号 E2E 单独覆盖初始化、登录、退出、重新解锁及换账号缓存隔离。

仍不在当前交付范围：管理员 MFA、只读运维角色、独立 `/account/` 页面、所有权转移、告警的外部通知渠道（邮件等）、浏览器下载整套服务器备份、归档与长期保留策略，以及“维护中”服务状态。管理员审核的一次性码密码恢复已实现，见下节。托管账号重置密码后可恢复原账本；私密账号仍需恢复码。Web 统一账号启动、即时同步调度及独立账本合并仍按账号模式记录继续推进。

## 管理员审核的密码恢复

1. 用户通过双方可信渠道联系管理员，请求恢复账号；目前不提供匿名工单或邮件服务。
2. 管理员在后台用户详情核实身份，勾选审核确认，发放一次性重置码，私下交给本人。此操作要求最近 5 分钟内登录。
3. 用户在记账或管理登录页展开“忘记账号密码”，输入用户名、重置码、新密码与确认密码。完成后使用新密码登录。

重置码有效期 15 分钟、仅可使用一次，重新发放使旧码失效。服务器只保存 SHA-256 摘要；页面只在当前详情内显示本次原码，不提供再次查询。账号禁用或角色变更也使待使用重置码失效。重置、撤销所有旧会话和写入审计在同一事务完成，并阻止重置前开始的登录再次建立会话。

原码到期自动隐藏，后台标签重新可见时再次检查有效期。手动隐藏或离开详情也不再显示；隐藏仅清除页面内容，不会提前撤销仍有效的码。

“撤销未使用的重置码”会清除当前待使用的一次性码并写入管理审计（动作 `password-reset-revoke`）；若没有待使用的码，操作返回 `revoked: false` 且不改变任何状态。撤销失败时页面明确提示，不会假装撤销成功。

Owner 可为 Admin/Member 发码，Admin 仅可为 Member 发码。网页管理员审核不支持为唯一 Owner 发码。Owner 使用部署者本机维护命令恢复，见 [账号安全与所有者恢复](account-security.md)。

重置保留 accountId、角色、配额和服务器上的加密账本数据。托管账本可在账号密码重置后自动恢复；私密账本仍须原恢复码或已有设备授权。
