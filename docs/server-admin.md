# 独立服务器管理后台

新版用户入口以 [Web 账号 v2](web-account-v2.md) 为准：不再兼容旧浏览器本地账本，按账号隔离缓存，用户端不再提供服务器管理页面或跳转。

## 入口与初始化

同一服务器提供 `/app/` 记账应用和 `/admin/` 管理后台。设置 `BASE_PATH=/ledger` 后，入口分别为 `/ledger/app/`、`/ledger/admin/`。需要同站 Web + API 部署，远程访问使用可信 HTTPS。

首次打开 `/admin/`，在 Web 引导中设置管理员用户名和密码即可，不再要求读取或填写初始化密钥。没有内置 admin 用户或默认密码。已有所有者直接登录，不重新初始化；初始化写入为原子操作，只允许一个所有者创建成功。新部署请先完成此设置，再对外开放服务。旧版自动化的密钥接口暂时兼容，但不是 Web 初始化的前置条件。

管理后台不经过 StoreProvider，不创建或解锁账本、不打开账本 IndexedDB、不申请账本持久存储或磁盘文件权限。页面明确说明这些边界；管理身份不授予用户账本解密权限。

## 角色权限

| 行为 | Owner 所有者 | Admin 管理员 | Member 普通用户 |
|---|---|---|---|
| 进入后台、查看状态/用户/审计 | 可以 | 可以 | 拒绝 |
| 管理普通用户状态、设备、配额 | 可以 | 可以 | 拒绝 |
| 管理其他管理员状态、设备、配额 | 可以 | 拒绝 | 拒绝 |
| 调整所有者自身配额 | 可以 | 拒绝 | 拒绝 |
| 任免管理员、修改注册策略 | 可以 | 拒绝 | 拒绝 |
| 禁用所有者或更改所有者角色 | 不开放 | 拒绝 | 拒绝 |

角色变更要求所有者在最近 5 分钟内登录，刷新访问令牌不延长该窗口。过期时需退出后台、重新登录再操作。角色变更撤销目标现有全部会话；禁用账号同样立即撤销会话，但保留数据。启用账号不复活旧会话。

新服务器默认仅邀请注册，Node、Docker、Windows 启动脚本及桌面内置服务器一致；已有数据库中的注册策略保持不变。Windows 脚本保留显式环境变量覆盖。

## 页面

- 概览：账号数、禁用数、有效会话、密文提交用量、数据库版本；有效会话不等于在线人数。
- 用户管理：25 条分页、用户名/accountId 搜索、角色/状态筛选、启用/禁用、任免管理员、设备撤销、提交和附件配额。新操作 URL 使用稳定 accountId，旧用户名端点经过同样授权。
- 注册与邀请：所有者改变注册策略；随机单次邀请码有效期 1–30 天，支持撤销/启用。旧邀请保留原行为并标注未设期限。
- 设备与安全：当前管理会话及权限说明；目标设备操作在用户详情。个人全部设备管理留给后续账号中心。
- 存储维护：校验数据库与加密附件，不提供清库、删除账号、远程停服或数据库替换操作。
- 审计日志：独立持久表、50 条分页、服务端全历史账号 ID/操作代码查询。尚无导出或保留期管理。

管理变更有确认对话框。管理操作只在独立后台；用户端同步页的管理标签、管理链接和设置页本机服务器控制面板均已移除。

配额操作与禁用/降权保护分开校验；所有者可以调整自身提交、附件配额并恢复服务器默认值。降低上限不删除已有内容，但可能限制新上传。用户名叫 `admin` 不等于角色为 Admin，请以后台显示的角色为准。

网页版每次打开记账入口先验证本站账号会话；失效时显示账号密码登录，不选择本地模式或填写服务器地址。登录与注册分开，注册需确认密码，邀请模式注册需邀请码。未初始化服务器提示联系部署者。桌面版继续保留本地/服务器选择；旧浏览器账本不读取或迁移。账本加密解锁仍独立于账号认证。

## 会话与审计

- 管理 Cookie 为 `zichan_admin_session`，记账 Cookie 为 `zichan_session`，互不覆盖。独立显式请求头选择刷新与退出上下文；Origin 校验阻止跨站 Cookie 操作。
- 管理 Cookie 使用 HttpOnly、SameSite=Strict、会话 Cookie；生产 HTTPS 下为 Secure。服务端仍使用最多 7 天的会话有效期；后台不提供记住设备或离线管理。
- 访问令牌仅内存，不把账号密码、刷新令牌或管理数据写入 Web Storage/IndexedDB。浏览器自身密码管理器不属于应用存储。
- 并发请求共享刷新，多标签页序列化刷新。管理登录切换/退出通过 BroadcastChannel 通知其他管理标签页清空界面。旧管理请求取消或丢弃结果，不能重新填回旧数据。
- 离线退出先清空本页；若服务端撤销未确认，页面明确提示，不声称已撤销远端会话。
- 角色、账号状态、设备撤销、注册策略、邀请和两类配额，与审计在同一 SQLite 事务提交。审计失败会回滚变更。附件元数据也是同一 server.sqlite，避免跨连接事务。
- 审计记录操作者/目标 accountId、时间、动作和前后值。邀请码仅以 SHA-256 指纹关联，不写入可用秘密；运行日志遮盖邀请 URL 中的秘密。

## 升级与验证

当前 schema 9，新增一次性密码重置码摘要表。从 schema 6/7/8 追加式升级，保留所有者、accountId、注册策略、凭据、账本绑定和数据。服务器备份允许这些可升级版本，恢复后下次启动升级；未知结构停止启动，不自动清库。通过恢复工具恢复备份时撤销所有旧会话、清除未完成登录及重置码，防止已使用的凭据恢复生效；用户需重新登录。

服务端与 Web 应成套更新。旧客户端可能不认识 `owner` 角色，桌面客户端也应升级。本轮没有重启用户服务、部署远端或迁移用户实际数据。

2026-09-09 验证：601 项单元/集成测试通过；类型检查、Lint、Web 和服务端构建、发布一致性检查通过；Chrome 的 13 项原有记账流程通过；Chrome、Edge 各通过 4 项账号/管理流程。测试覆盖后台不申请账本持久存储或创建账本 IndexedDB、越权拒绝、角色撤销、审计失败回滚、旧备份恢复、跨标签退出、独立 Cookie，以及密码恢复的单次消费、过期、并发兑换、旧会话/待完成登录失效和恢复备份后凭据不复活。Web 构建仍提示 ledger 分块大于 500 kB；桌面 Rust 安装包未重新构建。

命令：`npm test`、`npm run typecheck`、`npm run lint`、`npm run build:web`、`npm run build -w @zichan/sync-server`、`npm run test:e2e`、`npm run test:e2e:account`。本机用 `PLAYWRIGHT_EXECUTABLE_PATH` 指向 Chrome/Edge；默认 Playwright 浏览器未安装时，应指定已安装浏览器或先安装测试运行时。测试使用临时服务器和隔离浏览器资料。

早期原记账 E2E 曾在用例通过后发生 Windows 测试服务退出等待，核对测试 PID 与启动时间后仅停止该测试进程。新版已改为每例独立的进程内服务器 fixture，不复用用户服务，也不依赖外部进程树清理。

## 后续范围

本轮补齐：管理员创建成功后即切换登录状态，登录失败可重试；同步执行期间的新写入合并为一轮补跑，关闭账本后不再补跑；审计先查询再分页；`/api/admin/quotas` 和 `/devices` 支持 `cursor`、`limit`（1–500，默认 100），调用方必须跟随 `nextCursor` 读取后续页，设备列表按账号分页。

网页版设置提供“退出记账账号”，锁屏提供“退出并切换账号”：撤销记账 Cookie、清理内存凭据、关闭账本并锁定密钥，保留配置及分账号加密缓存，不撤销管理 Cookie；其他记账标签页同步锁定。断网退出标记服务端撤销未确认。现已接入主存储账号分区，退出后可以登录其他账号，不需清除网站数据。

记账 E2E 已改为真实账号注册、登录和缓存解锁，不再模拟旧本地模式。账号 E2E 单独覆盖初始化、登录、退出、重新解锁及换账号缓存隔离。

个人 `/account/` 中心、登录后的主动改密、所有权转移、MFA 尚未交付。管理员审核的一次性码密码恢复已实现，见下节。管理员不能通过重置密码恢复用户加密账本。Web 统一账号启动、即时同步调度及独立账本合并仍按账号模式记录继续推进。

## 管理员审核的密码恢复

1. 用户通过双方可信渠道联系管理员，请求恢复账号；目前不提供匿名工单或邮件服务。
2. 管理员在后台用户详情核实身份，勾选审核确认，发放一次性重置码，私下交给本人。此操作要求最近 5 分钟内登录。
3. 用户在记账或管理登录页展开“忘记账号密码”，输入用户名、重置码、新密码与确认密码。完成后使用新密码登录。

重置码有效期 15 分钟、仅可使用一次，重新发放使旧码失效。服务器只保存 SHA-256 摘要；页面只在当前详情内显示本次原码，不提供再次查询。账号禁用或角色变更也使待使用重置码失效。重置、撤销所有旧会话和写入审计在同一事务完成，并阻止重置前开始的登录再次建立会话。

Owner 可为 Admin/Member 发码，Admin 仅可为 Member 发码。此审核流程不支持为唯一 Owner 重置密码，也不提供匿名认领所有者的后门；所有者忘记密码的独立恢复方式尚未实现。

重置保留 accountId、角色、配额和服务器上的加密账本数据。账号密码不是账本解密密码：此操作不会更改或找回账本密钥，原账本仍须原解密凭据或可用的加密备份。
