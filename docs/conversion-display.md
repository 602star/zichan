# 资产转换与统一成本核算

## 余额与展示

- 当前余额来自账户起始余额、日常收支和有效转换，遵循账户余额起点，排除外部账户与已作废记录。日期、操作、涉及资产、账户和搜索筛选只影响历史记录。
- 法币、稳定币和投资资产都显示真实余额；游戏和物品沿用各自模块。全部可用金融资产即使余额为零也显示卡片和买入／卖出入口，避免与换入／换出重复。旧成本口径的货币资产首次点击买卖时先核对成本起点，确认后继续原交易；已启用统一成本的资产直接录入。投资资产还可在统一成本期间选择互换。转入／转出用于账户间移动或外部流入流出。已停用资产保留历史，但禁用新增快捷操作。
- 标题可以留空，默认显示资产路径。标题、平台、备注在详情显示；文字修改不重算成本，没有修改不写空审计。
- 数量按资产精度显示并去掉尾零；汇率与单位成本使用 8 位有效数字，详情可展开完整值。保存与计算仍使用 Decimal 原始精度。
- 缺少价格显示“待估值”，可输入当前持仓总现值或每单位现价；总现值按余额换算为行情，不写入历史成本。已知成本即使缺少报表币种折算率也先显示冻结核算币种的均价与总成本，并提示缺失汇率；成本不完整显示已知金额、未知数量及数量缺口，不把未知金额替换成零。
- 时间线每行显示转换路径、实际到账数量和实际付出或盈亏；点击打开居中详情弹窗。“全部流水与账户分布”也使用居中弹窗，逐笔显示该资产的流入和流出。手机使用全屏弹窗，关闭后恢复原列表位置与焦点。

## 核算事实与计算

- 客户端数据库当前为 schema 127；旧 schema 不支持原地升级。旧 lots/lotConsumptions 保留原期间的兼容用途。
- `CostBasisOpening`、原始转换/日常交易和价值快照是事实。新成本结果由纯计算事件重放产生，不独立同步。
- 成本起点冻结核算币种；起点只承接成本，不增加余额。数量和币种匹配的旧批次、已启用期间的有效批次可作建议，其他部分可明确保留未知。
- 新起点保留此前期间的收益及原核算币种。修改起点前的经济事实会使受影响成本需要重新核对，文字修改不会使成本失效。
- FIFO、LIFO、平均成本及手动批次使用同一个计算器。缺少批次数量仍允许记录；后续收入只补数量，不能倒填历史盈利。
- 资产互换消耗来源成本、确认处置盈亏，并按冻结价值建立目标成本。来源、目标、第三资产费用各记一次；第三资产处置盈亏单列。
- 同币种内部转账不改变总成本，手续费单独处理。本位币单位成本为 1。
- 退款按原支出的消耗明细恢复成本，累计退款不能重复恢复同一部分。相同核算币种跨成本起点可继续追溯；核算币种改变后缺乏可靠折算的退款部分为未知。
- 每一步可展开成交价值与依据，手动填写或主动采用交易日当日/此前行情；未采用可靠依据时保留未知。公共账面价值对应最终段，表单明确显示覆盖关系。
- 日常收入/支出可在更多字段中补录成本核算价值；经济条件变化后重新确认或清除，文字修改保留原冻结依据。
- 冻结值不跟随新行情变化。手续费保存手填/成交/行情依据，行情引用与实际日期；数量、日期等条件变化后必须重新确认、重新采用或清除为未知。

## 连续转换与提交

- 后一步默认继承前一步资产、净到账数量和到账账户；手动改过的字段不会静默覆盖。
- 保留余额按后一步实扣（包括来源费用）计算；补入必须明确来源账户。所有段一次预览、一次原子保存、一次撤销。
- 预览展示资产净变化、当前账户变化、发生时账户余额、手续费、保留余额、成本前后变化及盈亏完整性。
- 预览与正式保存共用计算器，提交检查全量依赖版本。组内任意段失败时不会留下余额、定投、审计或同步半成品。
- 整组编辑保留各段原有时间、类型和冻结价值；只有实际改变公共字段时才应用对应更改。独立子记录不通过业务接口单独编辑。
- 财务修改的撤销检查账务及成本起点依赖，发现后续修改时不覆盖。文字修改只检查其所需的版本与审计约束。

## 草稿、同步和恢复

- 转换草稿按账户、账本和新增/记录 ID 隔离，正文以当前账本密钥加密后保存在本机 KV，不进入财务报表或同步。
- 修改后 500ms 防抖保存；恢复需选择继续或新建。编辑版本冲突保留草稿并展示差异。关闭、Esc、遮罩统一处理保留/放弃。
- 正式保存成功即阻止迟到的草稿写入。草稿清理失败会说明交易已保存，防止重复提交。
- 连续转换作为一个同步聚合拥有全部子记录。备份 v8、导入、自检和冲突名称覆盖成本起点、价值快照及连续转换组。
- 启用成本核算的账本要求 `asset-cost-v2`。旧客户端不能继续写；不支持能力协商的旧服务端保留本地待同步状态并提示升级。
