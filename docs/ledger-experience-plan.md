# 记账初始化方案：首次两选一，默认账户必建，全部功能开放

状态：修订设计，待实施。本文取代上一版“取消首次选择、使用无账户选项”的方案；当前仅更新设计文档。

## 1. 已确定的产品规则

1. 新个人账本首次需要选择记账方式，让用户知道是否需要细分账户。
2. 两条初始化路径都实际创建“默认支出账户”和“默认收入账户”，普通收入与支出保存时有明确账户归属。
3. 首次选择只决定初始化步骤和初始界面，不成为长期模式开关，不控制功能权限。
4. 收入、支出、退款、预算、固定账单、转账、对账、投资、物品、游戏功能均可访问。具体操作需要资料时，在操作处引导补充。
5. 用户随时可以添加银行卡、钱包等资金账户及起始余额。默认账户和资金账户可以同时使用，无需补齐过去所有流水。

## 2. 首次选择页面

页面标题：**你希望怎样开始记账？**

说明：**先决定要不要分开记录银行卡、微信和支付宝。以后随时可以添加账户。**

| 选项 | 主文案 | 补充说明 | 主按钮 |
| --- | --- | --- | --- |
| 先记收支 | 看赚了多少、花在哪里 | 系统准备好收入和支出账户，你直接记金额和分类。暂时不区分钱来自哪张卡、哪个钱包。 | 开始记账 |
| 分账户记账 | 还想看每个账户剩多少钱 | 添加银行卡、微信、支付宝等账户，填写开始记录时的余额。记账时选择收付款账户，之后可以转账和核对账单。 | 添加常用账户 |

首项可标注“不确定就先选这个”。两卡下方固定一句：**两种方式都能使用全部功能；这个选择只影响开始时的设置。**

币种默认为人民币，提供次要的更改入口。导入已有账本和体验演示放在次要位置；恢复已有账本不重新套用新用户选择。

### 路径 A：先记收支

选择后原子创建账本、币种、分类、模板和两个默认账户，设置收入与支出的默认账户，直接打开“记一笔支出”。不要求用户填写账户名或金额。

首次完成时可用一行轻提示：**已准备好收入和支出账户，以后可在“账户”里添加银行卡和钱包。**

### 路径 B：分账户记账

同样先创建两个默认账户，再进入“添加常用账户”：

- 常见类型：银行卡、微信、支付宝、现金；其他类型放次要入口。
- 填写账户名称、开始记录时余额；币种沿用账本默认值，可修改。
- 添加一个即可继续，可连续添加多个。
- 明确设置“支出默认用哪个账户”“收入默认进哪个账户”，允许选择刚建的资金账户，也允许继续使用两个默认账户。
- 提供“稍后添加，先开始”出口；已经初始化的默认账户保证此时也能正常记账。

这是一段初始化流程，结束后不展示“当前模式”或“切换模式”。添加账户向导被中断时保留已建账户，下次继续时不重复初始化。

## 3. 两个默认账户的实际行为

| 项目 | 默认支出账户 | 默认收入账户 |
| --- | --- | --- |
| 持久化 | 创建真实账户记录，有稳定 ID | 创建真实账户记录，有稳定 ID |
| 默认使用 | 新支出自动选中 | 新收入自动选中 |
| 账户页指标 | 本月支出、累计支出；退款冲减支出 | 本月收入、累计收入 |
| 是否要求用户填余额 | 否 | 否 |
| 资产总额 | 不计入资金资产 | 不计入资金资产 |
| 转账、对账 | 这些操作使用银行卡、钱包等资金账户 | 这些操作使用银行卡、钱包等资金账户 |

默认账户用于归集暂不细分来源的收支。账户页提供“默认账户”一组，并说明：**没有细分银行卡、钱包的收支记录在这里。** 这里显示收入、支出指标，而不是把累计流水标为可用余额。

资金账户放在“银行卡与钱包”一组，展示各账户的账面余额。收支报表合并两组账户中的收入、支出和退款，资产总额按资金账户及其他资产模型计算。

账户用途由独立、稳定的字段标识，不能靠账户名称判断，也不能直接借用现有 kind='other'。默认账户可改名；已有引用及当前默认设置需要受保护，不能直接删除导致流水失去归属。停用、迁移和替换默认值沿用明确的账户管理流程。

初始化账户只创建实体和默认设置，不写虚构收入、支出或初始业务流水。

## 4. 日常记账体验

所有“记一笔”入口共用同一套表单：支出/收入切换、金额、分类、可选备注、紧凑日期；附件、地点、标签等按需展开。默认类型为支出，退款从原支出进入。

### 只有默认账户时

收入和支出自动归入相应默认账户；账户选择不占用主表单空间。更多信息中可以查看账户，账户页始终可以打开。

### 添加资金账户后

主表单显示收付款账户，使用用户保存的收入、支出默认值。添加账户后可以顺手设为默认，不能仅因新建了某张卡就悄悄改掉用户设置。

每笔都可以改选。例如工资记入招商银行卡，未细分支付来源的小额消费仍记入默认支出账户。没有模式切换，也没有强制把全部记录改成银行卡记录的步骤。

具体规则：

- 修改默认值只影响下一笔新记录；编辑已有记录保留原账户及状态。
- 退款默认沿用原支出账户，允许按实际到账情况选择其他合适账户；默认收入账户不承接支出退款。
- 固定账单优先使用自身保存的账户；未指定时按收入或支出方向采用账本默认值。
- 转账必须选择两个资金账户；对账针对单个资金账户进行。
- 转账和对账入口始终可见；账户不足时直接引导添加，已填内容保留。
- 修改一笔记录的账户是更新归属，不是复制流水。按现有业务约束处理已对账和来源关联的记录。

## 5. 核心过渡场景：先用默认账户，之后添加资金账户

这是正常的新用户成长路径，作为单独的完整流程设计和验收。添加账户发生在日常使用中，不重新初始化账本，也不重走首次方式选择。

### 推荐流程：从现在开始分账户

账户页提供“添加银行卡 / 钱包”；记账表单的账户选择中也能进入。检测到已有默认账户流水时，添加页显示：**之前的收支会完整保留，添加后可以从现在开始分账户记账。**

第一步填写账户名称、当前实际余额和币种。系统记录这笔余额截至的明确时点，界面紧凑显示“余额截至：今天 14:30”，需要时可改。该时点是余额起点，不能用完成整个向导的时间代替用户填写余额时对应的时间。

第二步设置以后怎么记：

- “今后支出默认使用这个账户”。
- “今后收入默认使用这个账户”。

两个选项独立选择，默认不替用户改变现有设置；保存前清楚列出本次设置结果。既有固定账单和模板的明确账户不随之改变，需要时另行批量调整。

第三步保存并展示：

> 已添加微信零钱
>
> 余额起点：今天 14:30，¥1,200
>
> 今后支出默认使用微信零钱，收入继续使用默认收入账户。
>
> 以前的记录已保留，可随时整理。
>
> [记一笔]  [整理以前的记录]

“整理以前的记录”是次要操作，可直接跳过。账户、余额起点和用户选定的默认值原子保存；失败不应留下半个账户或已经切换的默认值。用户也可以分几天逐个添加银行卡和钱包，每个账户有自己的余额起点。

### 以前的记录如何处理

默认保持原账户、金额和日期，原有收支报表继续可查。默认支出账户和默认收入账户继续承接暂不细分的记录，不批量转成新增银行卡，不把两个账户的累计数转成资金账户初始余额。

“整理以前的记录”提供日期、分类、关键词筛选和多选，让用户把自己确定来源的流水改归到指定账户。执行前显示记录数量及余额影响：

| 相对于目标账户余额起点 | 修改后的行为 | 预览文案 |
| --- | --- | --- |
| 已包含在起始余额中的历史收支 | 修改归属和账户收支统计；不再次增减余额 | 这些记录已包含在起始余额中，只补充账户归属 |
| 起点之后的实际收支 | 修改归属并正常影响目标账户余额 | 本次将使账户余额增加/减少 X 元 |
| 发生顺序无法确定 | 用户确认起点前或起点后，再计算预览 | 这笔收支发生在开始记录余额之前还是之后？ |

总收入和总支出不会因改账户归属而增加一份。操作是修改原流水，不复制流水，也不生成默认账户到银行卡的转账。批量处理保留原归属并支持撤销；撤销前检查记录是否已被后续编辑、同步变更或对账，冲突不能静默覆盖。

同一天开始记录余额前发生的消费，也可能已包含在当前余额里。实现必须保存明确的账户余额起点覆盖关系，或等价的可验证判定信息，不能只按日历日期过滤。归属改到另一账户时，要按那个账户自己的余额起点重新判断。

资金账户可以查看起点之前整理进来的历史收支，但这部分不展示推算的历史余额。余额曲线和余额流水从已确认的余额起点开始。

### 漏记、退款和长期混合记账

- 补记起点前已发生的消费：计入对应日期的支出统计，不重复扣当前余额。
- 起点后发生的消费误记在默认支出账户：改归资金账户时正常扣余额；保存前显示差额。
- 起点前的消费，起点后才收到退款：退款以实际到账时点和到账账户影响余额，不继承原消费“已包含在起始余额”的属性。支出统计归属继续沿用账本退款规则。
- 用户后来仍使用默认账户记部分收支：正常保留；应用展示的是已登记资金账户的账面余额，无法自动知道这些收支具体影响了哪张卡。核对余额发现差额时，可先补账户归属或补漏记，再按现有对账规则处理。
- 手动补录后又导入银行流水：导入需查重、匹配原记录，不能把补归属变成新的一笔消费。

### 想完整整理过去的人

普通“整理以前的记录”只补账户归属，不承诺还原过去每日余额。需要从更早日期核算余额的人，可从账户的“从更早日期核算”进入高级流程：提供更早时点的可靠余额，补齐此后收支、账户归属和转账，预览与当前已知余额的差额后再确认。

已有当前余额起点在前移后用作核对参照，不能与更早的起点重复累加。无法解释的差额需展示并处理，不能伪造成收入或消费。已对账期间遵循已有修改保护。这项高级操作不阻塞默认的“从现在开始”流程。

### 完整数值示例

用户已用默认账户记收入 8,000 元、支出 3,000 元，之后开始记录微信零钱：

| 操作 | 微信零钱账面余额 | 全账本支出净额 |
| --- | --- | --- |
| 填入当前实际余额 1,200 元 | 1,200 元 | 3,000 元 |
| 将昨天已记过的 400 元消费改归微信零钱 | 1,200 元 | 3,000 元 |
| 起点之后新记微信支付 100 元 | 1,100 元 | 3,100 元 |
| 昨天的消费今天退款 400 元到微信零钱 | 1,500 元 | 2,700 元 |

示例为全账本累计净支出，退款归属日期只影响期间统计；添加账户本身及修改归属均不生成收入或支出。

## 6. 金额与统计边界

为新资金账户填写开始记录时的余额，并保存明确的生效时点。该余额是计算起点，不算收入。信用卡与贷款使用各自的欠款语义。

- 资金账户的账面余额按起始余额和生效时点后的相关变动计算。
- 默认账户中的历史收支不会因新增银行卡而自动分配或再次计入银行卡余额。
- 将历史记录改归到资金账户时，必须按生效时点处理：此前记录可参与该账户历史收支统计，但不重复影响已包含其结果的起始余额。
- 收支统计覆盖默认账户和资金账户；转账、余额初始化和对账调整不当作普通收入或支出。
- 已有流水、余额和对账结果的账户保留其原有口径，不自动再注入一笔起始余额。
- 全局统计、账户列表、资产总览、投资及物品关联流水、SQL 聚合和内存计算必须遵循同一边界，不能只在界面隐藏数值。

首页首先展示本月收支。资金余额只汇总资金账户，并明确展示已记录范围；没有资金账户时给出添加入口，而不是从默认收支账户推导现有存款。

## 7. 功能与导航

所有功能从首次创建完成起均可访问。账本页聚焦记录与收支；账户页可以随时管理默认账户和资金账户；预算、固定账单、投资、物品、游戏可从对应入口打开。

首次两条路径只设置合理初始展示：

- 先记收支：突出记账、收支统计，账户管理作为次要入口。
- 分账户记账：额外突出账户列表和记账表单的账户选择。

后续展示随已存在的账户和用户导航偏好变化。隐藏入口仅影响导航，不停用功能，也不修改记录。无需功能解锁页、启用余额开关或专业模式开关。

## 8. 数据与实施计划

### 数据层

新增明确的账户用途和收入/支出默认账户设置。两个默认账户随新账本一起原子、幂等创建；重试、恢复和多设备同步不得生成重复默认账户。类型校验保证支出、收入、退款、转账选用适当账户。

保留旧 ledgerMode 的兼容读取，迁移后不再以它决定功能开放、账户必填或清空字段。新流水均有适当账户归属。

旧账本不重新弹初始化选择。迁移时补齐缺少的默认账户及默认设置；已有账户关联和自定义导航保留。旧无账户流水通过可追溯迁移分配：支出进入默认支出账户、收入进入默认收入账户、退款沿用原支出归属；其余异常类型预检处理，不按名称或模式猜测。

迁移前保留保护备份，验证收入支出统计一致；旧版本曾把无账户收支并入资产的口径需要明确校正并说明，不能以“总资产完全不变”作为迁移承诺。数据库版本、备份恢复、同步和旧客户端写入兼容必须纳入交付检查。

### 实施顺序

1. 先实现账户用途、默认账户初始化、默认值和统一统计规则；修复编辑时账户/状态丢失风险，补迁移测试。
2. 实现首次两条路径及日常使用中的资金账户添加向导；完整覆盖“默认账户使用一段时间后，从现在开始分账户”的流程，以及可选的历史归属整理、余额影响预览和撤销。确保中断、重试和跳过历史整理都可继续。
3. 统一日常记账表单、取消持续模式开关、开放所有功能入口，补齐账户页的两组展示。
4. 完成旧备份恢复、同步、类型检查、构建和浏览器流程验证后整体交付。

关键涉及 FirstRunWizard、ledger-initialization、Settings、Transactions、QuickExpenseModal、forms、账户/总览/报表选择器，以及 core/db 的类型、校验、余额、SQL 聚合、迁移和同步。所有金额继续使用 core 的 decimal.js 工具。

## 9. 验收场景

| 场景 | 预期 |
| --- | --- |
| 选择先记收支 | 必须创建两个账户；不用手填账户即可记收入和支出 |
| 选择分账户记账 | 同样创建两个默认账户，并进入资金账户添加流程 |
| 分账户流程稍后添加或中断后重开 | 默认账户可正常记账，已建账户不重复 |
| 默认账户支出 28 元、退款 8 元 | 净支出 20 元；不增加收入，不生成资金余额 |
| 新钱包起始 100 元，之后支出 28 元 | 钱包余额 72 元；起始 100 元不计收入 |
| 工资选银行卡，小额消费选默认支出账户 | 两笔均正常保存；统计覆盖两笔，银行余额只受所属变动影响 |
| 添加银行卡后修改收入/支出默认值 | 下一笔采用新默认，旧记录不被改归属 |
| 默认账户使用一个月后添加当前余额 | 旧记录完整保留；新增余额不算收入；添加页说明后续默认设置及历史处理 |
| 将余额起点前消费改归新账户 | 仅改变归属和账户收支统计，当前余额不重复扣减 |
| 将起点后错记在默认账户的消费改归新账户 | 预览并正确扣减余额，总支出不重复增加 |
| 起点前消费在起点后退款到账 | 退款增加实际收款账户余额，并正确冲减支出 |
| 同一天内起点前和起点后的消费 | 根据明确发生顺序/覆盖关系分别处理，不能只看日期 |
| 不同日期添加两张卡并整理历史 | 每个账户使用自身的余额起点，修改归属后重新判断 |
| 撤销批量归属整理 | 恢复原归属和对应余额效果；已修改或对账的记录不被静默覆盖 |
| 新账户向导失败或重试 | 账户、余额起点、默认值一致提交，不重复创建 |
| 将余额起点前移以核算更早历史 | 预览、核对差额并保留旧起点作为参照，不重复累加余额 |
| 更改一笔记录账户 | 只有一笔记录，不重复收入/支出；余额按生效边界更新 |
| 进入预算、投资、物品、游戏 | 不要求切换模式；只补该操作必需的信息 |
| 打开转账/对账但缺少资金账户 | 就地引导添加，无模式限制提示 |
| 任意初始化路径完成后查看设置 | 没有模式开关，保留账户默认值和导航偏好 |
| 旧账本迁移、备份恢复、多设备同步 | 默认账户唯一，收入支出一致，账户关联完整，资产口径清楚 |

用户测试先问：“你只想看花费，还是也想核对银行卡和钱包余额？”观察能否选到合适初始化路径，并完成记午餐、记工资。然后给出已有一个月默认账户记录的账本，让用户添加当前余额的钱包、设置以后支出默认账户、整理昨天的消费、处理今天的退款，观察能否理解哪些操作会改变余额。不要先讲账户类型或内部计算规则。
